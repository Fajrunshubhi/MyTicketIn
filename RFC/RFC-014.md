# RFC-014 — Hardening dan Release Gate

## Metadata dan urutan

- Status: Diusulkan.
- Fitur yang dimiliki: **F53, F56, F57, F58, F60, F62**.
- Kompleksitas: **Tinggi**.
- Prasyarat wajib: **RFC-001, RFC-002, RFC-003, RFC-004, RFC-005, RFC-006, RFC-007, RFC-008, RFC-009, RFC-010, RFC-011, RFC-012, dan RFC-013 seluruhnya selesai dan lulus**.
- Pendahulu langsung: **RFC-013 — Notifikasi dan Pemulihan Akun**.
- Penerus langsung: **UAT dan Rilis Akademik**.
- UAT hanya boleh dimulai setelah Definition of Done dan release gate RFC-014 lulus.
- RFC ini mengeraskan sistem yang sudah lengkap; tidak menambah fitur produk atau implementasi pasca-MVP.

## Sasaran dan keputusan

Tutup seluruh risiko rilis melalui taxonomy error seragam, kompatibilitas browser/kamera, WCAG 2.1 AA, observability tanpa data sensitif, restore drill ber-RPO 24 jam, serta CI/CD yang memblokir rilis dan mendukung rollback. Release bersifat immutable, hanya payment sandbox/data uji, dan bukti gate disimpan sebagai artifact. Hardening harus memperbaiki gap pada pemilik modul terdahulu tanpa mengubah requirement, state machine, atau scope fitur.

## Ruang lingkup

- F53 typed error/envelope/recovery/correlation dan F56 matriks browser serta scanner Chrome Android.
- F57 audit/remediasi WCAG 2.1 AA dan F58 structured log, metric, health, alert, dashboard, redaction.
- F60 backup/restore RPO 24 jam dan F62 CI/CD/migration/security/performance/smoke/deploy/rollback, termasuk regression E2E penuh.

## Non-scope

- Tidak mencakup fitur/redesign/microservice baru, uang/data nyata, SLA/sertifikasi produksi, offline/native/push/multi-locale, settlement/payout, atau UAT itu sendiri.
- Provider tanpa gate, PII/session replay observability, migration destructive, dan major upgrade dilarang; hasil RFC hanya kandidat beserta bukti siap UAT.

## Gap kondisi saat ini

Error/log/test masih lokal dan konsistensi, browser/kamera, serta WCAG belum memiliki bukti lintas alur. Health/alert/redaction, restore end-to-end, promotion, dan rollback drill juga belum terbukti.

## Prinsip release

- Default deny: tanpa bukti berarti gagal; Must Have 100%, blocker/critical dan security Critical/High nol.
- Candidate dibangun sekali lalu artifact sama dipromosikan pada environment terisolasi dengan credential sandbox.
- Migrasi expand→backfill→contract tanpa contract destructive; rollback kompatibel minimal satu versi.
- Error jaringan/provider bukan status bisnis invalid; observability bukan source of truth dan tidak memblokir transaksi selain audit wajib.

## Taxonomy error

- `VALIDATION` 400/422 dengan fieldErrors; `AUTHENTICATION` 401; `AUTHORIZATION` 403; recovery sesuai konteks tanpa enumeration.
- `NOT_FOUND` 404 generik lintas tenant; `CONFLICT` 409 untuk version/idempotency/inventory dengan refresh/retry aman.
- `RATE_LIMIT` 429 + `Retry-After`; `PROVIDER` 502/503 tanpa transaksi setengah selesai.
- `NETWORK_CLIENT` adalah UI lokal untuk cek koneksi; `INTERNAL` 500 memakai pesan generik + correlation ID.
- Setiap code Inggris stabil dipetakan satu kategori, status, pesan Indonesia, retryability, severity, dan owner module.

## Diagram komponen tekstual

```text
Request → Correlation Middleware → Route/Service → typed AppError
                                      └→ ErrorMapper → safe envelope/UI recovery
All modules → Pino JSON → log sink → metrics/alerts/dashboard
CI → static gates → integration/E2E/security/performance → immutable artifact
   → preview migration/smoke → approval → production-demo deploy → smoke
Backup snapshot → isolated restore branch → migrate/checksum/smoke → drill evidence
Rollback command → prior artifact + compatible schema → post-rollback smoke
```

## Diagram aliran data tekstual

1. Setiap request menerima/generates correlation ID dan child logger.
2. Boundary menangkap typed error, memetakan response aman, lalu mencatat code/outcome/duration.
3. Log sink membentuk metrik/alert setelah token/PII disensor; CI memvalidasi source, dependency, schema, test, aksesibilitas, kompatibilitas, dan artifact.
4. Pipeline menerapkan migration preview/smoke lalu mempromosikan artifact yang sama.
5. Restore isolasi memverifikasi invariant/read-only; manifest bertanda waktu dan kegagalan menghentikan promotion.

## Skema database, kolom, constraint, dan indeks eksak

- **Tidak ada migration/tabel/kolom/enum/index baru**; skema final adalah gabungan RFC-001–013 dan PostgreSQL tetap source of truth.
- Log, metric, trace, gate report, SBOM, browser matrix, dan restore evidence adalah artifact operasional, bukan row bisnis.
- CI menjalankan `prisma migrate status`, checksum, dan introspection seluruh PK/FK/check/unique/index persis; drift memblokir rilis.
- Tabel runtime `errors|logs|releases|health` dilarang; kebutuhan skema harus kembali ke RFC pemilik melalui migration additive dan regression.

## Kontrak API

Semua endpoint aplikasi terdahulu wajib memakai envelope:
`{"error":{"code":"STABLE_CODE","message":"Bahasa Indonesia","correlationId":"req_...","fieldErrors":{}}}`.

### `GET /api/health/live`

- Auth publik; tanpa body/query; rate limit longgar; `Cache-Control: no-store`.
- 200: `{status:"ok",version,correlationId}` jika process hidup.
- Tidak mengakses database/provider dan tidak membuka env/topologi.

### `GET /api/health/ready`

- Auth publik atau platform probe allowlist.
- 200: `{status:"ready",checks:{app:"ok",database:"ok"},version,correlationId}`.
- 503 `SERVICE_UNHEALTHY`; timeout database 2 detik; provider nonkritis tidak membuat unready.

### `GET /api/admin/operations/health`

- Auth ADMIN ACTIVE.
- 200: `{window,requestErrorRate,webhookFailures,expiryLag,notificationLag,checkInP95,backupFreshness,alerts}`.
- Data teragregasi; tidak ada log mentah, host, connection string, email, token, atau payload.

### `POST /api/internal/smoke/payment-webhook`

- Hanya tersedia `APP_ENV=test|preview`, service credential scoped dan IP/platform allowlist.
- Request fixture sandbox bertanda tangan; 202 safe result.
- Route tidak dibangun/aktif pada production-demo publik.

### Header dan recovery

- Semua response memiliki `X-Correlation-Id`; sensitive page/API `private,no-store`.
- 429 memiliki `Retry-After`; 503 retryable boleh memiliki `Retry-After`.
- Browser UI menampilkan correlation ID untuk 5xx/provider, bukan stack trace.

## Kontrak artifact release

- `release-manifest.json`: `schemaVersion`, `releaseId`, `gitSha`, `buildId`, `createdAt`, `nodeVersion`, `migrationChecksums`, `artifactDigest`, `gateResults`, `sandboxOnly`.
- `gateResults` hanya `PASS|FAIL|NOT_APPLICABLE`; Must Have tidak boleh `NOT_APPLICABLE`.
- `compatibility-report.json`: browser/device/version, flow, result, evidence path, testedAt.
- `restore-report.json`: source backup time, restore start/end, measured RPO/RTO, migration state, invariant checks, smoke result.
- Artifact tidak memuat env value, URL database, credential, test password, email nyata, atau token.

## State dan caching

- Error UI lokal; retry memakai use case idempoten/refetch; health no-store dan dashboard operasional cache privat maksimum 30 detik.
- Log/metric bukan authority order/payment/ticket/check-in; tidak ada service worker/offline state yang menandai Used.
- Release state di CI/platform; repository hanya menyimpan workflow/runbook tanpa credential.

```text

```

## Algoritma/pseudocode

```text
mapError(error, correlationId):
  if known AppError: catalog lookup; return status + localized safe envelope
  log INTERNAL_ERROR with fingerprint, never stack to client
  return 500 generic envelope

releaseGate(candidate):
  require format/lint/typecheck/build/unit/integration/E2E/security PASS
  require migrations/compatibility/WCAG/performance/restore/smoke PASS
  require blockers=0 and criticalHigh=0
  only then promote immutable digest
```

## UI/UX error dan recovery

- Form menghubungkan field error dan fokus; 401 login, 403 kembali, 404 konteks aman, 409 refresh, 429 waktu tunggu, 5xx retry.
- Payment provider error mengarahkan cek status tanpa klaim gagal sebelum webhook.
- Scanner membedakan Invalid/Used/Wrong Event/camera/jaringan/server; camera denied memberi langkah dan F41 bila tersedia.
- Semua halaman membedakan loading, empty, error, offline, dan retry.

## Kompatibilitas browser dan kamera

- Dua versi stabil terbaru Chrome/Edge/Firefox/Safari menguji katalog, login, organizer, checkout, payment, wallet, dashboard.
- Scanner diuji Chrome Android fisik: HTTPS, rear camera, allow/deny/revoke, background/resume, rotate, dan low light.
- Safari/iOS diuji tampilan/wallet; scanner selain target best-effort; fallback F41 bila aktif dan tidak ada offline.
- Matrix mencatat versi aktual dan wajib diulang untuk candidate dengan perubahan scanner.

## Aksesibilitas WCAG 2.1 AA

- Axe otomatis dilanjutkan keyboard, screen reader smoke, zoom 200%, reflow 320 CSS px, contrast, dan reduced motion.
- Fokus/urutan/skip link/semantic/label/error wajib; dialog mengunci dan mengembalikan fokus, status memakai live region.
- Scanner/status/chart nonwarna dengan alternatif manual/tabel; tidak ada critical/serious atau manual blocker.
- Halaman `lang=id`, kontrol Indonesia, waktu/zona/Rupiah konsisten.

## Logging, metrik, alert, dan health

- Log JSON memuat timestamp/level/service/env/version/correlation/route/action/outcome/error/duration dan meredaksi password/cookie/auth/secret/token/hash/DB URL/PII/provider payload.
- Metrik request, auth, inventory, webhook, expiry, issuance, check-in, outbox, export, DB; alert error >5%/5m, lag >5m, scan p95 >1,5s, health 503 tiga kali, backup >24h.
- Runbook memuat owner/severity/query/mitigasi/escalation/close; retensi 14 hari dengan akses terbatas dan gate baru sebelum data nyata.

## Keamanan

- SAST, dependency/license scan, secret scan, SBOM, lockfile integrity, dan security test RBAC/ownership wajib di CI.
- Critical/High harus nol; suppress memerlukan alasan, expiry, owner, dan persetujuan Product Owner/security reviewer.
- Security headers: CSP terukur, HSTS pada HTTPS, `nosniff`, referrer policy, frame protection.
- Env fail-fast membedakan sandbox/production dan menolak payment produksi; log/artifact/screenshot/trace bebas PII/token/secret.
- DAST terbatas pada preview terisolasi dengan data uji dan rate aman.

## Kinerja dan reliability

- Katalog/detail p95 ≤2 detik; QR validation p95 ≤1,5 detik.
- Profil: event 5.000 tiket, 50 checkout bersamaan, 10 scanner, durasi 15 menit.
- Overselling dan double successful check-in wajib nol; webhook replay tidak menggandakan ticket.
- Error rate target test <1%; hasil percentile, throughput, resource, dan bottleneck disimpan.
- Test dilakukan pada preview menyerupai production-demo; cache dingin/hangat dicatat.
- Gate gagal bila target wajib gagal; tidak menaikkan timeout atau menurunkan beban tanpa keputusan scope.

## Backup dan restore drill

- Backup/snapshot maksimal setiap 24 jam; baseline RPO **24 jam**.
- Restore ke branch/database terisolasi, bukan menimpa production-demo.
- Runbook: pilih snapshot, provision target, validasi env isolation, restore, migrate forward bila perlu, checksum/count non-PII, invariant SQL, smoke read-only, hapus target sesuai approval.
- Invariant: quota tidak oversold, payment reference unik, Paid unit=ticket count, maksimal satu successful check-in/ticket, audit immutable.
- Ukur RPO aktual dan RTO observasi; pilot komersial wajib menetapkan target baru.
- Drill gagal atau backup lebih tua 24 jam memblokir release.

## Pipeline CI/CD dan rollback

- PR gate: format, lint, typecheck, unit, integration PostgreSQL, migration drift, build, SAST/dependency/secret scan.
- Candidate gate: E2E, concurrent invariant, webhook replay, accessibility, compatibility, performance, restore drill, SBOM.
- Deploy preview: env validation, `prisma migrate deploy`, readiness, smoke seluruh jalur inti.
- Promote production-demo memakai artifact digest sama dan approval Product Owner; lalu smoke read-only dan satu transaksi sandbox terkontrol.
- Rollback aplikasi ke digest sebelumnya; migration harus backward-compatible.
- Bila data rusak, hentikan write, nilai incident, dan restore hanya lewat runbook/approval; jangan otomatis menjalankan down migration destruktif.

## Dependensi dan fallback

- Memakai seluruh RFC-001–013; tidak ada domain baru.
- Provider log/error tracking opsional melalui adapter; fallback adalah structured stdout platform dengan retensi/akses tervalidasi.
- Jika camera API gagal, F41 manual input bila tersedia; jika tidak, petugas diberi error jujur dan perangkat target yang didukung.
- Jika observability provider gagal, transaksi berjalan dan platform log/health tetap aktif.
- Jika deployment platform tidak mendukung atomic promotion, gunakan staged rollout + health gate; kegagalan memicu rollback artifact.

## Kasus uji

- `F53-E2E-001`: setiap kategori error memberi copy/recovery/status/correlation yang benar.
- `F53-SEC-002`: 500/provider tidak membocorkan stack, SQL, secret, atau status bisnis palsu.
- `F56-COMP-001`: alur utama lulus pada matriks browser aktual.
- `F56-DEVICE-002`: Chrome Android camera allow/deny/revoke/resume/manual fallback.
- `F57-A11Y-001`: axe tanpa critical/serious dan keyboard/screen-reader/reflow manual lulus.
- `F58-INT-001`: correlation lintas request/job/webhook; redaction fixture bebas data sensitif.
- `F58-OPS-002`: alert sintetis dan setiap runbook berhasil dipakai menemukan failure.
- `F60-REC-001`: backup ≤24 jam dipulihkan isolasi; invariant dan smoke lulus.
- `F62-CI-001`: setiap gate wajib sengaja dibuat gagal dan terbukti memblokir promotion.
- `F62-ROLL-002`: prior artifact rollback, readiness, dan smoke lulus tanpa down migration.
- `NFR-PERF-001`: profil 15 menit memenuhi p95, overselling=0, double-check-in=0.

## Migrasi dan rollout

1. Bekukan fitur setelah RFC-001–013 lulus; triage defect berdasarkan severity.
2. Normalisasi error/catalog/redaction dan tambahkan test tanpa mengubah state machine.
3. Jalankan compatibility, WCAG, security, performance; perbaikan kembali ke module owner dan regression penuh.
4. Validasi backup, lakukan restore drill terisolasi, simpan evidence aman.
5. Jalankan candidate pipeline dan deploy preview; lakukan rollback drill.
6. Hanya candidate dengan manifest seluruh gate PASS dipromosikan ke production-demo.
7. Setelah smoke sukses, tandai siap UAT; rollback segera jika readiness/smoke wajib gagal.

## Risiko dan mitigasi

- Hardening berubah menjadi fitur/refactor: freeze scope dan perbaikan terkecil pada module owner.
- False green CI: negative gate tests, artifact digest, evidence manifest, dan approval.
- Log membocorkan data: centralized redaction, snapshot/canary secret test, akses terbatas.
- Browser matrix cepat usang: catat versi aktual per candidate dan ulangi saat scanner berubah.
- Restore merusak data aktif: target isolasi, credential marker, read-only verification, approval.
- Rollback gagal karena schema: additive migration dan kompatibilitas satu versi.

## Kriteria penerimaan per fitur

- **F53:** seluruh alur membedakan validasi, akses, conflict, provider, kamera, jaringan, dan internal; pesan Indonesia memberi recovery tanpa detail sensitif.
- **F56:** dua versi terbaru browser target lulus smoke; scanner Chrome Android dan permission/fallback kamera memiliki bukti.
- **F57:** alur utama memenuhi pemeriksaan WCAG 2.1 AA otomatis/manual, termasuk keyboard, fokus, label, kontras, reflow, dan status nonwarna.
- **F58:** health aman, log terstruktur/redacted, correlation, metrik dan alert menemukan kegagalan webhook/job/scan/database dengan runbook.
- **F60:** backup memenuhi RPO 24 jam dan restore drill isolasi berhasil dengan invariant/smoke serta evidence.
- **F62:** pipeline memblokir kegagalan wajib, migration preview dan immutable promotion bekerja, rollback aplikasi teruji dan terdokumentasi.

## Definition of Done

1. Seluruh RFC-001–013 dan regression suite lulus; Must Have 100%.
2. Tidak ada defect blocker/critical atau security Critical/High terbuka.
3. Error catalog, browser/camera matrix, WCAG audit, observability/alert/runbook, dan redaction memiliki bukti.
4. Load/concurrency/webhook replay memenuhi seluruh NFR wajib pada profil 15 menit.
5. Backup ≤24 jam dan restore drill isolasi lulus; RPO/RTO observasi tercatat.
6. CI/CD candidate, migration preview, immutable deploy, smoke, dan rollback drill lulus.
7. Release manifest/artifact bebas secret/PII, berlabel sandbox, dan seluruh gate wajib PASS.
8. Format, Markdown, lint, typecheck, build, test, SAST/dependency/secret scan, SBOM lulus.
9. Tidak ada fitur pasca-MVP, uang/data nyata, forward implementation, migration destruktif, TODO, atau secret.
10. Kandidat dinyatakan siap **UAT dan Rilis Akademik**, bukan siap pilot komersial.
