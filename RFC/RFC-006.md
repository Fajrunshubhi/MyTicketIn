# RFC-006 — Lifecycle Event dan Petugas

## Metadata dan urutan
- Status: Diusulkan.
- Fitur yang dimiliki: **F11, F12, F13, F14, F17**.
- Kompleksitas: **Tinggi**.
- Prasyarat: **RFC-001, RFC-002, RFC-003, RFC-004, dan RFC-005 wajib selesai dan lulus**.
- Pendahulu langsung: **RFC-005 — Penulisan Event dan Tipe Tiket**.
- Penerus langsung: **RFC-007 — Katalog dan Discovery**.
- RFC-007 hanya boleh dimulai setelah Definition of Done RFC ini lulus.
- Tidak membuat order, payment, ticket, scanner, atau notification yang dimiliki RFC sesudahnya.

## Sasaran dan keputusan
RFC ini mengaktifkan lifecycle event yang enum-nya disiapkan RFC-005: admin memoderasi, organizer memperbaiki penolakan, event dapat dibatalkan/diselesaikan, tipe tiket dapat dihentikan penjualannya, draft dapat dipratinjau secara privat, dan akun ACTIVE dapat ditugaskan sebagai petugas. Semua keputusan status memakai transaksi, expected version, audit atomik, serta analytics setelah commit.

## Ruang lingkup
- Moderasi `PENDING_REVIEW → PUBLISHED|REJECTED` oleh admin.
- Edit/resubmit event Rejected melalui authoring service RFC-005.
- Pembatalan irreversible dan penyelesaian event setelah waktu berakhir.
- Pratinjau privat untuk owner organizer Approved.
- Assignment/revocation petugas per event dan policy operator.
- Penghentian penjualan per tipe tiket tanpa mengubah data historis.
- Antrean moderasi admin, reason, audit, analytics, dan invalidasi cache kontraktual.

## Non-scope
- Katalog/search/detail publik (RFC-007).
- Checkout, reservasi, order, atau perhitungan kuota terpakai (RFC-008).
- Refund/payment (RFC-009), pembatalan Ticket Unused (RFC-010), scanner (RFC-011).
- Dashboard/notifikasi/email (RFC-012/013), mode offline, tim organizer, undangan tanpa akun.
- Side effect ke tabel commerce yang belum ada; kontraknya diuji ulang saat RFC pemilik tabel tersebut masuk.

## Gap kondisi setelah RFC-005
- Event hanya dapat menjadi DRAFT/PENDING_REVIEW; belum ada keputusan admin atau alasan.
- Belum ada published/cancelled/completed timestamp, assignment, preview, atau stop-sale.
- Enum lifecycle ada tetapi nilai selain authoring tidak dapat dihasilkan command mana pun.
- Data event belum boleh dikonsumsi publik dan belum ada consumer commerce.

## State machine dan aturan domain
```text
DRAFT ─submit→ PENDING_REVIEW ─approve→ PUBLISHED ─complete(after ends_at)→ COMPLETED
  ↑                    └─reject→ REJECTED ─edit/resubmit→ PENDING_REVIEW
  └──────────────────────── delete (hanya sebelum history)
PENDING_REVIEW|PUBLISHED|REJECTED ─cancel→ CANCELLED
CANCELLED dan COMPLETED terminal; tidak dapat kembali PUBLISHED.
```
- Admin saja approve/reject; reject wajib alasan 10–1000 karakter; approve memakai catatan opsional maksimum 1000.
- Owner boleh cancel miliknya; admin boleh cancel semua; alasan 10–1000 wajib.
- Complete hanya dari PUBLISHED jika `ends_at <= database_now`; owner atau admin boleh menjalankan command idempoten.
- Perubahan field event PUBLISHED tidak tersedia; koreksi pascapublikasi memerlukan RFC perubahan scope.
- Rejected dapat diedit oleh owner, status tetap REJECTED; resubmit memvalidasi aggregate terbaru.
- Stop sale hanya dari tipe aktif milik event PUBLISHED; irreversible pada RFC ini.
- Organizer owner secara implisit operator event; assignment hanya memberi capability operator kepada user lain.
- Assignee harus user ACTIVE, bukan ADMIN khusus, dan assignment dicabut efektif pada request berikutnya.

## Diagram komponen tekstual
```text
Admin Moderation UI → requireRole(ADMIN) → ModerateEventService
                                         → transaction(event + audit)
Organizer Lifecycle UI → requireApprovedOrganizer + ownership → Cancel/Complete/StopSale
Private Preview → owner policy → EventReadRepository → shared EventPresentation (tanpa public route)
Staff UI → EventStaffService → UserRepository + AssignmentRepository + AuditWriter
Future scanner → requireEventOperator(userId,eventId) [policy only; scanner belum dibuat]
```

## Diagram aliran data tekstual
1. Route mengambil actor dari session dan memvalidasi body/query dengan Zod.
2. Service memuat event menggunakan row lock, memeriksa role/ownership/status/version.
3. Conditional update status/assignment/ticket type dan append audit terjadi dalam satu transaction.
4. Commit sukses memicu analytics dan invalidasi tag event; kegagalan analytics tidak rollback.
5. Preview membaca aggregate owner langsung dari database dan tidak mengubah status.
6. Policy operator membaca owner Approved atau assignment ACTIVE setiap request; tidak disimpan pada JWT.
7. Karena commerce belum ada, cancel tidak menyentuh order/ticket; RFC-008–010 wajib menambahkan side effect dalam transaksi mereka tanpa mengubah state machine ini.

- Constraint `events_publish_state_chk`: PUBLISHED/COMPLETED/CANCELLED yang pernah published wajib `published_at`; validasi provenance pembatalan juga dijaga service/audit.
- Constraint `events_cancel_state_chk`: CANCELLED wajib tiga cancellation fields; non-CANCELLED ketiganya null.
- Constraint `events_complete_state_chk`: COMPLETED wajib `completed_at`; non-COMPLETED null.

- `event_id TEXT NOT NULL REFERENCES events(id) ON DELETE RESTRICT`.

- `revoked_by_user_id TEXT NULL REFERENCES users(id) ON DELETE RESTRICT`.

- Index `event_staff_assignments_user_active_idx(user_id,event_id) WHERE status='ACTIVE'`.
- Index `event_staff_assignments_event_status_idx(event_id,status,assigned_at DESC,id DESC)`.
- Reassignment mengaktifkan kembali row yang sama, mereset revoke fields, menaikkan version, dan tetap diaudit.

## Kontrak API
Seluruh mutation: session ACTIVE, CSRF, Zod, rate limit, expectedVersion, error envelope, correlation ID, dan `Cache-Control: private,no-store`.

### Moderasi admin
- `GET /api/admin/events?status=PENDING_REVIEW&cursor&limit=1..100&q`; auth ADMIN; respons `200 {items:[{id,title,organizerName,submittedAt,version}],nextCursor}`.
- `GET /api/admin/events/{id}`; auth ADMIN; respons `200 {event,ticketTypes,image,organizer,auditSummary,version}`.
- `POST /api/admin/events/{id}/decisions`; request `{decision:"APPROVE"|"REJECT",reason?,expectedVersion}`; respons `200 {id,status,reason,decidedAt,publishedAt?,version}`.

### Lifecycle organizer/admin
- `POST /api/organizer/events/{id}/resubmit`; owner Approved; request `{expectedVersion}`; hanya REJECTED; respons PENDING_REVIEW.
- `POST /api/organizer/events/{id}/cancel`; owner Approved; request `{reason,expectedVersion}`; respons CANCELLED.
- `POST /api/admin/events/{id}/cancel`; ADMIN; request `{reason,expectedVersion}`; respons CANCELLED.
- `POST /api/organizer/events/{id}/complete`; owner Approved; request `{expectedVersion}`; respons COMPLETED; repeated pada COMPLETED mengembalikan 200 state sama.
- `POST /api/organizer/events/{id}/ticket-types/{typeId}/stop-sales`; owner Approved; request `{reason,expectedVersion}`; respons `200 {id,salesStoppedAt,version}`.

### Preview dan petugas
- `GET /organizer/events/{id}/preview`; halaman server, owner Approved saja, `noindex`, no-store; tidak ada URL token publik.
- `GET /api/organizer/events/{id}/staff?cursor&limit`; owner; respons daftar safe user identity + status/version.
- `POST /api/organizer/events/{id}/staff`; request `{userId,expectedExistingVersion?}`; respons `201|200 {assignment}`.
- `POST /api/organizer/events/{id}/staff/{assignmentId}/revoke`; request `{reason,expectedVersion}`; respons 200 REVOKED.
- Pencarian kandidat memakai `GET /api/organizer/staff-candidates?q&cursor&limit<=20`, minimum 3 karakter, hasil hanya `id,displayName,maskedEmail`; rate-limited.

## State dan caching
- Database adalah source of truth; status/capability/assignment tidak masuk JWT.
- Moderation list filters dan cursor di URL; dialog memakai state lokal tanpa optimistic update.
- Preview dan seluruh organizer/admin response no-store.
- Mutasi memanggil `invalidateTag("event:{id}")`; tag baru digunakan cache publik RFC-007, bukan mengaktifkan katalog sekarang.
- Revalidate setelah conflict; assignment revoke berlaku pada lookup database berikutnya.

## Algoritma/pseudocode
```text
transition(eventId, command, expectedVersion, actor):
  transaction:
    event = SELECT FOR UPDATE
    authorize command; assert expectedVersion; validate transition
    if COMPLETE: require event.endsAt <= database_now
    conditional UPDATE status + timestamps + version
    append audit(before,after,reason); commit
  emit analytics; invalidate event tag

requireEventOperator(userId,eventId):
  allow if event.organizer.owner == userId and organizer APPROVED
  else allow only ACTIVE user + ACTIVE assignment
  otherwise deny
```

## UI/UX
- Admin queue mengurutkan submission tertua, menampilkan checklist aggregate, preview aman, approve/reject dialog, dan conflict refresh.
- Rejected menampilkan alasan dan CTA edit/resubmit; Published menampilkan badge dan aksi cancel/complete/stop-sale dengan warning.
- Preview memakai komponen presentasi detail tetapi banner “Pratinjau—tidak publik”.
- Staff manager mencari akun, mengonfirmasi identitas masked, menunjukkan Active/Revoked, dan meminta alasan revoke.
- Status terminal tidak menampilkan aksi yang tidak valid.

## Error, logging, dan monitoring
- Kode: `EVENT_TRANSITION_INVALID`, `EVENT_REASON_REQUIRED`, `EVENT_VERSION_CONFLICT`, `EVENT_NOT_ENDED`, `EVENT_ALREADY_CANCELLED`, `EVENT_ACCESS_DENIED`, `TICKET_SALES_ALREADY_STOPPED`, `STAFF_USER_NOT_FOUND`, `STAFF_USER_INACTIVE`, `STAFF_ASSIGNMENT_CONFLICT`, `STAFF_ASSIGNMENT_NOT_FOUND`, `STAFF_ACCESS_DENIED`.
- Log allowlist: actor/event/assignment IDs, action, from/to, duration, correlation; tanpa reason, kontak, description, atau candidate query.
- Metrik: queue age, approve/reject/cancel/complete, stop-sale, assignment/revoke, conflict, p95; alert audit failure, pending >72 jam, transition 5xx >2%/15 menit.

## Keamanan, performa, aksesibilitas, dan i18n
- Role dan ownership diperiksa server; user ID kandidat harus lookup, bukan dipercaya; admin tidak dapat dimasukkan otomatis sebagai staff.
- Preview tidak memakai bearer URL, sitemap, metadata sosial, atau cache publik; HTML di-escape.
- Cursor default 25/maksimum 100; detail berat hanya on-demand; target p95 policy ≤200 ms, list/detail ≤700 ms, mutation ≤1 s.
- Keyboard/focus dialog, status teks+ikon, alasan terkait field, destructive action punya konfirmasi; layout 360 px.
- Copy Indonesia; timestamp ditampilkan menurut timezone event dan menyertakan offset untuk keputusan admin.

## Dependensi dan fallback
- Memakai authoring/repository RFC-005, organizer capability RFC-004, audit/analytics RFC-003, auth RFC-002.
- Tidak memerlukan provider baru; analytics gagal degraded, audit/database gagal rollback.
- Status event owner adalah fallback notifikasi sampai RFC-013.
- Tanpa scheduler, complete adalah command owner/admin setelah `ends_at`; RFC-008 boleh menjadwalkan pemanggilan use case yang sama, bukan membuat aturan baru.

## Kasus uji
- `F11-UNIT-001`: transition matrix exhaustive; reject tanpa reason ditolak.
- `F11-CONC-002`: dua admin expectedVersion sama hanya satu berhasil dan satu audit.
- `F11-SEC-003`: non-admin tidak moderasi; Published memiliki decided/published timestamp.
- `F12-INT-001`: cancel irreversible, historical row tetap ada, tag invalidated.
- `F12-INT-002`: complete sebelum endsAt ditolak dan sesudahnya idempoten.
- `F12-REG-003`: saat RFC-008–010 hadir, cancellation Paid/Unused/Used wajib diuji tanpa mengubah Used ke Unused.
- `F13-SEC-001`: preview hanya owner, no-store/noindex, tanpa status mutation.
- `F14-INT-001`: assign/revoke/reactivate mengubah policy request berikutnya dan diaudit.
- `F14-SEC-002`: organizer lain, inactive user, dan enumeration kandidat ditolak/dibatasi.
- `F17-INT-001`: stop-sale hanya Published dan irreversible; record historis tidak berubah.

## Migrasi dan rollout
1. Regression RFC-001–005 dan backup preview lulus.
2. Tambah kolom, enum, tabel, constraint, serta indeks secara additive.
3. Backfill tidak diperlukan: event lama RFC-005 hanya DRAFT/PENDING dan kolom baru nullable.
4. Deploy policy/reads, lalu moderation/lifecycle/staff di balik flag; verifikasi audit dan concurrency.
5. Aktifkan admin lalu organizer; rollback menutup command tanpa menurunkan status/data yang sudah terminal.

## Risiko dan mitigasi
- Lost update moderator/owner: row lock + expectedVersion + audit atomik.
- Cancel sebelum commerce tidak menguji side effect masa depan: contract regression wajib pada RFC-008–010.
- Capability petugas stale: database lookup per request, tanpa JWT/global cache.
- Preview bocor: owner session, noindex/no-store, tidak ada share token.
- Complete terlambat tanpa scheduler: command eksplisit; katalog RFC-007 menghitung keterjualan dari status, bukan waktu saja.

## Kriteria penerimaan per fitur
- **F11:** admin approve/reject Pending secara valid, reason sesuai aturan, Published menjadi satu-satunya status siap katalog, Rejected dapat diperbaiki/resubmit, seluruh keputusan auditable.
- **F12:** lifecycle dan terminal state dipaksa server; Cancelled berhenti menjadi eligible, tidak kembali Published, data historis tidak dihapus; integrasi tiket diuji ketika tabelnya resmi tersedia.
- **F13:** owner melihat representasi draft terbaru secara privat tanpa mengubah status atau memberi akses/beli kepada publik.
- **F14:** owner memberi/mencabut akses operator per event; hanya ACTIVE assignment berlaku dan setiap perubahan tercatat.
- **F17:** tipe tiket yang dihentikan tidak eligible untuk penjualan baru, sedangkan data event/tipe tetap utuh.

## Definition of Done
1. Regression RFC-001–005 lulus sebelum implementasi RFC-007.
2. Migration/constraint/index/Prisma mapping dan rollback diuji PostgreSQL.
3. Semua endpoint memakai auth/RBAC/ownership, Zod, CSRF/rate limit, expectedVersion, envelope, dan correlation ID.
4. Unit/integration/concurrency/security/E2E F11–F14/F17 lulus; branch coverage module ≥90%.
5. Audit atomik, analytics after-commit, policy operator, dan invalidasi tag terverifikasi.
6. UI admin/organizer responsif, Indonesia, keyboard accessible, WCAG 2.1 AA.
7. Format/lint/typecheck/build/test/security scan lulus; tidak ada Critical/High atau defect blocker.
8. Tidak ada katalog, order, payment, ticket, scanner, notification, scheduler/provider baru, TODO, atau secret.
9. RFC-007 baru dimulai setelah exit criteria ini disetujui.
