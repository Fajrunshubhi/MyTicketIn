# RFC-013 — Notifikasi dan Pemulihan Akun

## Metadata dan urutan

- Status: Diusulkan.
- Fitur yang dimiliki: **F6, F49, F50, F51**.
- Kompleksitas: **Sedang**.
- Prasyarat wajib: **RFC-001, RFC-002, RFC-003, RFC-004, RFC-005, RFC-006, RFC-007, RFC-008, RFC-009, RFC-010, RFC-011, dan RFC-012 seluruhnya selesai dan lulus**.
- Pendahulu langsung: **RFC-012 — Dashboard, Pelaporan, dan Rekomendasi Event**.
- Penerus langsung: **RFC-014 — Hardening dan Release Gate**.
- RFC-014 hanya boleh dimulai setelah Definition of Done RFC-013 lulus.
- Prioritas: **F49 notifikasi in-app, F50 email, dan F51 reminder adalah Must Have; F6 reset password tetap Should Have**.
- Decision gate email provider wajib ditutup sebelum implementasi delivery dan merupakan blocker penyelesaian RFC-013. Provider dipilih melalui gate, bukan oleh RFC ini.
- Tidak menerapkan hardening/release gate RFC-014.

## Sasaran dan keputusan

Bangun notifikasi in-app persisten dan email transaksional wajib untuk hasil moderasi, pembayaran/tiket, pembatalan, dan refund melalui antrean/outbox, retry terbatas, serta adapter provider yang telah lolos decision gate. Kegagalan delivery email saat runtime tidak membatalkan transaksi domain; notifikasi in-app tetap menjadi fallback delivery resmi. Reset password akun lokal menggunakan token acak sekali pakai yang disimpan sebagai hash. Reminder event wajib dikirim satu kali melalui scheduler yang sudah tersedia dari RFC-008, tanpa membuat scheduler baru.

## Ruang lingkup

Mencakup F49 inbox in-app, unread count, list/detail, mark read, serta producer domain; F50 email transaksional wajib melalui adapter; F6 request/confirm dan admin-assisted reset; F51 reminder wajib; endpoint job pada scheduler RFC-008; serta outbox, deduplication, retry/backoff, status delivery, template version, dan redaction.

## Non-scope

Tidak mencakup push, SMS/WhatsApp, marketing, newsletter, mobile native, QR/token dalam email, email verification, MFA, passkey, ubah email, preference center kompleks, reminder berulang, kalender eksternal, AI, scheduler baru, atau perubahan status domain akibat delivery.

## Gap kondisi saat ini

Domain telah menghasilkan audit/analytics, tetapi belum ada inbox, unread state, dedup, outbox, delivery attempt, adapter email, atau reset token lifecycle. Tanpa pemisahan, kegagalan provider dapat menggagalkan domain.

## Aturan domain

- Notifikasi in-app dibuat untuk penerima yang diturunkan server, tidak menerima `recipientUserId` dari client.
- Jenis wajib: hasil moderasi organizer/event, payment succeeded/failed, ticket issued, event cancelled, refund status.
- Delivery email tidak rollback domain; in-app diretry dari outbox dengan dedup `domainEventId + recipient + notificationType + channel`.
- User hanya mengubah read state miliknya; reset request selalu generik untuk akun tidak ada/OAuth-only.
- Token reset minimum 256 bit, TTL 30 menit, sekali pakai, disimpan sebagai SHA-256; maksimum satu aktif per user.
- Reset sukses menaikkan `users.auth_version`, menggugurkan sesi, dan request baru mencabut token lama.
- Reminder dikirim satu kali per user per event pada T-24 jam, hanya event Published ketika user memiliki minimal satu ticket Unused dari order Paid.
- Timestamp reminder dihitung dari `events.starts_at`; scheduler memakai database time.

```text

                                  └── EmailProviderPort (wajib, provider bergate)

```

## Diagram aliran data tekstual

1. Use case terdahulu commit status dan menulis domain event/outbox dalam transaksi yang sama melalui hook yang wajib tersedia untuk jenis notifikasi.
2. Dispatcher mengunci batch outbox dengan `FOR UPDATE SKIP LOCKED`.
3. Dispatcher membuat in-app idempoten dan delivery email wajib, mengirim melalui adapter provider bergate, memetakan status tanpa payload/secret, dan retry maksimal lima kali.
4. Forgot-password membuat hash; redeem mengunci token/user, mengganti password, menaikkan authVersion, menandai used, lalu commit.
5. Scheduler RFC-008 memanggil reminder producer pada cadence maksimum lima menit; producer mengecek ulang eligibility dengan database time dan menulis outbox unik per event+recipient.

### Enum

- `notification_type`: `ORGANIZER_APPROVED|ORGANIZER_REJECTED|ORGANIZER_SUSPENDED|EVENT_PUBLISHED|EVENT_REJECTED|EVENT_CANCELLED|PAYMENT_SUCCEEDED|PAYMENT_FAILED|TICKET_ISSUED|REFUND_UPDATED|EVENT_REMINDER|PASSWORD_RESET_ASSISTED`.
- `notification_channel`: `IN_APP|EMAIL`; `notification_delivery_status`: `PENDING|PROCESSING|SENT|FAILED|SKIPPED`; `outbox_status`: `PENDING|PROCESSING|COMPLETED|FAILED`.

### Tabel `notifications`

- `id TEXT PRIMARY KEY` (CUID); `recipient_user_id TEXT NOT NULL REFERENCES users(id) ON DELETE RESTRICT`; `type notification_type NOT NULL`.
- `title VARCHAR(160) NOT NULL`; `body VARCHAR(1000) NOT NULL`; `action_path VARCHAR(500) NULL` dengan aturan relative path diawali `/`, bukan `//`/origin eksternal.
- `entity_type VARCHAR(60) NULL`; `entity_id TEXT NULL`; `deduplication_key VARCHAR(180) NOT NULL`.
- `created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`; `read_at TIMESTAMPTZ NULL`; `expires_at TIMESTAMPTZ NULL`.
- `metadata JSONB NOT NULL DEFAULT '{}'::jsonb`; object allowlist tanpa PII/token.
- Constraint pasangan entity keduanya null atau keduanya non-null; title/body trim; `expires_at > created_at` bila ada.
- Unique `notifications_recipient_dedup_key(recipient_user_id,deduplication_key)`.
- Index `notifications_recipient_created_idx(recipient_user_id,created_at DESC,id DESC)`; partial `notifications_recipient_unread_idx(recipient_user_id,created_at DESC,id DESC) WHERE read_at IS NULL`.

### Tabel `notification_outbox`

- `id TEXT PRIMARY KEY` (CUID); `domain_event_id VARCHAR(160) NOT NULL`; `recipient_user_id TEXT NOT NULL REFERENCES users(id) ON DELETE RESTRICT`.
- `notification_type notification_type NOT NULL`; `payload JSONB NOT NULL`; `status outbox_status NOT NULL DEFAULT 'PENDING'`.
- `attempt_count SMALLINT NOT NULL DEFAULT 0`; `next_attempt_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `locked_at TIMESTAMPTZ NULL`; `locked_by VARCHAR(100) NULL`.
- `last_error_code VARCHAR(80) NULL`; `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`; `completed_at TIMESTAMPTZ NULL`.
- Check payload object dan ukuran aplikasi maksimum 16 KiB; attempts `BETWEEN 0 AND 5`.
- Check PROCESSING wajib lock fields; COMPLETED wajib completed_at; status lain completed_at null.
- Unique `(domain_event_id,recipient_user_id,notification_type)`.
- Index `notification_outbox_dispatch_idx(status,next_attempt_at,id)`; `notification_outbox_locked_idx(locked_at) WHERE status='PROCESSING'`.

### Tabel `notification_deliveries`

- `id TEXT PRIMARY KEY` (CUID); `notification_id TEXT NOT NULL REFERENCES notifications(id) ON DELETE RESTRICT`.
- `channel notification_channel NOT NULL`; `status notification_delivery_status NOT NULL DEFAULT 'PENDING'`.
- `provider VARCHAR(40) NULL`; `provider_message_id VARCHAR(255) NULL`.
- `template_key VARCHAR(80) NOT NULL`; `template_version SMALLINT NOT NULL DEFAULT 1`.
- `attempt_count SMALLINT NOT NULL DEFAULT 0`; `next_attempt_at TIMESTAMPTZ NULL`.
- `last_error_code VARCHAR(80) NULL`; `sent_at TIMESTAMPTZ NULL`; `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- Check version `>0`, attempts `BETWEEN 0 AND 5`; SENT wajib `sent_at`; selain SENT null.
- Unique `(notification_id,channel)`; unique partial `(provider,provider_message_id) WHERE provider_message_id IS NOT NULL`.
- Index `notification_deliveries_retry_idx(status,next_attempt_at,id) WHERE status IN ('PENDING','FAILED')`.

### Tabel `password_reset_tokens`

- `id TEXT PRIMARY KEY` (CUID); `user_id TEXT NOT NULL REFERENCES users(id) ON DELETE RESTRICT`.
- `token_hash CHAR(64) NOT NULL`; `requested_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `expires_at TIMESTAMPTZ NOT NULL`; `used_at TIMESTAMPTZ NULL`; `revoked_at TIMESTAMPTZ NULL`.
- `requested_ip_hash CHAR(64) NULL`; `created_by_admin_user_id TEXT NULL REFERENCES users(id) ON DELETE RESTRICT`.
- Check `expires_at > requested_at`; paling banyak satu dari used/revoked; admin-assisted tidak menyimpan raw password/token.
- Unique `password_reset_tokens_hash_key(token_hash)`; partial unique `password_reset_tokens_one_active_user_key(user_id) WHERE used_at IS NULL AND revoked_at IS NULL`.
- Index `password_reset_tokens_expiry_idx(expires_at) WHERE used_at IS NULL AND revoked_at IS NULL`.

## Kontrak API

Semua endpoint memakai Zod, error envelope, correlation ID, no-store untuk data privat, CSRF pada mutasi session, dan rate limit.

### `GET /api/me/notifications`

- Auth: user ACTIVE.
- Query: `filter=all|unread`, `cursor?`, `limit=1..50` default 20.
- 200: `{items:[{id,type,title,body,actionPath,createdAt,readAt}],unreadCount,nextCursor}`.

### `POST /api/me/notifications/{id}/read`

- Auth: recipient owner; body kosong; idempoten.
- 200: `{id,readAt}`; ID asing memberi 404 generik.

### `POST /api/me/notifications/read-all`

- Auth user; request `{before?:ISO-8601}`; maksimum row tidak dibatasi client.
- 200: `{updatedCount,readAt}`; update hanya recipient dari session.

### `POST /api/auth/password-reset/request`

- Auth publik; request `{email}`.
- Limit 3/email-hash/jam dan 10/IP-hash/jam.
- Selalu 202: `{message:"Jika akun memenuhi syarat, instruksi pemulihan akan dikirim."}`.
- Email unavailable: catat eligibility untuk admin-assisted flow tanpa memberi tahu caller.

### `POST /api/auth/password-reset/confirm`

- Auth publik; request `{token,newPassword,confirmPassword}`.
- 200: `{message:"Kata sandi berhasil diubah. Silakan masuk kembali."}`.
- 400 generik `PASSWORD_RESET_TOKEN_INVALID`; token expired/used/revoked tidak dibedakan.

### `POST /api/admin/users/{userId}/password-reset-assistance`

- Auth ADMIN ACTIVE + CSRF; request `{reason}` 10–1000.
- Hanya akun lokal ACTIVE; membuat one-time recovery flow yang diserahkan melalui kanal demo terkontrol, bukan menetapkan password pilihan admin.
- 202 safe result; aksi dan pengambilan token harus diaudit; token tidak pernah masuk log.

### `POST /api/internal/jobs/send-event-reminders`

- Auth memakai signed scheduler/service credential yang sudah tersedia pada RFC-008; bukan session user dan tidak membuat provider scheduler baru.
- Request `{batchSize?:1..500}` default 100 dengan invocation ID; worker multi-instance memakai keyset/`FOR UPDATE SKIP LOCKED`.
- Kandidat recipient jatuh tempo ketika `starts_at - INTERVAL '24 hours' <= database_now`, belum mulai, event masih `PUBLISHED`, dan recipient memiliki minimal satu ticket `UNUSED` dari order `PAID`; eligibility diperiksa ulang tepat sebelum enqueue/delivery.
- 200: `{scanned,enqueued,skipped,hasMore,durationMs}` tanpa PII. Dedup key `event-reminder:{eventId}:{recipientUserId}` memastikan pembelian beberapa tiket serta replay/concurrent invocation tetap menghasilkan tepat satu reminder per user per event.
- Scheduler cadence maksimum lima menit dan lag reminder p95 maksimum lima menit; event `CANCELLED`, ticket `USED`, atau order non-Paid tidak pernah dikirim.

## State dan caching

- PostgreSQL source of truth; inbox/unread `private,no-store`.
- URL menyimpan filter/cursor; dropdown open/loading memakai state lokal.
- Badge unread boleh refetch ketika window focus, tidak optimistic pada lintas perangkat.
- Mark-read boleh menampilkan respons server segera, lalu rollback visual bila request gagal.
- Outbox/delivery bukan antrean memory; worker aman dijalankan ulang/bersamaan.
- Template adalah file versioned, bukan editable runtime database.

## Algoritma/pseudocode

```text
dispatch(batch=50):
  claim due rows FOR UPDATE SKIP LOCKED; mark PROCESSING
  for row:
    upsert in-app by dedup key
    create required EMAIL delivery and send through adapter with idempotency key
    complete; on transient error retry min(2^attempt minutes,6h), max 5

produceReminders(invocationId,batch):
  find distinct recipients of due Published events with Paid+Unused tickets using database time
  recheck eligibility; enqueue unique event-reminder:eventId:recipientUserId
  concurrent/replayed invocations treat unique conflict as already enqueued

confirmReset(rawToken,newPassword):
  hash token; transaction lock active token + user
  require not expired/used/revoked and local account ACTIVE
  bcrypt async; update password_hash, auth_version+1; mark used; audit; commit
```

## UI/UX

- Header memiliki badge unread/“Lihat semua”; inbox membedakan unread/read/empty/error dan pesan tidak memuat pembayaran/QR sensitif.
- Forgot/reset menyediakan respons generik, aturan/show/confirm password; email/reminder berbahasa Indonesia, berlabel SANDBOX, memuat waktu/zona/venue dan hanya tautan HTTPS ke aplikasi/wallet.

## Error dan recovery

- Kode: `NOTIFICATION_NOT_FOUND`, `NOTIFICATION_CURSOR_INVALID`, `NOTIFICATION_DELIVERY_FAILED`, `EMAIL_NOT_CONFIGURED`, `EMAIL_PROVIDER_UNAVAILABLE`, `PASSWORD_RESET_RATE_LIMITED`, `PASSWORD_RESET_TOKEN_INVALID`, `PASSWORD_RESET_NOT_ELIGIBLE`, `PASSWORD_RESET_ASSISTANCE_REQUIRED`, `REMINDER_NOT_ELIGIBLE`, `REMINDER_JOB_UNAUTHORIZED`, `REMINDER_JOB_FAILED`.
- `EMAIL_NOT_CONFIGURED` pada startup/rollout adalah blocker dan aplikasi fail-fast; timeout/reject provider saat runtime menjadi FAILED/retry tanpa rollback domain karena in-app tetap tersedia.
- PROCESSING basi >10 menit direclaim; reset unavailable tetap memberi respons generik dan correlation ID; kegagalan job reminder diulang scheduler dengan dedup yang sama.

## Logging dan monitoring

- Log hanya type/channel/ID/attempt/mapped provider code/outcome/correlation; larang email, nama, body, payload, token/hash, URL penuh, raw response, atau QR.
- Metrik lag/sent/failed/retry/unread/reset/reminder due/enqueued/skipped/delivery lag; alert outbox >5 menit, permanent email failure >10%/15 menit, reminder lag >5 menit, atau reset 5xx >2%/15 menit.

## Keamanan dan privasi

- Recipient/entity/action path diturunkan server dan memakai allowlist; cegah open redirect.
- Token CSPRNG 256-bit, compare constant-time, single-use/TTL 30 menit; respons/durasi seragam dan dummy work mencegah enumeration.
- Reset menaikkan authVersion dan hash async; credential hanya env; admin assistance wajib reason/least privilege/audit dan tidak melihat/menentukan password.

## Kinerja

- Inbox p95 ≤500 ms/20 item, mark-read ≤300 ms; worker batch 50, lima retry, timeout 5 detik, concurrency maksimum 5.
- Tambahan commit outbox p95 ≤50 ms; delivery asynchronous, reminder memakai keyset/batch, dan job 500 kandidat p95 ≤5 detik tanpa N+1.

## Aksesibilitas dan i18n

- Bell mempunyai accessible name/count; list semantic, fokus terlihat, dan live region hanya mengumumkan perubahan penting.
- Reset berlabel/autocomplete/error summary/keyboard; Bahasa Indonesia `id-ID`, timezone event, template semantic, layout 320/360 px, dan status nonwarna.

## Dependensi dan fallback provider

- Wajib memakai auth RFC-002, audit RFC-003, domain producer RFC-004–010, scheduler RFC-008, dashboard tidak menjadi dependency runtime.
- Email provider wajib dipilih dan dikonfigurasi melalui decision gate; adapter + deterministic fake wajib untuk test, dan RFC-013 tidak dapat selesai sebelum contract/delivery test provider lulus.
- Jika provider yang sudah dikonfigurasi mengalami kegagalan saat runtime, delivery email masuk retry/FAILED dan **in-app adalah fallback resmi**; transaksi domain tetap committed.
- Untuk F6 saat delivery email gagal, **admin-assisted reset** menjadi fallback demo yang diaudit; F6 tetap Should Have dan status self-service harus dilaporkan jujur.
- F51 wajib menggunakan scheduler RFC-008 yang telah tersedia. Ketiadaan scheduler invocation, email provider, atau bukti delivery reminder adalah blocker penyelesaian RFC.

## Kasus uji

- `F49-INT-001`: tiap domain event wajib menghasilkan satu in-app untuk recipient benar.
- `F49-SEC-002`: user A tidak membaca/menandai notifikasi user B.
- `F49-CONC-003`: replay outbox/dedup menghasilkan satu notification.
- `F50-CONTRACT-001`: fake/provider adapter memetakan success/transient/permanent tanpa rollback domain.
- `F50-INT-002`: lima retry lalu FAILED; in-app tetap tersedia.
- `F50-E2E-003`: seluruh jenis transaksional wajib menghasilkan delivery EMAIL dan IN_APP; konfigurasi provider hilang memblokir startup/release.
- `F6-SEC-001`: request existing/non-existing/OAuth-only tidak dapat dibedakan.
- `F6-INT-002`: token valid sekali; expired/used/revoked invalid; sesi lama gugur.
- `F6-CONC-003`: dua confirm bersamaan hanya satu berhasil.
- `F6-SEC-004`: admin assistance diaudit tanpa password/token di log.
- `F51-INT-001`: hanya Paid+Unused+Published pada T-24 menerima satu reminder.
- `F51-INT-002`: Cancelled/Used/non-Paid tidak mengirim; duplicate/concurrent scheduler menghasilkan satu outbox/delivery.
- `F51-E2E-003`: invocation scheduler bergate menghasilkan reminder in-app dan email; outage email mempertahankan in-app, retry, metric, dan alert.
- `F51-PERF-004`: batch 500 memenuhi budget tanpa N+1 dan lag p95 maksimum lima menit.

## Migrasi dan rollout

1. Pastikan regression RFC-001–012, backup preview, scheduler RFC-008 aktif, dan decision gate email ditutup dengan provider/configuration owner tercatat.
2. Terapkan enum/tabel/constraint/index additive; validasi template dan redaction.
3. Deploy outbox writer/worker pada preview dengan deterministic fake untuk shadow verification recipient/dedup, lalu jalankan contract test adapter provider terpilih.
4. Verifikasi F49 in-app dan F50 email bersama untuk seluruh event transaksional; simulasi transient/permanent provider failure dan pastikan in-app fallback.
5. Jalankan F51 dengan scheduler RFC-008, uji boundary T-24, replay/concurrency, cancellation/use race, delivery email, lag, dan alert; F6 diluncurkan sesuai status Should yang tervalidasi.
6. Rollback mematikan producer/worker/flags, mempertahankan inbox/token history; jangan drop tabel saat rollback aplikasi.

## Risiko dan mitigasi

- Notifikasi ganda/hilang: outbox transaksional, dedup key, locking, retry, lag alert.
- Account enumeration/takeover: respons generik, rate limit, token hash/TTL/single-use, authVersion.
- Provider outage runtime: in-app fallback, timeout, retry terbatas, alert, dan admin-assisted reset untuk F6; provider belum dipilih/dikonfigurasi memblokir penyelesaian RFC.
- PII/QR bocor: template allowlist, tautan authenticated, redaction snapshot.
- Reminder salah waktu: database UTC, timezone event, eligibility ulang saat dispatch.

## Kriteria penerimaan per fitur

- **F6:** self-service reset aman, generik, sekali pakai, kedaluwarsa, menggugurkan sesi lama; pada kegagalan delivery email runtime, admin-assisted fallback demo aman dan terdokumentasi.
- **F49:** hasil moderasi, pembayaran/tiket, pembatalan, dan refund muncul satu kali pada inbox recipient; owner dapat membaca/mark-read dan user lain ditolak.
- **F50:** provider bergate dan terkonfigurasi mengirim email transaksional wajib dengan status/retry/idempotensi tanpa menggagalkan domain; kegagalan runtime tetap memiliki in-app sebagai fallback.
- **F51:** scheduler RFC-008 mengirim tepat satu reminder in-app dan email kepada pemilik tiket Unused dari order Paid pada event Published di T-24; Cancelled/Used/non-Paid tidak menerima dan replay aman.

## Definition of Done

1. Seluruh RFC-001–012 dan regression suite lulus.
2. Migration, constraint, index, outbox concurrency, retry, cleanup, dan rollback diuji PostgreSQL.
3. F49/F50/F51 Must Have lulus penuh dan tidak boleh disabled/`NOT_APPLICABLE`; F6 tetap Should Have dengan status delivery dilaporkan jujur.
4. API memakai Zod, auth/ownership/CSRF/rate limit, envelope, correlation ID, no-store, dan respons anti-enumeration.
5. Unit/integration/concurrency/security/contract/E2E/performance lulus; token/redaction/template snapshot aman, provider failure terdegradasi ke in-app, dan reminder replay tepat satu.
6. UI/email Indonesia, responsif, keyboard-accessible, WCAG 2.1 AA, dan label SANDBOX jelas.
7. Format, Markdown, lint, typecheck, build, test, scan lulus tanpa blocker/Critical/High.
8. Email provider decision gate, konfigurasi fail-fast, contract test, scheduler invocation, mandatory email/reminder, lag metric, alert, dan runtime in-app fallback memiliki bukti.
9. Tidak ada push/SMS, QR email, hardening RFC-014, provider tanpa gate, scheduler baru, forward implementation, TODO, atau secret.
10. RFC-014 hanya dimulai setelah RFC ini disetujui.
