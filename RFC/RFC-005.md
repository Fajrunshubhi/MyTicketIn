# RFC-005 — Penulisan Event dan Tipe Tiket

## Metadata dan urutan
- Status: Diusulkan.
- Fitur yang dimiliki: **F9, F10, F15, F22, F76 (Must Have)**; fondasi authoring F65 (penyelesaian dimiliki RFC-008); kompleksitas: **Tinggi**.
- Prasyarat: **RFC-001, RFC-002, RFC-003, dan RFC-004 seluruhnya wajib selesai dan lulus**; pendahulu langsung: **RFC-004 — Organizer dan Moderasi**.
- Penerus langsung: **RFC-006 — Lifecycle Event dan Petugas**; hanya boleh dimulai setelah Definition of Done RFC ini lulus.
- Implementasi dibatasi pada authoring; publikasi, katalog, order, inventori terpakai, dan notifikasi belum dibuat.

## Sasaran dan keputusan
Organizer `APPROVED` dapat membuat banyak draft event, mengelola tipe tiket, gambar, mode inventori, section/kursi, denah statis, lalu mengajukan snapshot lengkap untuk review. PostgreSQL adalah source of truth; waktu disimpan `TIMESTAMPTZ`, harga integer Rupiah, dan setiap mutasi memakai ownership serta optimistic concurrency. Status lifecycle disediakan pada enum agar skema stabil, tetapi RFC ini hanya menghasilkan `DRAFT` dan `PENDING_REVIEW`; status lain baru boleh dihasilkan RFC-006. F65 belum selesai di sini: hold, ketersediaan runtime, dan checkout kursi dimiliki RFC-008.

## Ruang lingkup
- CRUD draft event milik organizer Approved dengan field tatap muka lengkap, slug stabil, waktu, dan zona waktu.
- CRUD/pengurutan beberapa tipe tiket beserta validasi harga, kuota, limit, dan periode penjualan.
- Pemilihan tepat satu `inventory_mode` per event: `GENERAL_ADMISSION`, `ZONED`, atau `RESERVED_SEATING`.
- Authoring `VenueSection`, `EventSeat`, dan unggahan `SeatMapAsset` (gambar denah statis + alt text/legenda) untuk mode zoned/reserved; bukan peta klik atau editor drag-and-drop.
- Upload/finalisasi/penghapusan lunak satu gambar utama melalui adapter object storage.
- Placeholder jika gate storage belum ditutup; pengajuan atomik `DRAFT → PENDING_REVIEW`; audit/analytics memakai RFC-003.

## Non-scope
- Keputusan admin, lifecycle, preview, dan petugas (RFC-006); katalog/search/filter/publik (RFC-007).
- Ketersediaan terpakai, order, reservasi, dan locking kuota (RFC-008).
- Payment, tiket, QR, notifikasi, email, KYC, uang nyata, promo, atau file selain gambar event dan denah statis.
- Hold kursi, ketersediaan runtime, checkout, atau penyelesaian F65 (RFC-008).
- Clickable map, editor drag-and-drop, orphan-seat optimization, atau collaborative map editing.
- AI yang mengubah atau menerbitkan event secara otomatis; F76 hanya memberi saran draft yang harus dipilih, diterapkan, dan disimpan eksplisit oleh organizer.
- Pemilihan provider storage tanpa decision gate; filesystem runtime tidak boleh menjadi fallback.

## Gap kondisi saat ini
- Repository hanya memiliki auth prototype/model `User`; belum ada module/skema event, tipe tiket, gambar, atau constraint domain.
- RFC-004 berhenti pada capability organizer; UI belum memiliki workspace, form event, atau test authoring.

## Aturan domain
- Event baru selalu `DRAFT`; hanya owner organizer Approved dapat membaca atau memutasi.
- `PENDING_REVIEW` read-only bagi organizer sampai keputusan RFC-006.
- Setiap event memiliki tepat satu `inventory_mode`; `RESERVED_SEATING` wajib punya section, kursi, denah READY, dan alt text/legenda sebelum submit.
- Label kursi unik per event; section merepresentasikan kategori/area yang terhubung ke tipe tiket berharga.
- Judul trim 3–160, deskripsi 20–10.000, kategori 2–80, venue 2–160 karakter.
- `starts_at < ends_at`; keduanya harus masa depan saat submit, bukan wajib saat menyimpan draft.
- Zona waktu wajib IANA dan salah satu `Asia/Jakarta`, `Asia/Makassar`, `Asia/Jayapura`.
- Event harus memiliki alamat, kota, provinsi, syarat, kontak, dan minimal satu tipe tiket valid saat submit.
- Harga tipe tiket integer `0..1.000.000.000` Rupiah, kuota `> 0`, limit per akun/event `1..5`.
- `sale_starts_at < sale_ends_at <= event.starts_at`.
- Nama tipe unik case-insensitive per event; penghapusan masih hard-delete hanya selama belum ada consumer commerce.
- Gambar READY maksimum satu yang primary; placeholder bukan row database.
- Edit yang mengubah field authoring selalu menaikkan `version`.

## Diagram aliran data tekstual
1. Session menghasilkan `userId`; capability menghasilkan `organizerProfileId`.
2. Input dinormalisasi, divalidasi Zod, lalu service memeriksa ownership dari database.
3. Draft event dan tipe tiket ditulis dengan `expectedVersion`; zero update menjadi conflict.
4. Upload meminta target dari adapter, client mengunggah langsung, lalu finalize memverifikasi metadata provider.
5. Submit mengunci event dan seluruh tipe tiket, memvalidasi aggregate, mengubah status, mencatat audit, lalu commit.
6. Analytics `event_created`/`event_submitted` dikirim setelah commit; kegagalannya tidak membatalkan data.
7. Tidak ada data yang dibaca oleh route publik sebelum RFC-007.

### Enum

- `terms VARCHAR(5000) NOT NULL`; `contact_email VARCHAR(254) NOT NULL`.
- `contact_phone VARCHAR(32) NULL`.

- `inventory_mode inventory_mode NOT NULL DEFAULT 'GENERAL_ADMISSION'`.

- Constraint `events_slug_format_chk`: slug lowercase pola `^[a-z0-9]+(?:-[a-z0-9]+)*$`.

- `event_id TEXT NOT NULL REFERENCES events(id) ON DELETE RESTRICT`.

- Unique functional index `event_ticket_types_event_name_key(event_id, lower(name))`.
- Index `event_ticket_types_event_order_idx(event_id, sort_order ASC, id ASC)`.

## Kontrak API
Semua error memakai envelope standar RFC-001 dengan `correlationId`; mutasi wajib session ACTIVE, CSRF, rate limit, organizer Approved, dan ownership.

### Event
- `POST /api/organizer/events`; request `{title,description,category,venueName,addressLine,city,province,timezone,startsAt,endsAt,terms,contactEmail,contactPhone?}`; respons `201 {event:{id,slug,status:"DRAFT",version}}`.
- `GET /api/organizer/events?cursor&limit=1..100&status`; respons `200 {items:[safeSummary],nextCursor|null}`; default 25; `private,no-store`.
- `GET /api/organizer/events/{id}`; respons `200 {event,ticketTypes,sections,seats,seatMap,image,version}` atau 404 tanpa membocorkan tenant.
- `PATCH /api/organizer/events/{id}`; request field lengkap termasuk `inventoryMode` + `expectedVersion`; hanya DRAFT; respons `200 {event,version}`.
- `DELETE /api/organizer/events/{id}`; request `{expectedVersion}`; hanya DRAFT tanpa consumer; respons `204`.
- `POST /api/organizer/events/{id}/submit`; request `{expectedVersion}`; respons `200 {id,status:"PENDING_REVIEW",submittedAt,version}`.

### Tipe tiket
- `POST /api/organizer/events/{id}/ticket-types`; request `{name,description?,priceRupiah,quota,maxPerAccount,saleStartsAt,saleEndsAt,sortOrder}`; respons 201 record+version.

### Section, kursi, dan denah
- `PUT /api/organizer/events/{id}/sections`; request daftar section terhubung ke ticket type; hanya DRAFT.
- `PUT /api/organizer/events/{id}/seats`; request daftar `{sectionId,label}` unik; hanya `RESERVED_SEATING` DRAFT.
- `POST /api/organizer/events/{id}/seat-map`; upload denah statis + `{altText,legend}` melalui ObjectStoragePort yang sama dengan F22.
- `PATCH /api/organizer/events/{id}/ticket-types/{ticketTypeId}`; request field lengkap + `expectedVersion`; respons 200.
- `DELETE /api/organizer/events/{id}/ticket-types/{ticketTypeId}`; request `{expectedVersion}`; respons 204.
- Seluruh mutasi hanya ketika event DRAFT dan mengunci event agar tidak balapan dengan submit.

### Gambar
- `POST /api/organizer/events/{id}/images/upload-intents`; request `{fileName,mimeType,byteSize,altText}`; respons `201 {assetId,upload:{url,method,headers},expiresAt}`; URL tidak dicatat di log.
- `POST /api/organizer/events/{id}/images/{assetId}/finalize`; request `{expectedEventVersion}`; verifikasi object `HEAD`; respons `200 {image:{id,url,altText},eventVersion}`.
- `DELETE /api/organizer/events/{id}/images/{assetId}`; request `{expectedEventVersion}`; respons 204 dan cleanup provider asynchronous/best effort.
- Jika storage gate belum dipilih, endpoint gambar mengembalikan `503 STORAGE_NOT_CONFIGURED`; form tetap dapat submit dengan placeholder.

## State dan caching
- Database adalah state authoring; form draft belum disimpan hanya memakai local React state.
- Daftar/detail organizer `private, no-store`; status/filter/cursor berada di URL.
- Tidak ada optimistic update untuk status atau tipe tiket; refresh data server setelah mutasi.
- Upload progress lokal; metadata READY hanya setelah finalize server.
- Tidak ada public cache, global state library, atau cache capability.

## Algoritma/pseudocode
```text
submit(eventId, expectedVersion, actor):
  organizer = requireApprovedOrganizer(actor)
  transaction:
    event = SELECT ... FOR UPDATE; require owner + DRAFT + version
    types = SELECT ticket types FOR UPDATE
    validate required event fields, future time, >=1 type
    for each type: validate sale window against event start
    UPDATE event SET PENDING_REVIEW, submitted_at=db_now, version=version+1
    append audit allowlist; commit
  emit event_submitted

finalizeImage(assetId):
  verify provider metadata equals intent; reject mismatch
  transaction lock event/assets; mark old primary false; mark asset READY primary
```

## Dependensi dan fallback
- Wajib RFC-001–004: Prisma/migration, session/RBAC, audit/analytics, organizer capability.
- F22 membutuhkan keputusan provider object storage; adapter dilarang mengikat domain pada SDK.
- Fallback resmi adalah placeholder, bukan filesystem/base64/database blob; F22 baru dinyatakan lulus penuh setelah provider dipilih.
- Analytics gagal tidak rollback; audit/database gagal rollback; cleanup object gagal masuk retry log tanpa menghapus metadata historis.

## Kasus uji
- `F9-INT-001`/`F9-SEC-002`: organizer Approved mengelola banyak draft miliknya; cross-tenant/non-Approved ditolak.
- `F9-CONC-003`: expectedVersion sama hanya satu mutasi berhasil.
- `F9-INT-004`: Pending read-only dan delete ditolak.
- `F10-UNIT-001`/`F10-INT-002`: matriks kelengkapan/waktu/zona exhaustive; submit atomik dan rollback tanpa tipe.
- `F15-UNIT-001`: batas harga, quota, limit, dan sale window.
- `F15-INT-002`/`F15-CONC-003`: nama unik case-insensitive per event; edit versus submit tetap valid.
- `F22-CONTRACT-001`: fake deterministic memenuhi upload/head/delete contract.
- `F22-SEC-002`/`F22-E2E-003`: upload invalid/cross-tenant ditolak; READY tampil dan placeholder berfungsi.

## Migrasi dan rollout
1. Pastikan regression RFC-001–004, backup preview, dan decision gate storage tercatat.
2. Terapkan enum/tabel/constraint/index additive; seed eksplisit hanya test.
3. Deploy route tertutup feature flag organizer, jalankan contract/integration/E2E.
4. Buka authoring lalu submit; pantau conflict, audit, dan orphan.
5. Rollback menutup route dan mempertahankan tabel/data; jangan drop enum/tabel pada rollback aplikasi.

## Risiko dan mitigasi
- Data review berubah atau waktu lokal ambigu: Pending read-only, row lock/version, IANA allowlist, UTC persistence.
- Slug collision atau upload berbahaya/yatim: suffix/key acak, unique retry, allowlist, cleanup retry, dan placeholder tanpa SDK diam-diam.
- Validasi kuota terpakai belum relevan: belum ada order/reservasi; RFC-008 wajib memperluas update service dan regression F15.

## Kriteria penerimaan per fitur
- **F9:** organizer Approved mengelola banyak event lengkap miliknya; Pending terkunci; event memiliki waktu/zona/ownership/version valid; penghapusan tidak menyentuh data historis.
- **F10:** hanya aggregate lengkap dengan minimal satu tipe valid dapat berpindah DRAFT→PENDING_REVIEW secara atomik dan auditable; event pending belum publik/dapat dibeli.
- **F15:** banyak tipe menyimpan harga Rupiah, kuota, jadwal, limit, urutan dan snapshot authoring valid; perubahan harga tidak memiliki efek retroaktif karena commerce belum ada.
- **F22:** file valid tersimpan di object storage melalui adapter dan tampil sebagai gambar utama; invalid ditolak; placeholder dipakai tanpa filesystem. Jika provider belum dipilih, F22 tetap open dan RFC tidak boleh diklaim selesai penuh.
- **F76:** organizer Approved dapat mengunggah poster secara sementara untuk meminta saran draft terstruktur, melihat confidence serta field missing/ambiguous, memilih field allowlist yang akan diterapkan ke form, lalu menyimpannya melalui command authoring biasa; tidak ada submit/publish/save otomatis dan kegagalan AI tidak merusak draft.

## Definition of Done
1. Seluruh prasyarat RFC-001–004 dan regression suite lulus.
2. Migration eksak, constraint, indeks, Prisma mapping, dan rollback strategy diuji di PostgreSQL preview.
3. Endpoint memakai Zod, auth, capability, ownership, CSRF/rate limit, error envelope, dan correlation ID.
4. Unit/integration/concurrency/security/contract/E2E F9/F10/F15/F22/F76 lulus; branch coverage module ≥90%.
5. Audit atomik dan analytics after-commit terverifikasi tanpa PII.
6. UI Indonesia responsif dan WCAG 2.1 AA; format Rupiah/timezone benar.
7. Format, lint, typecheck, build, test, dependency/security scan lulus tanpa Critical/High.
8. Tidak ada katalog, moderation decision, petugas, order, payment, ticket, notification, hold kursi, auto-save/auto-submit/auto-publish AI, provider tak disetujui, TODO, atau secret. Clickable map tidak diimplementasikan.
9. RFC-006 baru dimulai setelah dokumen dan implementasi ini disetujui.

## Ekstensi F76 — AI/OCR Poster menjadi Saran Draft

Bagian ini menambah F76 ke kepemilikan RFC-005 tanpa mengubah urutan RFC. Jika ada kalimat sebelumnya yang menyiratkan seluruh provider baru berada di luar scope, pengecualian sempitnya adalah `AiInferencePort` setelah gate F76 lulus. Upload poster F76 diproses sementara dan tidak bergantung pada F22; object storage tetap hanya menangani gambar event persisten dan AI tidak memperoleh akses langsung ke SDK storage.

### Keputusan dan batas kepercayaan
- Poster, byte gambar, metadata EXIF, teks OCR, dan semua instruksi yang tampak di poster adalah input tidak tepercaya.
- AI hanya boleh mengusulkan field allowlist yang eksplisit terbaca pada poster: `title`, `description`, `category`, `venueName`, `addressLine`, `city`, `province`, `timezone`, `startsAt`, `endsAt`, `terms`, `contactEmail`, `contactPhone`, dan `ticketTypes[]` berisi `name`, `priceRupiah`, `saleStartsAt`, `saleEndsAt`. Field yang tidak terbaca wajib ditandai missing/ambiguous, bukan dikarang. `quota`, `maxPerAccount`, `sortOrder`, `status`, `slug`, ownership, moderation, dan seluruh identifier tidak boleh dihasilkan atau diubah AI.
- Setiap saran berbentuk `{field,value,confidence:"HIGH"|"MEDIUM"|"LOW"}`. Respons juga wajib memiliki `missingFields[]` dan `ambiguousFields:[{field,reasonCode}]`; reason code allowlist adalah `MULTIPLE_VALUES`, `UNREADABLE`, `INCOMPLETE_DATE`, `MISSING_TIMEZONE`, `UNSUPPORTED_FORMAT`.
- Nilai AI belum dipercaya: output divalidasi strict Zod, dinormalisasi, dan menjalani validator domain RFC-005 yang sama. Unknown key, nesting tambahan, URL, HTML aktif, atau nilai di luar batas dibuang dengan menolak seluruh hasil.
- Tombol “Terapkan yang dipilih” hanya menyalin saran terpilih ke local form state dan menampilkan diff. Tombol “Simpan draft” terpisah memanggil endpoint authoring yang sudah ada dengan `expectedVersion`. AI tidak pernah memanggil submit, resubmit, moderasi, atau publish.
- Saran tidak menjadi source of truth dan tidak dipersistenkan. Refresh sebelum save menghilangkan saran; hanya nilai yang dipilih organizer dan lolos command authoring menjadi data event.

### Gate provider/model/privacy/cost yang memblokir
F76 tidak boleh diaktifkan, dinyatakan lulus, atau diganti fake pada runtime sebelum Product Owner mencatat keputusan atas: provider dan region pemrosesan; model+versi; dukungan vision/OCR; kebijakan penggunaan data untuk training; retensi provider dengan target zero-retention dan batas keras maksimum 24 jam; subprocessor/privacy terms; batas biaya per request dan anggaran bulanan; timeout, quota, serta prosedur disable. Credential, endpoint, atau model tidak boleh memiliki fallback.

Gate harus menghasilkan allowlist konfigurasi `AI_PROVIDER`, `AI_MODEL`, `AI_MAX_IMAGE_BYTES`, `AI_REQUEST_TIMEOUT_MS`, `AI_DAILY_BUDGET_RUPIAH`, dan mode `AI_POSTER_SUGGESTIONS_ENABLED`. Startup fail-fast saat flag aktif tetapi konfigurasi/secret tidak lengkap. Provider/model hanya metadata operasional server, tidak dapat dipilih client.

### Skema dan retensi eksak
- Migration `0005_event_authoring` tidak menambah tabel/kolom AI. Tidak ada tabel OCR, prompt, completion, embedding, atau suggestion.
- Gambar sumber diterima sebagai upload sementara pada request F76, maksimum 5 MiB, dengan MIME `image/jpeg|image/png|image/webp`, magic-byte, dan dimensi `1..8000` yang diverifikasi server. Poster tidak otomatis menjadi `event_image_assets`; organizer tetap memakai alur F22 secara terpisah jika ingin menjadikannya gambar publik.
- Byte gambar dan teks OCR hanya berada di memori selama request, tidak masuk cache/queue/temp file, dan referensinya dilepas setelah response/timeout.
- Provider wajib dikonfigurasi tidak menyimpan konten; bila zero-retention tidak tersedia, gate wajib membuktikan auto-delete paling lambat 24 jam. Metadata log allowlist (`actorId`, `eventId`, provider/model code, outcome, token/image-size bucket, latency, correlation ID) memiliki retensi 30 hari.
- Raw image, thumbnail request, OCR text, system/user prompt, model completion, suggested values, filename, kontak, dan presigned URL dilarang di log, analytics, audit before/after, trace, atau error tracker.

### Port provider-netral dan fake
```text
AiInferencePort:
  suggestEventDraftFromPoster({
    image: ReadableByteStream,
    mimeType,
    locale: "id-ID",
    timezoneAllowlist,
    outputSchemaVersion: "event-poster-suggestion.v1"
  }) -> {
    suggestions: FieldSuggestion[],
    missingFields: AllowedField[],
    ambiguousFields: AmbiguousField[]
  }
```
- Adapter mengenkapsulasi OCR/vision dan SDK; application/domain tidak mengimpor tipe provider.
- Request provider memakai prompt statis berversi, output JSON schema strict, temperature deterministik terendah yang tersedia, tanpa tool/function call, browsing, retrieval, URL fetch, atau akses database.
- Instruksi keamanan menyatakan seluruh teks poster adalah data yang harus diekstrak, bukan instruksi. Delimiter acak per request, schema allowlist, batas output 32 KiB, timeout 15 detik, dan parser non-evaluating wajib.
- `DeterministicFakeAiInferencePort` memetakan fixture hash ke hasil tetap untuk success, missing, ambiguous, malformed, prompt-injection, timeout, dan provider failure; fake hanya dapat di-wire pada automated test.

### Kontrak endpoint dan UI
`POST /api/organizer/events/{id}/ai/poster-suggestions`
- Auth session ACTIVE + organizer Approved + ownership; event hanya `DRAFT|REJECTED`; CSRF; `Content-Type: multipart/form-data`.
- Request memuat `poster` dan `expectedEventVersion`. Server memverifikasi versi tetapi tidak menaikkannya karena endpoint read/inference-only; file tidak dipersistenkan.
- Rate limit: 3 request/menit dan 20 request/hari per user, 40/hari per organizer; concurrency maksimum satu request aktif per event; budget gate dapat mengembalikan unavailable.
- Respons 200 `{schemaVersion:"event-poster-suggestion.v1",suggestions,missingFields,ambiguousFields,disclaimer}`; response `private,no-store`, maksimum 32 KiB.
- Apply dilakukan lokal per checkbox; save memakai `PATCH /api/organizer/events/{id}` dan endpoint ticket type RFC-005. Submit tetap endpoint terpisah dan tidak boleh dipanggil sebagai side effect.

Error tambahan: `AI_NOT_CONFIGURED` (503), `AI_BUDGET_EXCEEDED` (503), `AI_RATE_LIMITED` (429), `AI_REQUEST_IN_PROGRESS` (409), `AI_INPUT_UNSUPPORTED` (422), `AI_OUTPUT_INVALID` (502), `AI_PROVIDER_UNAVAILABLE` (503), `AI_TIMEOUT` (504). Pesan UI selalu menawarkan input manual dan tidak menampilkan payload/provider detail.

### Algoritma
```text
suggestFromPoster(actor,eventId,poster,expectedVersion):
  authorize Approved owner; load event; require DRAFT|REJECTED and version
  enforce user+organizer rate, one-flight event, and approved budget
  stream bounded multipart bytes; strip/ignore EXIF; verify MIME, magic bytes and dimensions
  call AiInferencePort with static schema/prompt and untrusted-data delimiters
  strict-parse complete response; reject unknown keys or disallowed fields
  normalize each value; run existing field validators without persisting
  return suggestions + missing + ambiguous; always clear in-memory buffers

applyAndSave(selected):
  copy only explicitly checked, still-valid suggestions to local form
  show before/after and validation errors
  organizer presses Save; existing authoring command checks expectedVersion
```

### Keamanan, monitoring, pengujian, dan rollout
- SSRF dicegah karena adapter menerima byte stream, bukan URL dari model/client. OCR text tidak pernah disisipkan sebagai role system/developer dan model output tidak dirender sebagai HTML.
- Metrik hanya outcome, latency, rate-limit, malformed-output, injection-fixture rejection, image-size bucket, dan estimasi biaya agregat; tidak ada konten. Alert pada biaya ≥80% budget, output invalid >5%/15 menit, atau error provider >10%/15 menit.
- `F76-UNIT-001`: allowlist/schema/confidence/missing/ambiguous dan validator domain exhaustive.
- `F76-SEC-002`: poster berisi “abaikan instruksi”, SQL/status/publish/URL/HTML tidak dapat keluar atau dieksekusi; cross-tenant dan file dengan MIME/magic-byte/dimensi invalid ditolak.
- `F76-PRIV-003`: assertion sink log/trace/audit tidak menerima raw image, OCR, prompt, completion, atau suggested value; buffer cleanup dan retensi provider diuji dari konfigurasi.
- `F76-CONTRACT-004`: fake deterministik serta adapter memenuhi schema, timeout, size cap, malformed output, dan provider failure.
- `F76-E2E-005`: suggest → pilih sebagian → apply → review diff → save; refresh sebelum save tidak mengubah database; submit tidak terjadi.
- `F76-RATE-006`: batas user/organizer/concurrency/budget menghasilkan error stabil dan input manual tetap tersedia.

Rollout: (1) gate tertulis dan DPIA-lite data uji; (2) adapter+fake dan test tanpa network; (3) preview allowlist organizer dengan poster sintetis; (4) observasi biaya/error tanpa menyimpan konten; (5) aktivasi bertahap lewat kill switch. Rollback mematikan flag dan mempertahankan authoring manual; tidak ada data AI yang perlu dimigrasi/dihapus.

Definition of Done tambahan F76:
1. Gate provider/model/privacy/cost disetujui dan konfigurasi fail-fast/kill switch diuji.
2. Port provider-netral, adapter, dan deterministic fake lulus contract/security/privacy tests.
3. Tidak ada persistence atau log raw image/OCR/prompt/completion/saran; batas retensi 24 jam provider dan 30 hari metadata terbukti.
4. Explicit select/apply/save dan larangan auto-save/submit/publish dibuktikan integration/E2E.
5. Rate, budget, timeout, malformed output, prompt injection, ownership, accessibility, serta fallback input manual lulus.
