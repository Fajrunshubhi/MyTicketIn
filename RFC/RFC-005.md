# RFC-005 — Penulisan Event dan Tipe Tiket

## Metadata dan urutan
- Status: Diusulkan.
- Fitur yang dimiliki: **F9, F10, F15, F22**; kompleksitas: **Sedang–Tinggi**.
- Prasyarat: **RFC-001, RFC-002, RFC-003, dan RFC-004 seluruhnya wajib selesai dan lulus**; pendahulu langsung: **RFC-004 — Organizer dan Moderasi**.
- Penerus langsung: **RFC-006 — Lifecycle Event dan Petugas**; hanya boleh dimulai setelah Definition of Done RFC ini lulus.
- Implementasi dibatasi pada authoring; publikasi, katalog, order, inventori terpakai, dan notifikasi belum dibuat.

## Sasaran dan keputusan
Organizer `APPROVED` dapat membuat banyak draft event, mengelola tipe tiket, gambar, lalu mengajukan snapshot lengkap untuk review. PostgreSQL adalah source of truth; waktu disimpan `TIMESTAMPTZ`, harga integer Rupiah, dan setiap mutasi memakai ownership serta optimistic concurrency. Status lifecycle disediakan pada enum agar skema stabil, tetapi RFC ini hanya menghasilkan `DRAFT` dan `PENDING_REVIEW`; status lain baru boleh dihasilkan RFC-006.

## Ruang lingkup
- CRUD draft event milik organizer Approved dengan field tatap muka lengkap, slug stabil, waktu, dan zona waktu.
- CRUD/pengurutan beberapa tipe tiket beserta validasi harga, kuota, limit, dan periode penjualan.
- Upload/finalisasi/penghapusan lunak satu gambar utama melalui adapter object storage.
- Placeholder jika gate storage belum ditutup; pengajuan atomik `DRAFT → PENDING_REVIEW`; audit/analytics memakai RFC-003.

## Non-scope
- Keputusan admin, lifecycle, preview, dan petugas (RFC-006); katalog/search/filter/publik (RFC-007).
- Ketersediaan terpakai, order, reservasi, dan locking kuota (RFC-008).
- Payment, tiket, QR, notifikasi, email, KYC, uang nyata, kursi, promo, atau file selain gambar.
- Pemilihan provider storage tanpa decision gate; filesystem runtime tidak boleh menjadi fallback.

## Gap kondisi saat ini
- Repository hanya memiliki auth prototype/model `User`; belum ada module/skema event, tipe tiket, gambar, atau constraint domain.
- RFC-004 berhenti pada capability organizer; UI belum memiliki workspace, form event, atau test authoring.

## Aturan domain
- Event baru selalu `DRAFT`; hanya owner organizer Approved dapat membaca atau memutasi.
- `PENDING_REVIEW` read-only bagi organizer sampai keputusan RFC-006.
- Judul trim 3–160, deskripsi 20–10.000, kategori 2–80, venue 2–160 karakter.
- `starts_at < ends_at`; keduanya harus masa depan saat submit, bukan wajib saat menyimpan draft.
- Zona waktu wajib IANA dan salah satu `Asia/Jakarta`, `Asia/Makassar`, `Asia/Jayapura`.
- Event harus memiliki alamat, kota, provinsi, syarat, kontak, dan minimal satu tipe tiket valid saat submit.
- Harga tipe tiket `>= 0`, kuota `> 0`, limit per akun/event `1..5`.
- `sale_starts_at < sale_ends_at <= event.starts_at`.
- Nama tipe unik case-insensitive per event; penghapusan masih hard-delete hanya selama belum ada consumer commerce.
- Gambar READY maksimum satu yang primary; placeholder bukan row database.
- Edit yang mengubah field authoring selalu menaikkan `version`.

## Diagram aliran data tekstual
1. Session menghasilkan `userId`; capability menghasilkan `organizerProfileId`.
2. Input dinormalisasi, divalidasi Zod, lalu service memeriksa ownership dari database.
3. Draft event dan tipe tiket ditulis dengan `expectedVersion`; zero update menjadi conflict.
4. Upload meminta target dari adapter, client mengunggah langsung, lalu finalize memverifikasi metadata provider.
5. Submit mengunci event dan seluruh tipe tiket, memvalidasi aggregate, mengubah status, mencatat audit, lalu commit.
6. Analytics `event_created`/`event_submitted` dikirim setelah commit; kegagalannya tidak membatalkan data.
7. Tidak ada data yang dibaca oleh route publik sebelum RFC-007.

## Skema database eksak
Migration: `0005_event_authoring`.

### Enum
- `event_status`: `DRAFT`, `PENDING_REVIEW`, `PUBLISHED`, `REJECTED`, `CANCELLED`, `COMPLETED`.
- `image_asset_status`: `PENDING_UPLOAD`, `READY`, `FAILED`, `DELETED`.
- Nilai lifecycle selain dua nilai pertama dicadangkan dan tidak memiliki command pada RFC ini.

### Tabel `events`
- `id TEXT PRIMARY KEY` (CUID).
- `organizer_profile_id TEXT NOT NULL REFERENCES organizer_profiles(id) ON DELETE RESTRICT`.
- `slug VARCHAR(180) NOT NULL`; `title VARCHAR(160) NOT NULL`; `description VARCHAR(10000) NOT NULL`.
- `category VARCHAR(80) NOT NULL`; `venue_name VARCHAR(160) NOT NULL`.
- `address_line VARCHAR(500) NOT NULL`; `city VARCHAR(100) NOT NULL`; `province VARCHAR(100) NOT NULL`.
- `timezone VARCHAR(64) NOT NULL`; `starts_at TIMESTAMPTZ NOT NULL`; `ends_at TIMESTAMPTZ NOT NULL`.
- `terms VARCHAR(5000) NOT NULL`; `contact_email VARCHAR(254) NOT NULL`.
- `contact_phone VARCHAR(32) NULL`.
- `status event_status NOT NULL DEFAULT 'DRAFT'`.
- `submitted_at TIMESTAMPTZ NULL`.
- `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `version INTEGER NOT NULL DEFAULT 1`.
- Constraint `events_slug_format_chk`: slug lowercase pola `^[a-z0-9]+(?:-[a-z0-9]+)*$`.
- Constraint `events_time_chk`: `starts_at < ends_at`.
- Constraint trim/panjang untuk semua text wajib, email lowercase, timezone allowlist, dan `version > 0`.
- Constraint `events_submission_chk`: `PENDING_REVIEW` wajib `submitted_at IS NOT NULL`; `DRAFT` wajib null.
- Unique index `events_slug_key(slug)`.
- Index `events_organizer_updated_idx(organizer_profile_id, updated_at DESC, id DESC)`.
- Index `events_status_starts_idx(status, starts_at ASC, id ASC)`.

### Tabel `event_ticket_types`
- `id TEXT PRIMARY KEY` (CUID).
- `event_id TEXT NOT NULL REFERENCES events(id) ON DELETE RESTRICT`.
- `name VARCHAR(120) NOT NULL`; `description VARCHAR(1000) NULL`.
- `price_rupiah BIGINT NOT NULL`; `quota INTEGER NOT NULL`; `max_per_account INTEGER NOT NULL DEFAULT 5`.
- `sale_starts_at TIMESTAMPTZ NOT NULL`; `sale_ends_at TIMESTAMPTZ NOT NULL`.
- `sort_order SMALLINT NOT NULL DEFAULT 0`.
- `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `version INTEGER NOT NULL DEFAULT 1`.
- Constraints: harga `>= 0`, kuota `> 0`, limit `BETWEEN 1 AND 5`, urutan `>= 0`, waktu jual mulai `<` selesai, version `> 0`.
- Unique functional index `event_ticket_types_event_name_key(event_id, lower(name))`.
- Index `event_ticket_types_event_order_idx(event_id, sort_order ASC, id ASC)`.
- Aturan `sale_ends_at <= events.starts_at` divalidasi di transaction karena CHECK lintas tabel tidak valid di PostgreSQL.

### Tabel `event_image_assets`
- `id TEXT PRIMARY KEY` (CUID).
- `event_id TEXT NOT NULL REFERENCES events(id) ON DELETE RESTRICT`.
- `storage_key VARCHAR(512) NOT NULL`; `original_name VARCHAR(255) NOT NULL`.
- `mime_type VARCHAR(64) NOT NULL`; `byte_size INTEGER NOT NULL`.
- `width INTEGER NULL`, `height INTEGER NULL`.
- `alt_text VARCHAR(300) NOT NULL`.
- `status image_asset_status NOT NULL DEFAULT 'PENDING_UPLOAD'`; `is_primary BOOLEAN NOT NULL DEFAULT FALSE`.
- `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `deleted_at TIMESTAMPTZ NULL`.
- Constraints: MIME `image/jpeg|image/png|image/webp`, byte `1..5242880`, dimensi null bersama atau masing-masing `1..8000`, alt trim 3–300.
- Constraint: READY wajib dimensi; DELETED wajib `deleted_at`; non-DELETED wajib null.
- Unique index `event_image_assets_storage_key_key(storage_key)`.
- Partial unique index `event_image_assets_one_primary_key(event_id) WHERE is_primary AND status='READY'`.
- Index `event_image_assets_event_status_idx(event_id,status)`.

## Kontrak API
Semua error memakai envelope standar RFC-001 dengan `correlationId`; mutasi wajib session ACTIVE, CSRF, rate limit, organizer Approved, dan ownership.

### Event
- `POST /api/organizer/events`; request `{title,description,category,venueName,addressLine,city,province,timezone,startsAt,endsAt,terms,contactEmail,contactPhone?}`; respons `201 {event:{id,slug,status:"DRAFT",version}}`.
- `GET /api/organizer/events?cursor&limit=1..100&status`; respons `200 {items:[safeSummary],nextCursor|null}`; default 25; `private,no-store`.
- `GET /api/organizer/events/{id}`; respons `200 {event,ticketTypes,image,version}` atau 404 tanpa membocorkan tenant.
- `PATCH /api/organizer/events/{id}`; request field lengkap + `expectedVersion`; hanya DRAFT; respons `200 {event,version}`.
- `DELETE /api/organizer/events/{id}`; request `{expectedVersion}`; hanya DRAFT tanpa consumer; respons `204`.
- `POST /api/organizer/events/{id}/submit`; request `{expectedVersion}`; respons `200 {id,status:"PENDING_REVIEW",submittedAt,version}`.

### Tipe tiket
- `POST /api/organizer/events/{id}/ticket-types`; request `{name,description?,priceRupiah,quota,maxPerAccount,saleStartsAt,saleEndsAt,sortOrder}`; respons 201 record+version.
- `PATCH /api/organizer/events/{id}/ticket-types/{ticketTypeId}`; request field lengkap + `expectedVersion`; respons 200.
- `DELETE /api/organizer/events/{id}/ticket-types/{ticketTypeId}`; request `{expectedVersion}`; respons 204.
- Seluruh mutasi hanya ketika event DRAFT dan mengunci event agar tidak balapan dengan submit.

### Gambar
- `POST /api/organizer/events/{id}/images/upload-intents`; request `{fileName,mimeType,byteSize,altText}`; respons `201 {assetId,upload:{url,method,headers},expiresAt}`; URL tidak dicatat di log.
- `POST /api/organizer/events/{id}/images/{assetId}/finalize`; request `{expectedEventVersion}`; verifikasi object `HEAD`; respons `200 {image:{id,url,altText},eventVersion}`.
- `DELETE /api/organizer/events/{id}/images/{assetId}`; request `{expectedEventVersion}`; respons 204 dan cleanup provider asynchronous/best effort.
- Jika storage gate belum dipilih, endpoint gambar mengembalikan `503 STORAGE_NOT_CONFIGURED`; form tetap dapat submit dengan placeholder.

## State dan caching
- Database adalah state authoring; form draft belum disimpan hanya memakai local React state.
- Daftar/detail organizer `private, no-store`; status/filter/cursor berada di URL.
- Tidak ada optimistic update untuk status atau tipe tiket; refresh data server setelah mutasi.
- Upload progress lokal; metadata READY hanya setelah finalize server.
- Tidak ada public cache, global state library, atau cache capability.

## Algoritma/pseudocode
```text
submit(eventId, expectedVersion, actor):
  organizer = requireApprovedOrganizer(actor)
  transaction:
    event = SELECT ... FOR UPDATE; require owner + DRAFT + version
    types = SELECT ticket types FOR UPDATE
    validate required event fields, future time, >=1 type
    for each type: validate sale window against event start
    UPDATE event SET PENDING_REVIEW, submitted_at=db_now, version=version+1
    append audit allowlist; commit
  emit event_submitted

finalizeImage(assetId):
  verify provider metadata equals intent; reject mismatch
  transaction lock event/assets; mark old primary false; mark asset READY primary
```

## Error, logging, dan monitoring
- Kode: `EVENT_NOT_FOUND`, `EVENT_ACCESS_DENIED`, `EVENT_STATUS_INVALID`, `EVENT_VERSION_CONFLICT`, `EVENT_INCOMPLETE`, `EVENT_TIME_INVALID`, `EVENT_SLUG_CONFLICT`, `TICKET_TYPE_INVALID`, `TICKET_TYPE_NAME_EXISTS`, `TICKET_TYPE_REQUIRED`, `STORAGE_NOT_CONFIGURED`, `IMAGE_TYPE_INVALID`, `IMAGE_TOO_LARGE`, `IMAGE_METADATA_MISMATCH`, `RATE_LIMITED`.
- Log: action, event/organizer/asset ID, status, duration, correlation ID; tanpa deskripsi, kontak, upload URL, storage credential, atau nama file mentah.
- Metrik: create/submit failure, version conflict, upload failure/orphan, latency p95; alert audit failure dan storage error >5%/15 menit.

## Keamanan, performa, aksesibilitas, dan i18n
- ID owner selalu dari session; semua lookup memadukan event ID dan organizer ID; filename diabaikan sebagai storage key.
- Presigned upload maksimum 5 menit, key acak, MIME/magic-byte/provider metadata diverifikasi; SVG/GIF ditolak.
- Query memakai kolom eksplisit dan cursor; target p95 daftar/detail ≤700 ms dan mutasi ≤1 s di luar transfer file.
- Form keyboard penuh, semantic fieldset, focus ke error pertama, status tidak hanya warna, alt text wajib.
- Mobile 360 px tanpa overflow; tanggal tampil `id-ID` menurut timezone event; harga `Intl.NumberFormat("id-ID",{currency:"IDR"})`.

## Dependensi dan fallback
- Wajib RFC-001–004: Prisma/migration, session/RBAC, audit/analytics, organizer capability.
- F22 membutuhkan keputusan provider object storage; adapter dilarang mengikat domain pada SDK.
- Fallback resmi adalah placeholder, bukan filesystem/base64/database blob; F22 baru dinyatakan lulus penuh setelah provider dipilih.
- Analytics gagal tidak rollback; audit/database gagal rollback; cleanup object gagal masuk retry log tanpa menghapus metadata historis.

## Kasus uji
- `F9-INT-001`/`F9-SEC-002`: organizer Approved mengelola banyak draft miliknya; cross-tenant/non-Approved ditolak.
- `F9-CONC-003`: expectedVersion sama hanya satu mutasi berhasil.
- `F9-INT-004`: Pending read-only dan delete ditolak.
- `F10-UNIT-001`/`F10-INT-002`: matriks kelengkapan/waktu/zona exhaustive; submit atomik dan rollback tanpa tipe.
- `F15-UNIT-001`: batas harga, quota, limit, dan sale window.
- `F15-INT-002`/`F15-CONC-003`: nama unik case-insensitive per event; edit versus submit tetap valid.
- `F22-CONTRACT-001`: fake deterministic memenuhi upload/head/delete contract.
- `F22-SEC-002`/`F22-E2E-003`: upload invalid/cross-tenant ditolak; READY tampil dan placeholder berfungsi.

## Migrasi dan rollout
1. Pastikan regression RFC-001–004, backup preview, dan decision gate storage tercatat.
2. Terapkan enum/tabel/constraint/index additive; seed eksplisit hanya test.
3. Deploy route tertutup feature flag organizer, jalankan contract/integration/E2E.
4. Buka authoring lalu submit; pantau conflict, audit, dan orphan.
5. Rollback menutup route dan mempertahankan tabel/data; jangan drop enum/tabel pada rollback aplikasi.

## Risiko dan mitigasi
- Data review berubah atau waktu lokal ambigu: Pending read-only, row lock/version, IANA allowlist, UTC persistence.
- Slug collision atau upload berbahaya/yatim: suffix/key acak, unique retry, allowlist, cleanup retry, dan placeholder tanpa SDK diam-diam.
- Validasi kuota terpakai belum relevan: belum ada order/reservasi; RFC-008 wajib memperluas update service dan regression F15.

## Kriteria penerimaan per fitur
- **F9:** organizer Approved mengelola banyak event lengkap miliknya; Pending terkunci; event memiliki waktu/zona/ownership/version valid; penghapusan tidak menyentuh data historis.
- **F10:** hanya aggregate lengkap dengan minimal satu tipe valid dapat berpindah DRAFT→PENDING_REVIEW secara atomik dan auditable; event pending belum publik/dapat dibeli.
- **F15:** banyak tipe menyimpan harga Rupiah, kuota, jadwal, limit, urutan dan snapshot authoring valid; perubahan harga tidak memiliki efek retroaktif karena commerce belum ada.
- **F22:** file valid tersimpan di object storage melalui adapter dan tampil sebagai gambar utama; invalid ditolak; placeholder dipakai tanpa filesystem. Jika provider belum dipilih, F22 tetap open dan RFC tidak boleh diklaim selesai penuh.

## Definition of Done
1. Seluruh prasyarat RFC-001–004 dan regression suite lulus.
2. Migration eksak, constraint, indeks, Prisma mapping, dan rollback strategy diuji di PostgreSQL preview.
3. Endpoint memakai Zod, auth, capability, ownership, CSRF/rate limit, error envelope, dan correlation ID.
4. Unit/integration/concurrency/security/contract/E2E F9/F10/F15/F22 lulus; branch coverage module ≥90%.
5. Audit atomik dan analytics after-commit terverifikasi tanpa PII.
6. UI Indonesia responsif dan WCAG 2.1 AA; format Rupiah/timezone benar.
7. Format, lint, typecheck, build, test, dependency/security scan lulus tanpa Critical/High.
8. Tidak ada katalog, moderation decision, petugas, order, payment, ticket, notification, provider tak disetujui, TODO, atau secret.
9. RFC-006 baru dimulai setelah dokumen dan implementasi ini disetujui.
