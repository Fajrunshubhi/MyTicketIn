# RFC-007 — Katalog dan Discovery

## Metadata dan urutan
- Status: Diusulkan.
- Fitur yang dimiliki: **F18, F19, F20 (dipromosikan menjadi Must Have), F21, F77 (Must Have)**.
- Kompleksitas: **Tinggi**.
- Prasyarat: **RFC-001, RFC-002, RFC-003, RFC-004, RFC-005, dan RFC-006 wajib selesai dan lulus**.
- Pendahulu langsung: **RFC-006 — Lifecycle Event dan Petugas**.
- Penerus langsung: **RFC-008 — Order, Inventori, Reservasi, dan Expiry**.
- RFC-008 hanya boleh dimulai setelah Definition of Done RFC ini lulus.
- RFC ini read-only publik; tidak membuat checkout, order, reservasi, payment, atau tiket.

## Sasaran dan keputusan
Pengunjung tanpa login dapat menemukan event `PUBLISHED` melalui katalog berhalaman, pencarian, filter kategori/lokasi/tanggal, dan detail berbasis slug. URL query adalah source of truth. PostgreSQL full-text search konfigurasi `simple` dipakai tanpa provider pencarian baru. Ketersediaan pada fase ini hanya `sale eligibility` dari lifecycle, jadwal, stop-sale, dan kuota awal; validasi stok/hold final tetap milik RFC-008. Detail menampilkan denah statis dan daftar kursi read-only, bukan peta klik.

## Ruang lingkup
- Katalog publik event Published dengan cursor pagination.
- Pencarian kata kunci minimal judul, case-insensitive.
- Filter kategori, kota, provinsi, dan rentang tanggal yang dapat digabung; F20 adalah Must Have pada scope RFC ini.
- Input bahasa alami F77 yang hanya diterjemahkan AI menjadi DTO filter katalog yang sudah ada dan tervalidasi ketat.
- Detail event, organizer, gambar/placeholder, syarat, kontak, tipe tiket, harga, periode, status penjualan, denah statis, dan daftar/grid kursi read-only sesuai mode.
- Metadata SEO dasar, canonical URL, empty/error/loading state.
- Cache publik terbatas dengan invalidasi tag dari mutation RFC-006.
- Analytics discovery tanpa query mentah atau PII.

## Non-scope
- Event Draft/Pending/Rejected/Cancelled/Completed pada hasil publik.
- Checkout/cart, batas beli, reservasi, paid/reserved quantity, atau overselling (RFC-008).
- Ranking personal, rekomendasi, geolocation, peta, autocomplete, indeks/search provider eksternal, atau admin search. Parser AI F77 bukan recommendation engine maupun search provider dan tidak mengubah query repository.
- F74 rekomendasi personal; fitur tersebut baru boleh diselesaikan di RFC-012 karena membutuhkan histori order Paid.
- Preview privat (tetap RFC-006), favorit, voucher, event online, atau multi-bahasa.
- Clickable map, hold kursi, atau checkout (RFC-008). Projection publik hanya menampilkan denah statis dan ketersediaan awal, bukan reservasi runtime.
- Perubahan event dari route publik dan client-side global store.

## Gap kondisi setelah RFC-006
- Event Published sudah dapat terbentuk, tetapi tidak ada route/read model publik.
- Belum ada indeks pencarian, normalisasi filter, pagination publik, metadata, atau cache policy.
- Komponen preview bersifat owner-only dan tidak boleh dipakai langsung tanpa public projection.
- Belum ada order/reservasi; kuota terpakai secara sah selalu nol pada fase ini.

## Aturan domain/read projection
- Semua query publik selalu memiliki predicate `events.status='PUBLISHED'`; client tidak dapat menggantinya.
- Event yang statusnya berubah saat request harus mengikuti snapshot database dan cache invalidation.
- Query search trim/collapse whitespace, maksimum 100 karakter; kosong sama dengan katalog.
- Token pencarian memakai AND (`plainto_tsquery`) dan mencocokkan judul berbobot tertinggi, venue, kota, kategori.
- Filter kategori/kota/provinsi exact setelah lowercase+trim; daftar opsi berasal dari event Published.
- `dateFrom/dateTo` adalah tanggal lokal `YYYY-MM-DD` pada timezone filter `Asia/Jakarta`; overlap event dipakai: `starts_at < toExclusive AND ends_at >= from`.
- Maksimum rentang filter 366 hari; `dateFrom <= dateTo`.
- Urutan default: event mendatang `starts_at ASC, id ASC`; hanya `sort=soonest|newest`.
- Detail hanya menggunakan slug; ID internal tidak perlu tampil pada URL.
- Daftar katalog hanya menampilkan event Published yang belum dimulai melalui defense-in-depth `starts_at > now()`; detail event yang sedang berlangsung boleh tetap dapat dibuka secara informasional selama `ends_at > now()`, tetapi tidak purchasable.
- Sale status per tipe: `STOPPED`, `NOT_STARTED`, `ENDED`, atau `AVAILABLE`; `AVAILABLE` belum menjamin stok saat checkout.
- Harga ditampilkan dari integer `BIGINT`; harga minimum katalog adalah minimum tipe yang sale-eligible, atau minimum seluruh tipe untuk label informasional.

1. Route menormalisasi query dan menolak parameter invalid sebelum query database.
2. Repository menambahkan predicate Published, waktu, search/filter, serta keyset cursor.
3. Database hanya memilih kolom projection publik; kontak sensitif selain kontak event tidak ikut.
4. Service menghitung label tanggal/harga/sale status tanpa menghitung reserved/paid.
5. RSC merender hasil dan kontrol dari URL; tidak ada fetch ulang client untuk initial render.
6. Detail lookup slug menghasilkan 404 generik jika tidak Published/berakhir/ada.
7. View analytics dikirim setelah response secara best effort memakai event ID non-sensitif.

## Perubahan skema database eksak
Migration: `0007_catalog_discovery`. Tidak membuat tabel bisnis baru.

### Tambahan kolom `events`
- `search_document TSVECTOR GENERATED ALWAYS AS (`:
  `setweight(to_tsvector('simple',coalesce(title,'')),'A') ||`
  `setweight(to_tsvector('simple',coalesce(category,'')),'B') ||`
  `setweight(to_tsvector('simple',coalesce(venue_name,'')),'B') ||`
  `setweight(to_tsvector('simple',coalesce(city,'') || ' ' || coalesce(province,'')),'B')`
  `) STORED`.
- Kolom generated tidak ditulis Prisma; dipetakan read-only atau diakses raw SQL terparameterisasi yang terisolasi.

### Indeks
- GIN `events_search_document_idx ON events USING GIN(search_document)`.
- B-tree `events_catalog_soonest_idx ON events(starts_at ASC,id ASC) WHERE status='PUBLISHED'`.
- B-tree `events_catalog_newest_idx ON events(published_at DESC,id DESC) WHERE status='PUBLISHED'`.
- Functional `events_catalog_category_idx ON events(lower(category),starts_at,id) WHERE status='PUBLISHED'`.
- Functional `events_catalog_city_idx ON events(lower(city),starts_at,id) WHERE status='PUBLISHED'`.
- Functional `events_catalog_province_idx ON events(lower(province),starts_at,id) WHERE status='PUBLISHED'`.
- Indeks RFC-005 `events_slug_key` tetap dipakai; detail wajib tetap menambahkan predicate status.
- Indeks tipe RFC-006 `event_ticket_types_sale_window_idx` dipakai untuk projection.

## Kontrak API publik
Auth tidak diperlukan. Semua input Zod; rate limit per IP yang dipseudonimkan; error memakai envelope standar dan tidak membocorkan SQL.

### `GET /api/events`
- Query: `q?` max 100, `category?`, `city?`, `province?`, `dateFrom?`, `dateTo?`, `sort=soonest|newest`, `cursor?`, `limit=1..48`; default 12.
- Respons 200:
```json
{"items":[{"slug":"festival-musik","title":"Festival Musik","category":"Musik","city":"Bandung","startsAt":"ISO-8601","timezone":"Asia/Jakarta","image":{"url":"...","alt":"..."},"priceFromRupiah":75000,"saleStatus":"AVAILABLE"}],"nextCursor":"opaque-or-null","appliedFilters":{}}
```
- Cursor HMAC memuat versi query, sort key, ID, dan hash filter; cursor dari filter berbeda ditolak.
- Cache `public, s-maxage=60, stale-while-revalidate=300`; response memiliki ETag.

### `GET /api/events/{slug}`
- Respons 200: `{event:{slug,title,description,category,organizer:{name},venueName,addressLine,city,province,timezone,startsAt,endsAt,terms,contactEmail,contactPhone?,inventoryMode,image,seatMap:{url,altText,legend}?,sections:[{id,name,ticketTypeId}],seats:[{id,sectionId,label,saleStatus}],ticketTypes:[{id,name,description,priceRupiah,quota,saleStartsAt,saleEndsAt,maxPerAccount,saleStatus}]}}`.
- Tidak mengembalikan organizer owner ID, user, audit, staff, storage key, version, atau internal reason.
- 404 untuk slug tidak ada maupun status tidak eligible; `public,s-maxage=60,stale-while-revalidate=300`.
- `AVAILABLE` berarti lifecycle/jadwal mengizinkan, bukan reservasi; response menyertakan `availabilityDisclaimer`.

### `GET /api/events/filters`
- Respons 200 `{categories:[string],locations:[{city,province}]}` dari Published future event, diurutkan locale Indonesia, maksimum 200 tiap kelompok.
- Cache `public,s-maxage=300,stale-while-revalidate=900`.
- Jika cardinality melampaui 200, UI tetap menerima query manual tervalidasi; tidak membuat tabel taxonomy.

## State dan caching
- URL query adalah state q/filter/sort/cursor; input debounced hanya mengubah URL setelah submit/300 ms.
- Database source of truth; React local state hanya drawer filter dan teks sebelum commit URL.
- Cache hanya safe public projection dan ditag `events:list`, `event:{id}`, `event-slug:{slug}`, `events:filters`.
- Publish/reject/cancel/complete/edit/stop-sale/image finalize menginvalidasi tag relevan.
- Tidak cache stok, payment, check-in, session, atau endpoint organizer/admin.
- Optimistic availability dilarang; RFC-008 mengganti resolver availability pada service yang sama.

## Algoritma/pseudocode
```text
list(query):
  normalized = validateAndNormalize(query)
  where = status=PUBLISHED AND starts_at>db_now
  if q: search_document @@ plainto_tsquery('simple', q)
  apply exact normalized filters and overlap date range
  apply keyset predicate decoded from cursor bound to filter hash
  SELECT public columns ORDER BY sortKey,id LIMIT limit+1
  derive next cursor and sale labels; return

saleStatus(type, event, now):
  if event not PUBLISHED or type.salesStoppedAt: STOPPED
  if now < saleStartsAt: NOT_STARTED
  if now >= saleEndsAt or now >= event.startsAt: ENDED
  return AVAILABLE
```

## UI/UX
- `/events` mobile-first: heading, search, filter drawer, active chips, sort, cards, dan pagination “Muat berikutnya”.
- Setiap kartu menampilkan gambar/placeholder, kategori, judul, tanggal+zona, kota, harga “Mulai Rp…”, dan sale status.
- Empty state membedakan katalog kosong dengan filter tanpa hasil serta menyediakan “Hapus filter”.
- Detail memiliki hierarchy jelas, sticky CTA informasional, tipe tiket, jadwal, venue, syarat, organizer, dan kontak event.
- CTA sebelum RFC-008 berbunyi “Checkout belum tersedia” dan disabled; RFC ini tidak membuat tautan/order placeholder.
- 404 dan network error menawarkan kembali ke katalog; loading memakai skeleton tanpa layout shift.

## Error, logging, dan monitoring
- Kode: `CATALOG_QUERY_INVALID`, `CATALOG_DATE_RANGE_INVALID`, `CATALOG_CURSOR_INVALID`, `EVENT_NOT_FOUND`, `CATALOG_RATE_LIMITED`, `CATALOG_UNAVAILABLE`.
- Log: route, normalized filter categories, result count, duration, cache outcome, correlation ID; jangan log query mentah, IP mentah, kontak, atau user agent penuh.
- Analytics: `catalog_viewed`, `event_search_performed` dengan panjang/token count dan result count, `event_viewed`; tidak mengirim query string.
- Metrik: p50/p95, cache hit, zero-result, DB rows scanned, 4xx/5xx; alert p95 >2 s atau 5xx >2%/15 menit.

## Keamanan dan privasi
- Projection allowlist mencegah owner/staff/audit/moderation/storage key terekspos.
- Raw SQL hanya untuk full-text, selalu parameterized; sort/filter memakai enum/allowlist, bukan interpolasi bebas.
- Rate limit katalog lebih longgar daripada search; panjang query/cursor dibatasi untuk mencegah abuse.
- Output description/terms di-render sebagai plain text/sanitized content; tidak ada arbitrary HTML.
- Kontak yang tampil adalah kontak event yang sengaja diisi organizer, bukan email akun owner.

## Kinerja
- Keyset pagination, `limit+1`, projection eksplisit, dan query plan diuji dengan 5.000 event/ticket types realistis.
- Tidak ada `COUNT(*)` wajib pada setiap request; UI memakai next cursor.
- `EXPLAIN (ANALYZE,BUFFERS)` harus menunjukkan indeks untuk skenario soonest/search/filter utama.
- Target katalog/detail p95 ≤2 detik pada 50 pembaca bersamaan selama 15 menit; payload list ≤250 KB untuk 12 item.
- `next/image`, ukuran responsif, lazy loading card non-prioritas, placeholder berdimensi untuk mencegah CLS.

## Aksesibilitas dan i18n
- Landmark, heading, list semantic, label search/filter, tombol clear, focus setelah navigasi, dan `aria-live` ringkas untuk jumlah hasil.
- Filter/datepicker dapat keyboard; status bukan warna saja; alt dari aset atau placeholder dekoratif yang benar.
- Layout 320/360 px tanpa overflow; target WCAG 2.1 AA dan reduced motion.
- Copy Bahasa Indonesia; Rupiah tanpa pecahan; waktu ditampilkan menurut timezone event dengan nama zona yang jelas.
- Canonical tidak menyertakan cursor; metadata title/description aman dan OpenGraph memakai gambar READY atau placeholder.

## Dependensi dan fallback
- Wajib data/event lifecycle RFC-005/006, auth/audit foundation RFC-001–004.
- PostgreSQL FTS bawaan adalah satu-satunya search dependency; tidak memasang Elasticsearch/Algolia.
- Jika query PostgreSQL F19 gagal, tampilkan `CATALOG_UNAVAILABLE`; jangan diam-diam mengembalikan event tak terfilter. Jika hanya provider parser F77 yang gagal, fallback eksplisit adalah pencarian dasar F19.
- Jika storage tidak tersedia, placeholder; analytics gagal tidak memblokir response; cache gagal jatuh ke database dengan rate limit.
- RFC-008 harus mengimplementasikan availability port dengan paid+reservasi aktif; kontrak publik boleh menambah `remainingCategory`, bukan mengubah eligibility.

## Kasus uji
- `F18-INT-001`: hanya Published future event muncul; status lain tidak bocor.
- `F18-PERF-002`: keyset stabil tanpa duplikat/lompatan pada insert konkurens.
- `F19-INT-001`: case-insensitive title search, query kosong, karakter Unicode, dan no-result.
- `F19-SEC-002`: injection/cursor tamper/oversized query ditolak.
- `F20-INT-001`: kombinasi kategori+lokasi+overlap tanggal konsisten dengan URL.
- `F20-UNIT-002`: normalisasi dan batas tanggal/timezone.
- `F21-INT-001`: detail Published lengkap; non-Published/expired 404.
- `F21-UNIT-002`: empat sale status dan batas timestamp tepat.
- `F21-SEC-003`: projection tidak memuat field internal/PII.
- `F18-E2E-003`: mobile keyboard search→filter→detail→back mempertahankan URL state.
- `NFR-01-PERF-001`: load 15 menit, p95 ≤2 detik, error/hasil dicatat.

## Migrasi dan rollout
1. Regression RFC-001–006, backup preview, dan dataset performa tersedia.
2. Tambah generated column dan indeks; gunakan pembuatan indeks non-blocking bila lingkungan/data menuntut.
3. Jalankan query plan, integration, accessibility, E2E, dan load test sebelum membuka route.
4. Deploy detail lalu katalog di balik flag publik; warm cache aman dan pantau latensi/error.
5. Rollback menutup route/cache; generated column/index dapat dipertahankan sampai migration contract terpisah.

## Risiko dan mitigasi
- Status stale dari cache: tag invalidation + TTL 60 detik + eligibility dicek lagi RFC-008 saat checkout.
- Search Indonesia kurang stemming: konfigurasi `simple` memenuhi pencocokan token; evaluasi provider/stemming di luar MVP.
- Filter lokasi tidak konsisten: lowercase trim untuk pencocokan, display mempertahankan nilai authoring.
- Offset pagination drift: keyset cursor terikat filter/sort.
- Label “tersedia” disalahartikan sebagai stok final: disclaimer dan CTA disabled sampai RFC-008.
- Event lewat waktu masih Published: query defense-in-depth dan command complete RFC-006.

## Kriteria penerimaan per fitur
- **F18:** pengunjung tanpa login melihat hanya Published future event melalui daftar ringkas, cursor stabil, placeholder, empty state, dan tautan detail.
- **F19:** pencarian case-insensitive minimal nama, query kosong kembali ke katalog, input aman, dan no-result jelas.
- **F20:** kategori/lokasi/tanggal dapat digabung/dihapus, URL merepresentasikan state, normalisasi serta overlap tanggal konsisten.
- **F21:** detail Published menampilkan organizer, deskripsi, waktu/zona, venue, syarat, kontak event, tiket/harga/jadwal dan sale status; non-eligible 404; checkout tetap tidak dibuat.
- **F77:** input bahasa alami diterjemahkan hanya ke DTO filter F19/F20 yang strict, chips dan URL; model tidak dapat menentukan SQL, event, atau status, repository selalu menambahkan predicate Published, dan kegagalan provider turun secara jelas ke pencarian dasar F19.

## Definition of Done
1. Regression RFC-001–006 lulus sebelum RFC-008 dimulai.
2. Migration generated column/index, Prisma/raw SQL boundary, rollback, dan query plan diuji PostgreSQL preview.
3. API divalidasi Zod, rate-limited, cursor-bound, projection-safe, berkorelasi, dan memiliki cache headers/tag invalidation.
4. Unit/integration/security/E2E/performance F18–F21/F77 lulus; coverage global memenuhi RULES dan module branch ≥90%.
5. NFR-01 p95 ≤2 detik dibuktikan pada profil 5.000 event/50 client/15 menit.
6. UI mobile/responsif, Indonesia, SEO dasar, dan WCAG 2.1 AA terverifikasi pada browser target.
7. Format/lint/typecheck/build/test/security scan lulus tanpa blocker, Critical/High, TODO, atau secret.
8. Tidak ada checkout, order, reservation, payment, ticket, personalized recommendation/F74, search index provider eksternal, provider AI tak disetujui, atau forward implementation.
9. RFC-008 baru dimulai setelah exit criteria ini disetujui.

## Ekstensi F77 — Bahasa Alami ke Filter Katalog

F77 memperluas discovery tanpa mengganti PostgreSQL FTS, `CatalogReadService`, atau `CatalogQuery` F19/F20. F20 dipromosikan menjadi **Must Have** berdasarkan keputusan Product Owner terbaru. F74 tetap dimiliki/diselesaikan RFC-012 setelah histori Paid tersedia; tidak ada rekomendasi atau personalisasi dalam RFC ini.

### Batas model dan DTO strict
Input model hanya boleh menghasilkan `CatalogFilterDraftV1`:
```text
{
  q?: string(1..100),
  category?: string,
  city?: string,
  province?: string,
  dateFrom?: "YYYY-MM-DD",
  dateTo?: "YYYY-MM-DD",
  sort?: "soonest"|"newest"
}
```
- Schema Zod `.strict()` menolak unknown key. `status`, `eventId`, `slug`, `cursor`, `limit`, SQL/where/orderBy, operator, raw expression, recommendation score, user identity, dan daftar event tidak pernah menjadi bagian output schema.
- Model tidak menerima koneksi database, tool/function call, browsing, retrieval, atau daftar event. Ia hanya menerima input bahasa alami sebagai data tidak tepercaya, locale `id-ID`, tanggal database yang dibulatkan ke hari, timezone `Asia/Jakarta`, serta opsi kategori/lokasi Published yang sudah diproyeksikan dan dibatasi.
- Hasil model dinormalisasi oleh fungsi F19/F20 yang sama, dicocokkan ke opsi allowlist secara exact case-insensitive, divalidasi batas tanggal 366 hari, lalu diserialisasi menjadi canonical URL. Model tidak boleh membuat query repository.
- `CatalogReadService` tetap menambahkan `events.status='PUBLISHED' AND starts_at>db_now` secara unconditional untuk daftar hasil. DTO tidak mempunyai status sehingga route maupun model tidak dapat melemahkan predicate.
- Poster/prompt injection rule F76 juga berlaku: teks pengguna diletakkan dalam delimiter sebagai data, prompt statis berversi, output JSON schema strict maksimum 8 KiB, dan seluruh output invalid ditolak.

### Skema, port, dan gate
- Migration `0007_catalog_discovery` tidak menambah tabel/kolom F77. Input bahasa alami, prompt, completion, dan filter draft tidak dipersistenkan. Filter yang diterapkan hidup di URL sebagai field F19/F20 biasa.
- F77 memakai `AiInferencePort` provider-netral dari RFC-005 melalui public application contract dengan operasi baru:
```text
parseCatalogFilter({
  naturalLanguage,
  locale:"id-ID",
  today,
  timezone:"Asia/Jakarta",
  allowedCategories,
  allowedLocations,
  outputSchemaVersion:"catalog-filter.v1"
}) -> CatalogFilterDraftV1
```
- `DeterministicFakeAiInferencePort` wajib mencakup mapping fixture untuk kombinasi filter, relative date, unknown category, forbidden status/SQL/event output, malformed JSON, timeout, dan unavailable.
- Gate provider/model/privacy/cost F76 kembali memblokir aktivasi F77 dan harus secara eksplisit menyetujui operasi text parsing, zero-retention atau maksimum 24 jam, biaya/request, anggaran harian/bulanan, region, model/version, timeout, dan kill switch `AI_CATALOG_FILTER_ENABLED`. Tidak ada fallback credential/model/provider.

### Kontrak endpoint, URL, chips, dan fallback
`POST /api/events/ai-filter`
- Public; body JSON `{naturalLanguage}` dengan trim/collapse whitespace, 2–300 karakter; Zod; body maksimum 4 KiB.
- Rate limit 10/IP pseudonim/menit dan 50/IP/hari; satu inference aktif per fingerprint; response `private,no-store` karena memproses input pengguna.
- Respons sukses `200 {mode:"AI",filterDto,chips:[{key,label,value}],canonicalQuery}`. `canonicalQuery` hanya memuat key DTO yang diizinkan dan tidak memuat cursor.
- UI menampilkan chips hasil parse sebelum/ketika navigasi. Apply mengganti URL `/events?...`; edit/remove chip mengubah URL dan server merender ulang katalog dari DTO yang sama.
- Provider timeout/unavailable/budget/malformed output tidak mengembalikan 5xx ke alur pengguna. Service membuat fallback deterministik `{q: first100(normalizedNaturalLanguage)}`, merespons `200 {mode:"BASIC_SEARCH_FALLBACK",filterDto,chips,canonicalQuery,notice:"Filter AI tidak tersedia; pencarian kata kunci digunakan."}`, lalu F19 menjalankan pencarian dasar.
- Input boundary invalid tetap `400 CATALOG_NATURAL_QUERY_INVALID`; database F19 gagal tetap `503 CATALOG_UNAVAILABLE` dan bukan provider fallback.

Error tambahan: `CATALOG_AI_NOT_CONFIGURED`, `CATALOG_AI_RATE_LIMITED`, `CATALOG_AI_OUTPUT_INVALID`, `CATALOG_AI_PROVIDER_UNAVAILABLE`, dan `CATALOG_AI_BUDGET_EXCEEDED` dicatat sebagai reason internal/metric; response fallback memakai notice aman. Tidak ada raw model/provider error ke client.

### Algoritma
```text
parseNaturalFilter(input):
  normalized = validate 2..300 and collapse whitespace
  options = load Published-only category/location projection with fixed caps
  try:
    draft = AiInferencePort.parseCatalogFilter(normalized, dbToday, options)
    strictParse draft; reject forbidden/unknown keys
    dto = existing CatalogQuery.normalizeAndValidate(draft)
    require category/location exact member of options
    return AI + dto + chips + canonical URL
  catch not-configured|provider|timeout|rate-limit|budget|invalid-output:
    dto = existing CatalogQuery.normalizeAndValidate({q:first100(normalized)})
    return BASIC_SEARCH_FALLBACK + dto + q chip + canonical URL + notice

list(dto):
  repository always applies status=PUBLISHED and starts_at>db_now
  apply only existing F19/F20 predicates; model output never reaches SQL builder
```

### Privasi, logging, keamanan, dan performa
- Raw natural-language input, prompt, completion, category/location list, dan generated URL lengkap dilarang di log/analytics/trace. Log allowlist: input length bucket, produced filter keys, mode, provider/model code, latency, outcome, result count, correlation ID; retensi metadata 30 hari.
- Input dianggap dapat berisi prompt injection/PII. HTML/control characters dinormalisasi, output tidak dirender sebagai HTML, dan parameter URL di-encode oleh serializer tunggal.
- Provider timeout maksimum 5 detik agar fallback memenuhi p95; panggilan AI tidak di-cache lintas user. Opsi filter Published dapat memakai cache aman RFC-007 tetapi predicate repository diuji lagi saat list.
- Analytics membedakan `catalog_natural_filter_parsed` dan `catalog_natural_filter_fallback` tanpa input mentah. Cost/rate/provider alert mengikuti F76.

### Pengujian dan rollout
- `F77-UNIT-001`: Bahasa Indonesia, typo ringan, relative date, kombinasi kategori/lokasi/tanggal/sort menjadi DTO strict dan chips/canonical URL stabil.
- `F77-SEC-002`: input meminta `status=DRAFT`, event tertentu, SQL injection, override prompt, HTML, unknown key; semuanya tidak dapat mencapai repository/output.
- `F77-INT-003`: hasil AI melewati validator F19/F20; Published predicate selalu ada pada query SQL terparameterisasi dan database tetap source of truth.
- `F77-FALLBACK-004`: timeout, unavailable, budget, malformed, unknown option turun ke `{q}` F19 dengan notice; kegagalan database tidak salah diklasifikasikan.
- `F77-E2E-005`: natural input → chips → URL → refresh/back/forward mempertahankan filter; remove chip konsisten.
- `F77-PRIV-006`: sink log/analytics/trace tidak menerima input/prompt/completion; retensi provider dan metadata tervalidasi.
- `F20-REG-003`: F20 sebagai Must Have tetap bekerja tanpa AI dan seluruh kombinasi filter URL lulus.

Rollout: (1) gate AI ditutup; (2) fake dan shadow test fixture sintetis; (3) preview opt-in dengan response no-store; (4) enable 10% lalu 100% sambil memantau fallback/cost/latency; (5) kill switch kembali ke UI F19/F20. Tidak ada schema rollback.

Definition of Done tambahan:
1. Metadata ownership menunjukkan F20 Must dan F77 RFC-007; F74 tetap RFC-012 karena membutuhkan Paid history.
2. Strict DTO, larangan SQL/event/status, Published predicate unconditional, parameterized query, chips, dan URL state dibuktikan test.
3. Provider failure selalu memberi fallback F19 yang terlihat; pencarian/filter manual tetap lengkap tanpa AI.
4. Gate AI, fake deterministik, rate/budget/timeout, no-content logging, retensi, accessibility, dan performance target lulus.
