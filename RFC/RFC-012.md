# RFC-012 — Dashboard, Pelaporan, dan Rekomendasi Event

## Metadata dan urutan

- Status: Diusulkan.
- Fitur yang dimiliki: **F43, F44, F46, F47, F48, F74**.
- Kompleksitas: **Sedang**.
- Prasyarat wajib: **RFC-001, RFC-002, RFC-003, RFC-004, RFC-005, RFC-006, RFC-007, RFC-008, RFC-009, RFC-010, dan RFC-011 seluruhnya selesai dan lulus**.
- Pendahulu langsung: **RFC-011 — Scanner dan Check-in**.
- Penerus langsung: **RFC-013 — Notifikasi dan Pemulihan Akun**.
- RFC-013 hanya boleh dimulai setelah Definition of Done RFC-012 lulus.
- Prioritas yang wajib selesai pada RFC ini mencakup **F43, F44, F46, dan F74 sebagai Must Have**; F47/F48 tetap Could Have.
- RFC ini hanya membaca data domain terdahulu; F74 diselesaikan di sini karena sinyal histori order Paid sudah tersedia setelah RFC-009. RFC ini tidak membuat notifikasi atau hardening RFC berikutnya.

## Sasaran dan keputusan

Sediakan dashboard organizer dan admin yang menghitung langsung dari source of truth transaksi, ekspor CSV peserta/check-in wajib yang aman, rekomendasi event serupa yang deterministik dan menjaga privasi, grafik penjualan opsional, serta pencarian admin lintas entitas opsional. Seluruh nominal wajib berlabel **SANDBOX/UJI**, agregat memakai status domain final, dan semua query dibatasi ownership/RBAC serta pagination. Dashboard dan rekomendasi tidak menjadi ledger, tidak menyimpan counter/profil personal mutable, dan tidak mengubah data commerce.

## Ruang lingkup

- F43 ringkasan organizer per event: order Paid, tiket terjual, bruto sandbox, dan check-in.
- F44 antrean admin serta **F46 Must Have** ekspor CSV peserta/check-in milik organizer, termasuk kategori/area dan label kursi.
- F47 grafik tren dan F48 pencarian enam entitas sebagai Could Have; seluruhnya memakai filter, cursor, audit akses, dan query terukur.
- **F74 Must Have Rekomendasi Event Serupa:** kandidat hanya event `PUBLISHED` dengan `starts_at > database_now`; rekomendasi authenticated memakai histori order milik sendiri yang `PAID` sebagai sinyal kategori, kota/provinsi, dan organizer. Event saat ini selalu dikecualikan dan event yang pernah dibeli dikecualikan pada mode histori.
- Pengunjung anonymous dan user tanpa histori Paid mendapat fallback kontekstual dari kategori, lokasi publik, serta organizer event yang sedang dilihat. Semua mode memakai skor dan tie-break deterministik, alasan yang dapat dijelaskan, projection publik minimum, limit ketat, dan tidak memakai PII atau geolokasi perangkat.

## Non-scope

- Settlement, payout, fee, laba bersih, pajak, transaksi atau refund uang nyata.
- Data warehouse, BI eksternal, scheduled report, PDF/XLSX, atau email laporan.
- Mutasi moderasi/refund/payment; dashboard hanya menautkan ke use case RFC terdahulu.
- Prediksi, cohort, ranking organizer, leaderboard, atau analitik personal.
- Model ML/generative AI, embedding/vector database, collaborative filtering lintas pengguna, sponsored ranking, profil minat persisten, geolokasi/GPS/IP location, atau rekomendasi event Draft/Pending/Rejected/Cancelled/Completed.
- Notifikasi RFC-013, error taxonomy/observability/release gate RFC-014.

## Gap kondisi saat ini

- Data order, payment, ticket, dan check-in tersedia, tetapi belum ada read model operasional terpadu.
- Organizer belum memiliki angka konsisten per event atau ekspor peserta.
- Admin harus membuka modul satu per satu dan callback terlambat belum diringkas sebagai antrean.
- Belum ada kebijakan CSV injection, filter laporan, search projection, atau target query agregat.
- Histori order Paid telah tersedia, tetapi belum ada kontrak kandidat, scoring, alasan, projection, privasi, atau budget kinerja untuk rekomendasi event serupa.

## Aturan perhitungan

- `paidOrderCount`: jumlah order unik dengan `status='PAID'`.
- `ticketsSold`: jumlah row ticket yang diterbitkan dari order Paid, termasuk Used/Unused/Cancelled untuk histori penjualan.
- `grossSandboxRupiah`: jumlah `order_items.unit_price_rupiah * quantity` milik order Paid; refund tidak mengubah bruto.
- `completedRefundRupiah`: jumlah refund `COMPLETED`; ditampilkan terpisah, bukan mengurangi bruto diam-diam.
- `checkInCount`: jumlah ticket unik dengan satu percobaan check-in berhasil/`USED`.
- `attendanceRate`: `checkInCount / ticketsSold * 100`; null jika ticketsSold nol.
- Tren memakai `orders.paid_at` dalam timezone event; total bucket harus sama dengan ringkasan untuk rentang sama.
- Semua filter rentang memakai batas `[fromInclusive,toExclusive)` dan maksimum 366 hari.
- Organizer hanya melihat event dengan `organizer_profile_id` miliknya.
- Angka dibaca dalam satu transaksi read-only `REPEATABLE READ` per respons agar kartu konsisten.

## Aturan rekomendasi F74

- Kandidat selalu difilter server-side ke event `PUBLISHED` dan `starts_at > database_now`; current event dikecualikan sebelum scoring.
- Mode `HISTORY` hanya untuk user authenticated yang memiliki order `PAID`. Sinyal dihitung dari event pada order Paid milik actor sendiri: frekuensi kategori, kota/provinsi, dan organizer; status selain Paid tidak menjadi sinyal.
- Pada mode `HISTORY`, kandidat yang event-nya sudah pernah dibeli actor dikecualikan. Query tidak pernah membaca histori user lain.
- Mode `CONTEXTUAL` dipakai untuk anonymous atau actor tanpa histori Paid: kecocokan event saat ini memberi bobot kategori 3, kota 2, provinsi 1, dan organizer 1. Tidak ada fingerprinting atau geolokasi perangkat.
- Skor mode histori adalah `3*min(categoryPaidCount,5) + 2*min(cityPaidCount,5) + min(provincePaidCount,5) + min(organizerPaidCount,5)`. Tie-break eksak: `score DESC, starts_at ASC, id ASC`.
- Alasan hanya salah satu label aman dengan kontribusi terbesar dan urutan stabil `CATEGORY > CITY > PROVINCE > ORGANIZER`, misalnya “Kategori serupa” atau “Lokasi serupa”; count histori, score mentah, dan identitas pembelian tidak dikirim ke client.
- Jika tidak ada kandidat dengan score positif, respons boleh kosong; tidak boleh melonggarkan status/waktu atau memasukkan event yang telah dibeli. Limit `1..12`, default 6.

## Diagram aliran data tekstual

1. Boundary membentuk actor/correlation ID dan memvalidasi query dengan Zod.
2. Policy memperoleh organizer profile dari session atau memastikan ADMIN.
3. Service menjalankan agregat dengan predicate tenant/status/rentang yang sama.
4. DTO mengubah `BIGINT` menjadi string JSON bila melebihi safe integer; UI memakai formatter Rupiah.
5. CSV mengalir per batch tanpa memuat semua peserta ke memori dan mencatat audit ekspor.
6. Grafik/pencarian gagal secara terpisah dan tidak menghilangkan kartu ringkasan inti.
7. Service rekomendasi memilih mode, membaca kandidat Published-future dan hanya pada mode histori membaca order Paid actor, lalu memberi score/alasan deterministik.
8. Tidak ada counter, profil minat, status, atau source-of-truth baru yang ditulis.

## Perubahan skema database eksak

Migration `0012_reporting_indexes` hanya menambah indeks; tidak menambah tabel, kolom, enum, trigger, atau counter.

### Indeks

- `orders_organizer_paid_idx ON orders(event_id, paid_at DESC, id DESC) WHERE status='PAID'`.
- `orders_admin_status_updated_idx ON orders(status, updated_at DESC, id DESC)`.
- `order_items_order_ticket_type_idx ON order_items(order_id, ticket_type_id) INCLUDE (quantity,unit_price_rupiah)`.
- `payments_admin_status_updated_idx ON payments(status, updated_at DESC, id DESC) INCLUDE (order_id,provider,external_reference)`.
- `payments_external_reference_search_idx ON payments(lower(external_reference))`.
- `tickets_event_status_issued_idx ON tickets(event_id,status,issued_at DESC,id DESC)`.
- `tickets_order_item_idx ON tickets(order_item_id,id)`.
- `check_in_attempts_event_result_time_idx ON check_in_attempts(event_id,result,attempted_at DESC,id DESC)`.
- `refunds_admin_status_updated_idx ON refunds(status,updated_at DESC,id DESC) INCLUDE (order_id,amount_rupiah)`.
- `users_admin_username_search_idx ON users(lower(username),id)`.
- `users_admin_email_search_idx ON users(lower(email),id)`; hanya dipakai ADMIN dan hasil dimasked.
- `organizer_profiles_admin_name_search_idx ON organizer_profiles(lower(name),id)`.
- `events_admin_title_search_idx ON events(lower(title),id)`.
- `orders_buyer_paid_history_idx ON orders(buyer_user_id,paid_at DESC,event_id) WHERE status='PAID'`.
- `events_recommendation_candidate_idx ON events(status,starts_at ASC,id ASC) INCLUDE (category,city,province,organizer_profile_id,slug,title)`.
- Nama kolom harus cocok migration RFC-008–011; bila implementasi pendahulu berbeda, RFC-012 wajib memperbarui DDL secara eksplisit sebelum coding, bukan membuat alias runtime.
- Seluruh indeks dibuat `CONCURRENTLY` melalui migration non-transactional bila tabel berisi data; rollback hanya `DROP INDEX CONCURRENTLY`.

## Kontrak API

Semua respons privat memakai `Cache-Control: private, no-store`, error envelope RFC-001, correlation ID, dan cursor HMAC yang terikat filter.

### `GET /api/organizer/dashboard`

- Auth: user ACTIVE dengan organizer `APPROVED`.
- Query: `eventId?`, `from?`, `to?`, `cursor?`, `limit=1..50` default 20.
- Request tanpa body; eventId wajib milik organizer.
- 200: `{summary:{paidOrderCount,ticketsSold,grossSandboxRupiah,completedRefundRupiah,checkInCount,attendanceRate},events:[...],nextCursor,range,asOf,correlationId}`.
- 403 `ORGANIZER_REQUIRED`; 404 generik `EVENT_NOT_FOUND`; 400 `REPORT_RANGE_INVALID`.

### `GET /api/organizer/events/{eventId}/sales-trend`

- Auth: organizer owner; query `from,to,bucket=day|week`, maksimum 366 hari.
- 200: `{series:[{startAt,paidOrders,ticketsSold,grossSandboxRupiah}],totals,timezone}`.
- Jika F47 belum diaktifkan, 404 feature-disabled; ringkasan F43 tetap bekerja.

### `GET /api/organizer/events/{eventId}/participants.csv`

- Auth: organizer owner ACTIVE; rate limit 5 ekspor/event/jam.
- Query: `ticketStatus?`, `checkInResult?`, `from?`, `to?`; tanpa body.
- 200 `text/csv; charset=utf-8`, `Content-Disposition: attachment`, UTF-8 BOM opsional konsisten.
- Kolom eksak: `nomor_order,nama_pembeli_masked,email_masked,jenis_tiket,kategori_area,label_kursi,status_tiket,waktu_terbit,waktu_check_in`.
- Tidak memuat token QR, password, payment reference, alamat, atau audit payload.

### `GET /api/admin/operations`

- Auth: ADMIN ACTIVE.
- Query: `queue=moderation|late-payment|mismatch|cancellation|refund`, `cursor?`, `limit<=100`.
- 200: `{items:[{entityType,entityId,reasonCode,status,occurredAt,safeSummary}],nextCursor,countsAsOf}`.
- Endpoint tidak menyediakan mutasi; CTA menuju endpoint owner RFC terdahulu.

### `GET /api/admin/search`

- Auth: ADMIN; F48 feature flag; limit 20/kelompok; minimum query 3, maksimum 100.
- Query: `q`, `types=user,organizer,event,order,payment,ticket`, `cursor?`.
- 200: `{groups:{users:[],organizers:[],events:[],orders:[],payments:[],tickets:[]},nextCursors}`.
- Exact match didahulukan untuk ID/nomor/reference; substring hanya field nama yang diindeks/terbatas.
- Hasil user/email dimasked; setiap pencarian menghasilkan audit akses tanpa menyimpan query mentah.

### `GET /api/events/{slug}/recommendations`

- Auth opsional; slug harus menunjuk event publik yang dapat dilihat. Query `limit=1..12`, default 6; request tanpa body.
- Anonymous atau user tanpa histori Paid memakai mode `CONTEXTUAL`; user authenticated dengan histori Paid memakai mode `HISTORY` dan hanya histori miliknya.
- 200: `{items:[{slug,title,category,city,province,startsAt,timezone,organizer:{name},image:{url,altText},reason}],mode:"HISTORY"|"CONTEXTUAL",asOf}`.
- Projection tidak memuat score/count histori, buyer/order/ticket ID, email, alamat pembeli, koordinat, exact device location, kontak organizer, atau field authoring privat.
- 404 generik `EVENT_NOT_FOUND`; kegagalan query 503 `RECOMMENDATION_UNAVAILABLE` dan detail event tetap tampil tanpa rekomendasi palsu.

## State dan caching

- PostgreSQL adalah source of truth; URL menyimpan event, rentang, tab, filter, dan cursor.
- React state lokal hanya dropdown/dialog; tidak ada global client state.
- Organizer/admin dan setiap response recommendation authenticated selalu no-store; browser back dapat memakai URL lalu refetch.
- Grafik boleh memoized per request maksimum 30 detik hanya bila key mengandung tenant/rentang dan bukan authority.
- CSV tidak dicache, tidak disimpan ke filesystem/object storage, dan langsung kedaluwarsa setelah stream selesai.
- Rekomendasi untuk setiap request authenticated selalu `private,no-store`, termasuk mode `CONTEXTUAL` tanpa histori. Hanya response anonymous `CONTEXTUAL` yang boleh public-cache maksimum 60 detik dengan key slug+limit dan tag invalidasi event; cache tidak boleh memuat actor/history.
- Tidak ada optimistic update untuk angka operasional.

## Algoritma/pseudocode

```text
dashboard(actor, filter):
  organizerId = requireApprovedOrganizer(actor)
  validate range; authorize event ownership
  REPEATABLE READ:
    aggregate paid orders/items, issued tickets, successful check-ins, completed refunds
    fetch event page using keyset
  assert every count >= 0; return asOf database_now

exportCsv(actor,eventId,filter):
  require owner; audit export_requested
  stream cursor batches of 500
  for each cell: prefix "'" when first non-space char is =,+,-,@,tab,CR
  quote RFC4180; mask minimum PII; abort on disconnect

recommend(actor?, currentEventSlug, limit):
  current = require Published public event
  candidates = Published AND startsAt > database_now AND id != current.id
  if actor has Paid history:
    exclude event IDs purchased by actor; score from capped category/location/organizer counts
  else:
    score from current event category/location/organizer
  keep score > 0; order score DESC, startsAt ASC, id ASC
  return limit safe projections + highest-priority reason; never return score/history
```

## UI/UX

- Dashboard organizer menampilkan filter event/rentang, empat kartu wajib, label “Nilai bruto sandbox—bukan settlement”, tabel event, dan empty state.
- Angka memiliki waktu `asOf`; refresh eksplisit tersedia tanpa animasi berlebihan.
- Admin memakai tab antrean dengan jumlah, alasan stabil, usia kasus, dan tautan detail.
- Tombol ekspor menjelaskan kolom/PII, status proses, serta error retry; tidak mengunci halaman.
- Grafik F47 memiliki tabel data alternatif dan kegagalan terisolasi.
- Pencarian F48 mengelompokkan hasil per entitas dan tidak menyorot PII lengkap.
- Detail event menampilkan bagian “Event serupa” setelah konten utama; alasan singkat bukan klaim personal sensitif, empty state tidak mengganggu CTA pembelian, dan kartu menggunakan projection katalog publik.

## Error dan recovery

- Kode: `REPORT_RANGE_INVALID`, `REPORT_EVENT_FORBIDDEN`, `REPORT_QUERY_FAILED`, `REPORT_CURSOR_INVALID`, `EXPORT_RATE_LIMITED`, `EXPORT_FAILED`, `EXPORT_TOO_LARGE`, `ADMIN_SEARCH_INVALID`, `ADMIN_SEARCH_DISABLED`, `RECOMMENDATION_UNAVAILABLE`, `RECOMMENDATION_LIMIT_INVALID`.
- Validation memberi field error; stale cursor meminta ulang dari awal.
- Query/CSV gagal tidak mengubah transaksi domain; UI menawarkan retry dengan filter tetap.
- Grafik/search opsional gagal tidak mengganti ringkasan menjadi nol.
- Rekomendasi gagal tidak menggagalkan detail event atau checkout, tidak mengganti hasil dengan event non-eligible, dan dapat diretry tanpa mempertahankan state personal di client.

## Logging dan monitoring

- Log: report type, actor/organizer/event ID, filter category, row count, duration, outcome, correlation ID.
- Jangan log query search mentah, nama/email peserta, CSV row, external reference, token QR, atau signed cursor.
- Audit wajib untuk ekspor, admin search, dan pembukaan detail sensitif.
- Metrik p95 dashboard/query/export/recommendation, rows exported, candidate count, mode aggregated, error, timeout, dan search zero-result.
- Alert jika dashboard 5xx >2%/15 menit atau query p95 >1,5 detik selama 15 menit.

## Keamanan dan privasi

- RBAC dan ownership selalu server-side; event ID client tidak cukup.
- Projection allowlist, masking PII, rate limit, cursor bertanda tangan, dan CSV injection protection wajib.
- CSV memakai `nosniff`, tidak memiliki URL publik, dan tidak ditulis ke disk.
- Query parameterized; daftar sort/type berupa enum; maksimum rentang/limit mencegah data scraping.
- Admin search akses sensitif diaudit; organizer tidak dapat mencari lintas event/tenant.
- Rekomendasi authenticated hanya membaca Paid history actor dari session, menggunakan projection allowlist, tidak mengekspos score/count/sinyal, dan tidak menulis profil minat.
- Log, analytics, cache key, dan metric dilarang memuat user-event history, purchased event IDs, alasan per-user, PII, alamat pembeli, IP-derived location, atau koordinat.

## Kinerja

- Target p95 ringkasan/tabel ≤1,5 detik pada event 5.000 tiket; admin queue/search ≤2 detik.
- CSV 5.000 row mulai mengirim ≤2 detik, memori tambahan ≤20 MiB, batch 500.
- Gunakan keyset, field eksplisit, agregasi satu-pass, `EXPLAIN ANALYZE BUFFERS`, tanpa N+1.
- F47 bucket dihitung SQL dengan timezone event; chart library dimuat dinamis dan tidak memblokir F43.
- Rekomendasi p95 ≤500 ms untuk histori 500 order Paid dan katalog 10.000 event, memakai agregasi seluruh histori Paid actor melalui indeks dan satu query kandidat tanpa N+1; mode contextual p95 ≤300 ms.

## Aksesibilitas dan i18n

- Kartu memakai heading/list semantic; tabel caption/header; filter berlabel dan keyboard penuh.
- Grafik memiliki ringkasan dan tabel ekuivalen; warna bukan satu-satunya pembeda.
- Status loading/error diumumkan `aria-live`; fokus kembali ke hasil setelah filter.
- Bahasa Indonesia, `id-ID`, Rupiah integer tanpa pecahan, waktu sesuai timezone event.
- Layout 320/360 px tidak kehilangan filter atau aksi ekspor.

## Dependensi dan fallback

- Memakai auth/ownership RFC-002/004, audit RFC-003, serta event/order/payment/ticket/check-in RFC-005–011.
- F47 boleh memakai library chart yang telah disetujui; fallback wajib tabel data dan kartu F43.
- F48 memakai PostgreSQL/index, bukan provider search; jika disabled admin tetap memakai modul individual.
- F74 memakai PostgreSQL dan scoring rule lokal deterministik, bukan provider AI/ML; kegagalan rekomendasi hanya menyembunyikan section dan tidak memblokir detail/checkout.
- Kegagalan analytics tidak memblokir read; kegagalan audit memblokir ekspor/search sensitif.

## Kasus uji

- `F43-INT-001`: semua metrik cocok fixture Paid/Failed/Refunded/Cancelled/Used.
- `F43-SEC-002`: organizer A tidak melihat event atau agregat organizer B.
- `F43-CONC-003`: satu respons memiliki snapshot konsisten saat check-in berjalan.
- `F44-INT-001`: lima antrean hanya memuat case yang tepat dan cursor stabil.
- `F44-SEC-002`: non-admin ditolak dan safe projection tidak memuat PII berlebih.
- `F46-INT-001`: filter CSV sama dengan UI dan stream 5.000 row.
- `F46-SEC-002`: formula injection, CRLF, quote, Unicode, dan cross-tenant aman.
- `F46-E2E-003`: ekspor wajib tersedia untuk organizer owner pada candidate release dan menghasilkan header/kolom eksak.
- `F47-INT-001`: jumlah bucket sama dengan total ringkasan untuk timezone event.
- `F47-A11Y-002`: tabel alternatif memiliki data ekuivalen.
- `F48-INT-001`: exact ID/reference dan grouped search benar.
- `F48-SEC-002`: query tidak dilog, hasil dimasked, akses diaudit.
- `F74-UNIT-001`: score, cap, alasan, dan tie-break deterministik untuk seluruh kombinasi kategori/kota/provinsi/organizer.
- `F74-INT-002`: hanya Published-future; current, Cancelled, Completed, dan event yang sudah dibeli pada mode histori tidak muncul.
- `F74-SEC-003`: user A tidak memengaruhi/melihat sinyal user B; response/log/cache bebas PII, score, count, purchased IDs, dan geolokasi.
- `F74-E2E-004`: authenticated dengan histori memakai mode HISTORY; anonymous/no-history mendapat fallback CONTEXTUAL; empty/error tidak memblokir detail.
- `F74-PERF-005`: budget p95 dan query plan lulus pada 500 histori Paid/10.000 kandidat tanpa N+1.

## Migrasi dan rollout

1. Pastikan regression RFC-001–011, backup preview, serta skema nyata pendahulu diverifikasi.
2. Rekam baseline query plan; buat indeks additive/non-blocking dan ulangi plan.
3. Deploy repository/API di balik flag; bandingkan agregat dengan SQL fixture dan sample manual.
4. Aktifkan dan verifikasi F43/F44, kemudian F46 wajib; aktifkan F74 setelah hasil Paid-history dibandingkan dengan fixture scoring deterministik.
5. Pantau latensi, row scan, ekspor, cache separation, candidate count, recommendation error, dan audit selama preview; F47/F48 hanya setelah seluruh Must Have stabil.
6. Rollback menutup route/flag; indeks boleh dipertahankan atau dihapus concurrent tanpa mengubah data.

## Risiko dan mitigasi

- Definisi angka berbeda: rumus eksplisit, fixture lintas status, `asOf`, dan label bruto/refund terpisah.
- Kebocoran tenant/PII: predicate ownership, safe projection, masking, audit, security test.
- Query berat: indeks, keyset, batas rentang, plan test, streaming.
- CSV injection/memory spike: sanitasi RFC4180, batch stream, abort saat disconnect.
- Rekomendasi membocorkan preferensi atau bias nondeterministik: histori hanya milik actor, tanpa profil persisten/PII/geolokasi, score/alasan eksplisit, tie-break stabil, dan privacy regression.
- Fitur opsional mengganggu inti: flags dan failure boundary terpisah.

## Kriteria penerimaan per fitur

- **F43:** organizer hanya melihat event miliknya; Paid, tiket terjual, bruto sandbox, refund terpisah, dan check-in konsisten dengan sumber; empty state tersedia.
- **F44:** admin melihat antrean moderasi, payment bermasalah/terlambat, pembatalan, refund, dan membuka detail aman; mutasi tetap memakai service terdahulu dan diaudit.
- **F46:** organizer mengekspor peserta/check-in event sendiri sesuai filter, kolom minimum termasuk kategori/area dan label kursi, streaming, masking, dan perlindungan CSV injection.
- **F47:** bila diaktifkan, tren memiliki rentang/timezone jelas, total sama dengan ringkasan, tabel aksesibel, dan kegagalan tidak memblokir dashboard.
- **F48:** bila diaktifkan, admin mencari enam entitas secara grouped/paginated dengan exact match, masking, audit, dan tanpa akses non-admin.
- **F74:** authenticated mendapat event serupa dari histori Paid miliknya, sedangkan anonymous/no-history mendapat fallback kontekstual; hanya Published-future, current/already-purchased dikecualikan sesuai mode, score/tie-break/alasan deterministik, dan response/cache/log tidak membocorkan histori, PII, atau geolokasi.
