# RFC-004 — Organizer dan Moderasi

## Metadata dan urutan

- Status: Diusulkan.
- Fitur yang dimiliki: **F7, F8**.
- Kompleksitas: **Sedang**.
- Prasyarat seluruh RFC terdahulu: **RFC-001, RFC-002, dan RFC-003 wajib selesai dan lulus**.
- Pendahulu langsung: **RFC-003 — Audit dan Analitik**.
- Penerus langsung: **RFC-005 — Penulisan Event dan Tipe Tiket**.
- Hanya platform, auth/RBAC, audit, dan analytics terdahulu yang dipakai.
- RFC-005 baru boleh dimulai setelah Definition of Done RFC-004 lulus.

## Keputusan dan sasaran

Satu user memiliki maksimal satu profil organizer. Pengajuan awal langsung `PENDING`; hanya admin dapat approve, reject, suspend, atau restore dengan alasan. Capability organizer dihitung server-side dari profil `APPROVED`, tidak masuk JWT/role. Keputusan memakai optimistic concurrency, audit atomik, dan analytics setelah commit. Pending/rejected/suspended tidak memperoleh capability.

## Ruang lingkup

- Form pengajuan serta halaman status owner.
- Edit/resubmit pengajuan rejected.
- Antrean/detail moderasi admin dengan cursor pagination.
- Keputusan approve/reject/suspend/restore.
- Policy `requireApprovedOrganizer` dan ownership profil.
- Audit dan analytics submit/approve/reject.

## Non-scope

- KYC, dokumen identitas, legalitas, rekening, payout, dan uang nyata.
- Event, ticket type, image upload, storage, publikasi, atau katalog (RFC-005+).
- Hard delete, multi-owner/tim, transfer ownership, atau auto-approval.
- Email/in-app notification; halaman status adalah fallback.

## Gap kondisi saat ini

- Prototype hanya memiliki role user, tanpa profil/status/alasan organizer.
- Belum ada pengajuan, antrean admin, lifecycle, capability, atau ownership.
- RFC-002 menyediakan policy default-deny tetapi belum capability domain.
- RFC-003 menyediakan writer/emitter tetapi belum aksi organizer.

## Aturan domain

- Status: `PENDING`, `APPROVED`, `REJECTED`, `SUSPENDED`.
- Transisi user: none→PENDING; REJECTED→PENDING setelah edit/resubmit.
- Transisi admin: PENDING→APPROVED|REJECTED; APPROVED→SUSPENDED; SUSPENDED→APPROVED.
- Transisi lain ditolak `ORGANIZER_TRANSITION_INVALID`.
- Semua keputusan admin memerlukan alasan plain text 10–1000 karakter.
- `APPROVED` satu-satunya status dengan capability organizer.

## Arsitektur komponen tekstual

`Organizer UI → Route → Zod → OrganizerApplicationService → repository → Prisma`. `Admin UI → requireRole(ADMIN) → ModerateOrganizerService → transaction(update + AuditWriter)`. `Organizer use case → requireApprovedOrganizer(actorId) → profile lookup → capability`. `Commit berhasil → AnalyticsEmitter`; analytics gagal tidak membatalkan keputusan. Module masa depan memakai organizer ID/capability interface, bukan memeriksa status sendiri.

## Aliran data tekstual

1. User aktif mengirim form; owner dari session, input dinormalisasi, rate limit diperiksa.
2. Transaction insert profil PENDING dan audit submit; duplicate diputus unique constraint.
3. Admin mengirim decision/reason/expectedVersion.
4. Service membaca status, memvalidasi transition, conditional update version, dan audit before/after.
5. Zero update menjadi 409; commit sukses mengirim analytics.
6. Request capability berikutnya membaca status database terbaru.

## Perubahan model data/skema eksak

Migration `0004_organizer_moderation`:

### Enum

- `organizer_status`: `PENDING`, `APPROVED`, `REJECTED`, `SUSPENDED`.

### `organizer_profiles`

- `id TEXT PRIMARY KEY` (CUID).
- `owner_user_id TEXT NOT NULL REFERENCES users(id) ON DELETE RESTRICT`.
- `name VARCHAR(120) NOT NULL`.
- `contact_email VARCHAR(254) NOT NULL`.
- `contact_phone VARCHAR(32) NULL`.
- `description VARCHAR(2000) NOT NULL`.
- `status organizer_status NOT NULL DEFAULT 'PENDING'`.
- `decision_reason VARCHAR(1000) NULL`.
- `submitted_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `decided_at TIMESTAMPTZ NULL`.
- `decided_by_user_id TEXT NULL REFERENCES users(id) ON DELETE RESTRICT`.
- `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `version INTEGER NOT NULL DEFAULT 1 CHECK (version > 0)`.
- Unique index `organizer_profiles_owner_key(owner_user_id)`.
- Index `(status,submitted_at ASC,id ASC)` dan `(name)`.
- Check trimmed `name` 2–120, `description` 20–2000, lowercase contact email.
- Check status: PENDING wajib decision fields null; status lain wajib ketiganya non-null.
- Tidak ada cascade/hard delete; keputusan historis berada di `audit_logs`.

Tidak ada kolom `is_organizer` pada user, perubahan JWT, tabel event, file, atau notification.

## Endpoint

### `POST /api/organizer/applications`

- Auth user ACTIVE; limit 3/user/hari.
- Request: `name,contactEmail,contactPhone|null,description`.
- 201 profil PENDING + submittedAt/version; 409 `ORGANIZER_APPLICATION_EXISTS`.

### `GET /api/organizer/application`

- Auth owner ACTIVE; 200 profil/reason milik sendiri; 404 not found.
- `Cache-Control: private, no-store`.

### `PATCH /api/organizer/application`

- Auth owner; hanya REJECTED.
- Request field profil lengkap + `expectedVersion`; 200 tetap REJECTED/version+1.

### `POST /api/organizer/application/resubmit`

- Auth owner; hanya REJECTED; request `expectedVersion`.
- 200 PENDING, decision fields null, submittedAt baru.

### `GET /api/organizer/capabilities`

- Auth user ACTIVE; 200 `organizerProfileId,status,canManageOrganizerResources`.
- User ID diturunkan dari session; no-store.

### `GET /api/admin/organizer-applications`

- Auth ADMIN; query `status?,cursor?,limit 1..100,q?`; default 25.
- 200 safe summary dan signed next cursor.

### `GET /api/admin/organizer-applications/{id}`

- Auth ADMIN; 200 profil, owner minimum/masked, version, audit history; 404.

### `POST /api/admin/organizer-applications/{id}/decisions`

- Auth ADMIN + CSRF.
- Request: `decision APPROVE|REJECT|SUSPEND|RESTORE`, `reason`, `expectedVersion`.
- 200 profil terbaru; 409 transition/version conflict.

## State dan caching

- PostgreSQL source of truth; JWT tidak menyimpan organizer status.
- Owner/admin pages `private, no-store`; filters/cursor pada URL.
- Form/dialog memakai local state; tidak ada optimistic moderation.
- Selesai mutasi melakukan refresh server; tidak ada global capability cache.

## Algoritma/pseudocode inti

```text
moderate(id, decision, reason, version, admin):
  require ADMIN
  transaction: read current; validate transition
  conditional update WHERE id/version; bila 0, conflict
  append audit(before, after, reason); commit; emit analytics
requireApprovedOrganizer(userId):
  profile = findByOwner(userId)
  bila tidak ada/!APPROVED: deny dengan reason stabil
  return organizerId
```

## UI/UX

- Tanpa profil: manfaat+form tanpa KYC; Pending: “Sedang ditinjau”; Approved: capability aktif.
- Rejected/Suspended menampilkan alasan/pemulihan; hanya Rejected dapat edit/resubmit.
- Admin list menunjukkan usia antrean/status/nama/kontak masked.
- Dialog keputusan menampilkan target/alasan/warning; version conflict meminta refresh.

## Kode error stabil

`ORGANIZER_APPLICATION_EXISTS`, `ORGANIZER_APPLICATION_NOT_FOUND`, `ORGANIZER_APPLICATION_PENDING`, `ORGANIZER_ALREADY_APPROVED`, `ORGANIZER_NOT_APPROVED`, `ORGANIZER_REQUIRED`, `ORGANIZER_TRANSITION_INVALID`, `ORGANIZER_VERSION_CONFLICT`, `ORGANIZER_REASON_REQUIRED`, `ORGANIZER_CONTACT_INVALID`, `ORGANIZER_RATE_LIMITED`, `ORGANIZER_ACCESS_DENIED`.

## Logging dan monitoring

- Log hanya ID/action/from-to/correlation tanpa kontak/deskripsi/reason; audit menyimpan allowlisted diff.
- Analytics submit/approve/reject tanpa PII; metrik pending/decision/conflict/p95 dan alert audit failure, pending >72 jam, atau 5xx >2%/15 menit.

## Keamanan dan privasi

- Owner selalu dari session; endpoint user tidak menerima owner ID.
- Admin/CSRF server-side; input plain text/escaped; kontak hanya owner/admin dan masked pada list.
- Tanpa KTP/NPWP/rekening/file; capability database default-deny dan suspend berlaku request berikutnya.

## Kinerja

- Unique owner index memberi satu lookup capability berindeks.
- Cursor default 25/maksimum 100; description hanya detail; search minimum dua karakter dan field eksplisit.
- p95 capability ≤200 ms, list/detail ≤700 ms; conditional version mencegah lost update.

## Aksesibilitas dan lokalisasi

- Label/hint/error/focus dan keyboard penuh; status teks+ikon; dialog mengelola fokus.
- Waktu `id-ID` berzona, copy Indonesia, dan layout 360 px tanpa overflow.

## Dependensi pihak ketiga/fallback

- Hanya dependency RFC terdahulu; tanpa KYC/storage/email/moderation provider.
- Analytics gagal: degraded tetapi commit; audit gagal: rollback; database gagal: 503 tanpa hardcoded capability.

## Kasus uji spesifik

- `F7-INT-001`: user membuat satu profil Pending ternormalisasi.
- `F7-CONC-002`: submit paralel menghasilkan satu 201/satu 409.
- `F7-SEC-003`: owner A tidak membaca/mengubah profil B.
- `F7-INT-004`: hanya Rejected dapat edit/resubmit.
- `F8-UNIT-001`: seluruh transition matrix exhaustively tested.
- `F8-INT-002`: approve mengubah capability false→true.
- `F8-INT-003`: suspend mengubah true→false tanpa delete.
- `F8-CONC-004`: dua admin/version sama hanya satu sukses.
- `F8-AUD-005`: update+audit atomik; audit gagal rollback.

## Migrasi dan rollout

1. Regression RFC-001–003 dan backup preview lulus.
2. Terapkan enum/tabel/constraint/index additive.
3. Deploy default false, buka pengajuan/moderasi, lalu verifikasi audit, analytics, lifecycle, concurrency.
4. Promote dan pantau; rollback menutup route tetapi mempertahankan history tanpa down migration.

## Risiko dan mitigasi

- Role global disalahgunakan: capability hanya profil Approved.
- Lost admin update: conditional version dan 409.
- Reason berisi PII/HTML: plain text, escaping, no-log.
- Status/notifikasi: status tidak masuk JWT dan halaman status menjadi fallback.
- Scope KYC: tidak ada field/file dan wajib decision gate.

## Kriteria penerimaan per fitur

- **F7:** pengajuan valid Pending/terlihat admin; owner melihat status/reason; duplicate ditolak; Rejected dapat edit/resubmit; Pending tidak memberi capability.
- **F8:** admin menjalankan transition valid dengan alasan; Approved memberi dan Suspended mencabut capability; keputusan audit atomik/analytics aman; conflict/unauthorized berkode stabil.

## Definition of Done

1. Regression RFC-001–003 lulus.
2. Migration/constraint/index/transition/rollback strategy teruji PostgreSQL.
3. Endpoint memakai Zod, auth, ownership, CSRF/rate limit relevan, error envelope, correlation ID.
4. Unit/integration/E2E/security/concurrency F7–F8 lulus.
5. Audit atomik dan analytics submit/approve/reject tervalidasi.
6. UI owner/admin responsif, Indonesia, keyboard-accessible, WCAG 2.1 AA.
7. Branch coverage organizer ≥90%; format/lint/typecheck/build/test/scan lulus.
8. Tidak ada blocker/critical, security Critical/High, KYC, event, notification, atau provider baru.
9. RFC-005 hanya dimulai setelah RFC ini disetujui.
