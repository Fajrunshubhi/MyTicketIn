# RFC-011 — Scanner dan Check-in

## Metadata dan urutan
- Status: Diusulkan.
- Fitur yang dimiliki: **F37, F38, F39, F40, F41**.
- Kompleksitas: **Sangat tinggi**.
- Prasyarat: **RFC-001, RFC-002, RFC-003, RFC-004, RFC-005, RFC-006, RFC-007, RFC-008, RFC-009, dan RFC-010 wajib selesai dan lulus**.
- Pendahulu langsung: **RFC-010 — E-ticket, QR, dan Wallet**.
- Penerus langsung: **RFC-012 — Dashboard dan Pelaporan**.
- RFC-012 hanya boleh dimulai setelah Definition of Done RFC ini lulus.
- Scanner wajib online; RFC ini tidak membuat mode offline, sinkronisasi perangkat, dashboard, CSV, atau notifikasi.

## Sasaran dan keputusan
Organizer pemilik event dan petugas aktif dapat memindai QR melalui kamera browser atau memasukkan manual code. Server memvalidasi event, payment, dan status Ticket, lalu melakukan transisi atomik `UNUSED→USED`. Dua request bersamaan hanya menghasilkan satu `VALID`; setiap request yang mencapai validasi domain dicatat sebagai attempt immutable tanpa token mentah.

## Ruang lingkup
- Halaman scanner online per event dengan Browser Camera API dan `@zxing/browser`.
- Authorization organizer owner atau assignment ACTIVE pada setiap request.
- Hasil stabil: `VALID`, `ALREADY_USED`, `INVALID`, `CANCELLED`, `WRONG_EVENT`.
- Check-in atomik satu kali dan timestamp database.
- Attempt log untuk sukses/gagal serta idempotensi retry request.
- Input manual code dengan aturan domain yang sama dan rate limit lebih ketat.
- Riwayat attempt minimum untuk organizer event dan admin, berhalaman.

## Non-scope
- Scanner offline, local acceptance, predownload token, sync/conflict resolution, turnstile.
- Dashboard agregat, export CSV, grafik (RFC-012), notification (RFC-013).
- Undo check-in, mengubah Used menjadi Unused, transfer tiket, scan lintas event.
- Biometric/identity verification, penyimpanan foto peserta, GPS petugas.
- Perubahan Ticket/QR issuance selain kolom provenance Used.

## Gap kondisi setelah RFC-010
- Ticket dan QR aman tersedia, tetapi belum ada endpoint validasi atau akses kamera.
- Enum `USED` dan `used_at` ada, namun tidak ada command yang boleh menghasilkannya.
- Assignment staff tersedia dari RFC-006, belum dipakai scanner.
- Belum ada attempt log, reason code, debounce, idempotensi scan, atau metrik latensi.

## Invarian dan keputusan hasil
- Maksimum satu attempt `VALID` per Ticket; Ticket `USED` tidak pernah kembali.
- `VALID` hanya jika token/code dikenal, event cocok, Ticket `UNUSED`, order `PAID`, event bukan Cancelled, dan aktor berwenang.
- Ticket `USED` pada event benar menghasilkan `ALREADY_USED` dan `firstUsedAt`.
- Ticket `CANCELLED` pada event benar menghasilkan `CANCELLED`.
- Ticket dikenal untuk event lain menghasilkan `WRONG_EVENT`; token tidak dikenal/format salah menghasilkan `INVALID`.
- Order bukan Paid diperlakukan `INVALID` ke petugas dan reason internal `ORDER_NOT_PAID`.
- Masalah network/server menghasilkan error transport, bukan hasil `INVALID`.
- Authorization event dilakukan sebelum lookup token; aktor tanpa akses menerima 404/403 dan tidak dapat menguji token.
- Setiap idempotency key+payload sama mengembalikan attempt sama; key sama payload beda `409`.

## Diagram komponen tekstual
```text
ScannerPage(client) → CameraPermission → ZXing decode → debounce/single-flight
                   └→ manual input
POST check-in → EventOperatorPolicy → CheckInService
                                  → TokenHasher/manual lookup
                                  → TicketRepository atomic update
                                  → CheckInAttemptRepository + AuditWriter
Attempt List RSC → CheckInAttemptQueryService → owner/admin projection
Post-commit → analytics + sound/vibration best effort
```

## Diagram aliran data tekstual
1. RSC memeriksa akses event dan merender client scanner tanpa data Ticket.
2. Client meminta izin kamera setelah aksi pengguna, memilih kamera belakang, dan decode lokal.
3. Token dikirim sekali dalam single-flight dengan idempotency key; preview kamera tidak direkam.
4. Server memeriksa session/status/owner-assignment dan menghitung hash token berpepper.
5. Transaction mencari Ticket, menentukan reason, dan melakukan conditional update bila eligible.
6. Attempt untuk hasil tersebut disisipkan dalam transaction yang sama; insert gagal membatalkan update Used.
7. Response minimal menggerakkan feedback visual/audio; scanner menahan token sama selama cooldown.
8. Network failure mempertahankan Ticket server apa adanya dan menawarkan retry dengan key sama.

## Perubahan skema database eksak
Migration: `0011_scanner_check_in`.

### Enum
- `check_in_result`: `VALID`, `ALREADY_USED`, `INVALID`, `CANCELLED`, `WRONG_EVENT`.
- `check_in_input_type`: `QR_TOKEN`, `MANUAL_CODE`.

### Tambahan kolom `tickets`
- `used_by_user_id TEXT NULL REFERENCES users(id) ON DELETE RESTRICT`.
- Constraint `tickets_used_actor_chk`: status USED wajib `used_at` dan `used_by_user_id`; status lain keduanya null.
- Constraint status RFC-010 diperbarui agar rule baru menjadi satu sumber konsisten.
- Index `tickets_event_used_idx(event_id,used_at DESC,id DESC) WHERE status='USED'`.
- Unique token hash dan manual code dari RFC-010 tetap menjadi lookup index.

### Tabel `check_in_attempts`
- `id TEXT PRIMARY KEY` (CUID).
- `event_id TEXT NOT NULL REFERENCES events(id) ON DELETE RESTRICT`.
- `ticket_id TEXT NULL REFERENCES tickets(id) ON DELETE RESTRICT`.
- `operator_user_id TEXT NOT NULL REFERENCES users(id) ON DELETE RESTRICT`.
- `input_type check_in_input_type NOT NULL`; `result check_in_result NOT NULL`.
- `reason_code VARCHAR(80) NOT NULL`.
- `attempted_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- `first_used_at TIMESTAMPTZ NULL`.
- `input_fingerprint CHAR(64) NOT NULL`.
- `idempotency_key_hash CHAR(64) NOT NULL`; `request_hash CHAR(64) NOT NULL`.
- `correlation_id VARCHAR(80) NOT NULL`; `duration_ms INTEGER NOT NULL`.
- `client_context JSONB NOT NULL DEFAULT '{}'::jsonb`.
- Constraints: duration `>=0`; client context object dan hanya allowlist `{scannerVersion,cameraFacing,browserFamily}`.
- Result VALID/ALREADY_USED/CANCELLED/WRONG_EVENT wajib ticket; INVALID boleh ticket null untuk order mismatch internal.
- VALID dan ALREADY_USED wajib `first_used_at`; hasil lain wajib null.
- Unique `check_in_attempts_operator_event_key(operator_user_id,event_id,idempotency_key_hash)`.
- Partial unique `check_in_attempts_ticket_valid_key(ticket_id) WHERE result='VALID'`.
- Index `check_in_attempts_event_time_idx(event_id,attempted_at DESC,id DESC)`.
- Index `check_in_attempts_operator_time_idx(operator_user_id,attempted_at DESC,id DESC)`.
- Index `check_in_attempts_ticket_time_idx(ticket_id,attempted_at DESC,id DESC) WHERE ticket_id IS NOT NULL`.
- Trigger `check_in_attempts_immutable` menolak `UPDATE` dan `DELETE`; tidak ada write API selain CheckInService.

### Fingerprint input
- `input_fingerprint = HMAC-SHA-256(CHECKIN_FINGERPRINT_KEY, normalizedInput)`.
- Key terpisah dari QR pepper/encryption key, minimum 32 byte, berbeda per environment.
- Fingerprint hanya untuk korelasi abuse/duplikasi, tidak dapat dipakai lookup Ticket dan tidak tampil di API/UI.
- Retensi attempt sepanjang MVP akademik; perubahan untuk data nyata memerlukan decision gate privasi.

## Kontrak API
Semua route session ACTIVE, authorization objek server-side, Zod, correlation ID, rate limit, dan `private,no-store`.

### `GET /api/events/{eventId}/scanner-access`
- Auth organizer owner atau staff ACTIVE.
- Respons 200 `{event:{id,title,startsAt,timezone,venueName},permissions:{scan:true,manualEntry:true}}`.
- Event bukan milik/tugas mengembalikan 404 generik; assignment dibaca database setiap request.

### `POST /api/events/{eventId}/check-ins`
- Auth organizer owner atau staff ACTIVE; CSRF.
- Header `Idempotency-Key` 16–128 ASCII wajib.
- Request discriminated union:
  - `{"inputType":"QR_TOKEN","value":"ti1_<43 base64url chars>","clientContext":{...}}`
  - `{"inputType":"MANUAL_CODE","value":"XXXX-XXXX-XXXX-XXXX","clientContext":{...}}`
- QR rate 120/operator/event/menit; invalid burst 20/operator+IP pseudonim/menit; manual 20/operator/event/menit.
- Respons domain 200:
  `{attemptId,result:"VALID|ALREADY_USED|INVALID|CANCELLED|WRONG_EVENT",reasonCode,message,firstUsedAt?,ticket:{ticketNumberMasked,ticketTypeName}? ,serverTime}`.
- Hanya VALID/ALREADY_USED/CANCELLED pada event benar boleh mengembalikan ticket type dan nomor tersamar.
- `400 CHECKIN_REQUEST_INVALID` hanya untuk body/union/ukuran yang tidak dapat diproses; format token/code yang salah tetap hasil `INVALID` dan tercatat.
- `401`, `404`, `409 IDEMPOTENCY_KEY_REUSED`, `429`, `503 CHECKIN_UNAVAILABLE` adalah transport/boundary error, bukan result tiket.

### `GET /api/events/{eventId}/check-in-attempts`
- Auth organizer owner atau ADMIN; staff biasa tidak dapat menelusuri histori.
- Query `result?`, `from?`, `to?`, `cursor?`, `limit=1..100` default 25.
- Respons 200 `{items:[{id,result,reasonCode,attemptedAt,firstUsedAt?,ticketNumberMasked?,operatorName}],nextCursor}`.
- Projection tidak memuat token, hash/fingerprint, email, ciphertext, raw client context, atau provider data.

## State dan caching
- Database source of truth; tidak ada optimistic Used atau cache hasil sebagai otoritas.
- Scanner client memiliki state `IDLE|REQUESTING_PERMISSION|SCANNING|SUBMITTING|SHOWING_RESULT|NETWORK_ERROR`.
- Satu request in-flight; token sama diabaikan 3 detik setelah response, lalu dapat dipindai lagi dan menghasilkan ALREADY_USED.
- Retry network memakai idempotency key sama; scan baru membuat key baru.
- Halaman/API/attempt selalu no-store; tidak menyimpan token di URL, localStorage, IndexedDB, service worker, atau history.
- Pencabutan assignment berlaku pada request berikutnya tanpa menunggu refresh JWT.

## Algoritma/pseudocode
```text
checkIn(actor,eventId,input,key):
  authorize owner or ACTIVE assignment before token lookup
  normalized, formatValid = normalize bounded value; requestHash = sha256(inputType+normalized)
  tokenHash = formatValid and inputType QR ? sha256(normalized+QR_PEPPER) : null
  fingerprint = hmac(CHECKIN_FINGERPRINT_KEY, normalized)
  transaction:
    existing = attempt by actor+event+sha256(key)
    if existing: require requestHash equal; return existing response projection
    ticket = formatValid ? lookup exact tokenHash/manualCode with order status : null
    result = formatValid ? classify(ticket,eventId,event status,order status) : INVALID
    if result candidate VALID:
      updated = UPDATE tickets
        SET status='USED',used_at=statement_timestamp(),used_by_user_id=actor,version=version+1
        WHERE id=ticket.id AND event_id=eventId AND status='UNUSED'
      if updated row: result=VALID; firstUsedAt=used_at
      else reread: result=ALREADY_USED or CANCELLED
    insert immutable attempt; partial unique valid guards one success
    append audit only VALID and authorization abuse; commit
  on idempotency unique race: reread attempt, require requestHash equal, return it
  emit analytics after commit; return localized mapping
```

## UI/UX
- Scanner dibuka pada event terpilih dengan judul event selalu terlihat untuk mencegah wrong-event.
- Permission kamera diminta setelah tombol “Aktifkan kamera”; pilihan kamera belakang dan stop stream saat tab hidden/unmount.
- Viewfinder memiliki instruksi, torch bila browser mendukung, dan tombol input manual.
- Panel hasil layar penuh: hijau+ikon+“Valid”, amber “Sudah digunakan”, merah untuk Invalid/Cancelled/Wrong Event; warna bukan satu-satunya sinyal.
- VALID dapat memberi bunyi/getar singkat setelah preferensi pengguna; error network memakai tampilan berbeda dan tombol retry.
- Setelah hasil dikonfirmasi/delay singkat, petugas kembali scan; tidak auto-submit frame selama panel aktif.

## Error, logging, dan monitoring
- Reason code: `CHECKIN_OK`, `TICKET_ALREADY_USED`, `TOKEN_UNKNOWN`, `TOKEN_FORMAT_INVALID`, `TICKET_CANCELLED`, `WRONG_EVENT`, `ORDER_NOT_PAID`, `EVENT_CANCELLED`.
- Boundary: `SCANNER_ACCESS_DENIED`, `CAMERA_PERMISSION_DENIED`, `CAMERA_NOT_FOUND`, `CAMERA_IN_USE`, `CHECKIN_RATE_LIMITED`, `CHECKIN_UNAVAILABLE`, `IDEMPOTENCY_KEY_REUSED`.
- Log: event/operator/ticket internal ID bila dikenal, attempt/result/reason, duration, device family, correlation; tanpa token, manual code, fingerprint, peserta PII, atau frame.
- Analytics: `checkin_succeeded` atau `checkin_rejected` dengan event ID/reason; dedup attempt ID.
- Metrik: result count, p50/p95, DB conflict, invalid rate, camera client error, 429, 5xx; alert p95 >1,5 detik, 5xx >2%, atau pola invalid abnormal.

## Keamanan dan privasi
- HTTPS wajib untuk camera dan token transit; CSP membatasi script/library dan permission policy `camera=(self)`.
- Authorization owner/assignment pada server setiap scan/list; staff tidak memperoleh daftar peserta.
- Rate limit QR/manual/invalid, CSRF, input length/charset, timing-safe hash handling, dan generic invalid response.
- Wrong Event diberikan hanya kepada operator berwenang pada target event; tidak mengungkap event asal.
- Attempt immutable, minim PII, token tidak disimpan; retensi dan akses harus ditinjau sebelum pilot nyata.
- Dependency scanner dipin exact dan security scan; kamera dihentikan ketika tidak digunakan.

## Kinerja
- Lookup memakai unique token hash/manual code; update conditional dan insert attempt satu transaction.
- Target validasi online p95 ≤1,5 detik pada 10 scanner bersamaan selama 15 menit.
- Attempt list keyset dan projection eksplisit; tanpa count wajib.
- Debounce/single-flight mengurangi flood tanpa menjadi kontrol correctness.
- Connection pool dan transaction dibuat singkat; tidak ada network/provider call di dalam transaction.

## Aksesibilitas dan i18n
- Kamera mempunyai alternatif manual, instruksi tekstual, label, keyboard, focus result, dan `aria-live="assertive"`.
- Hasil dibedakan teks, ikon, pola, dan opsional audio; tidak hanya warna/audio.
- Target WCAG 2.1 AA, reduced motion, touch target ≥44 px, viewport 320 px tanpa overflow.
- Bahasa Indonesia konsisten; waktu penggunaan ditampilkan pada timezone event dengan nama zona.
- Uji dua versi terbaru browser target; camera flow wajib Chrome Android, fallback manual untuk incompatibility.

## Dependensi dan fallback
- Ticket/token/wallet RFC-010, Paid/order RFC-008/009, staff/event RFC-005/006, auth/audit RFC-002/003.
- `@zxing/browser` versi exact sesuai RULES; native `getUserMedia`.
- Kamera gagal/ditolak/tidak kompatibel → input manual online; koneksi gagal → tidak ada accept lokal.
- Sound/vibration tidak didukung → visual/teks tetap lengkap; analytics gagal tidak memblokir.
- Database/audit gagal → transaction rollback dan response unavailable, bukan Invalid.

## Kasus uji
- `F37-E2E-001`: Chrome Android permission→rear camera→decode→submit; stream berhenti saat keluar.
- `F37-NET-002`: offline/timeout tidak menandai Used dan retry key sama mengembalikan hasil sama.
- `F38-INT-001`: semua result/reason benar; server error terpisah dari INVALID.
- `F39-CONC-001`: 20 scan simultan Ticket sama menghasilkan satu VALID dan 19 ALREADY_USED.
- `F39-INT-002`: Cancelled, wrong event, non-Paid, event Cancelled tidak berubah Used.
- `F40-INT-001`: setiap request domain sukses/gagal memiliki attempt; satu partial unique VALID.
- `F40-SEC-002`: log/API/DB attempt tidak memuat raw token/manual code/PII berlebih.
- `F41-INT-001`: manual code mengikuti authorization/state/update yang sama dan rate limit.
- Assignment revoke saat scanner terbuka menolak request berikutnya.
- `NFR-02-PERF-001`: 10 scanner/15 menit, p95 ≤1,5 detik dan double success nol.

## Migrasi dan rollout
1. Regression RFC-001–010, backup preview, HTTPS test device, dan seed Ticket uji tersedia.
2. Tambah enum/kolom/tabel/trigger/index; backfill tidak diperlukan karena belum ada Ticket Used.
3. Deploy access policy dan attempt query, lalu manual input di balik flag.
4. Aktifkan kamera Chrome Android preview; jalankan concurrency, security, accessibility, dan load test.
5. Buka scanner demo per event; monitor p95, invalid burst, DB conflict, dan assignment denied.
6. Rollback menutup route scanner/check-in; status Used/attempt historis tidak dihapus atau dikembalikan.

## Risiko dan mitigasi
- Double check-in: conditional update + transaction + partial unique valid.
- Frame berulang: single-flight/debounce + server idempotency.
- Koneksi venue buruk: error eksplisit dan manual code tetap online; offline sengaja non-scope.
- Staff lintas tenant: policy database setiap request dan owner-scoped attempt query.
- Token brute force: 256-bit QR, 80-bit manual code, rate limit, generic invalid.
- Kamera/browser bermasalah: permission recovery, compatibility test, manual fallback.
- Attempt table tumbuh: indeks/pagination/monitoring; retensi baru wajib sebelum pilot nyata.

## Kriteria penerimaan per fitur
- **F37:** hanya operator berwenang membuka scanner online, decode dikirim single-flight, dan kegagalan kamera/koneksi memiliki recovery aman.
- **F38:** UI/API membedakan Valid, Already Used, Invalid, Cancelled, Wrong Event; first-use tampil tanpa PII dan server error terpisah.
- **F39:** `UNUSED→USED` atomik; scan bersamaan hanya satu sukses; wrong event/Cancelled/non-Paid ditolak.
- **F40:** setiap percobaan server menyimpan event, ticket nullable, operator, waktu, hasil/reason tanpa token mentah; akses log owner/admin.
- **F41:** manual code menjalankan aturan sama, dapat diakses saat kamera gagal, dan terlindung validasi/rate limit.

## Definition of Done
1. Seluruh RFC-001–010 dan regression suite lulus.
2. Migration/trigger/constraint/index, backup, dan rollback diuji pada PostgreSQL preview.
3. Atomic check-in dan immutable attempt dibuktikan dengan race nyata, idempotency retry, dan partial failure.
4. Unit/integration/security/E2E/device/performance F37–F41 lulus; module branch coverage ≥90%.
5. NFR-02 p95 ≤1,5 detik pada 10 scanner/15 menit dan check-in berhasil ganda = 0.
6. Chrome Android camera, fallback manual online, network recovery, mobile, dan WCAG 2.1 AA terverifikasi.
7. Authorization owner/staff revoke, rate limit, no-store, log redaction, dan privacy projection lulus.
8. Format/lint/typecheck/build/test/security scan lulus tanpa blocker, Critical/High, TODO, atau secret.
9. Tidak ada offline scanner, dashboard, CSV, notification, undo Used, atau forward implementation RFC-012+.
10. RFC-012 baru dimulai setelah exit criteria ini disetujui.
