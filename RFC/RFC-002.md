# RFC-002 — Identitas, Sesi, dan RBAC

## Metadata dan urutan

- Status: Diusulkan.
- Fitur yang dimiliki: **F1, F2, F3, F4, F5**.
- Kompleksitas: **Tinggi**.
- Prasyarat seluruh RFC terdahulu: **RFC-001 wajib selesai dan lulus**.
- Pendahulu langsung: **RFC-001 — Platform dan Fondasi Data**.
- Penerus langsung: **RFC-003 — Audit dan Analitik**.
- RFC ini tidak bergantung pada audit, organizer, event, atau RFC-003+.
- RFC-003 baru boleh dimulai setelah Definition of Done RFC-002 lulus.

## Keputusan dan sasaran

Gunakan NextAuth 4.24.15, JWT session, Credentials, Google OAuth, Prisma repository, dan policy default-deny. Role global hanya `USER|ADMIN`; capability organizer/petugas kelak berasal dari record domain, bukan input client atau role baru. Registrasi harus unik dan ter-rate-limit; login bersifat generik; Google linking wajib aman; logout/expiry/revoke menolak sesi lama; seluruh protected action memeriksa session, role, status, dan ownership server-side.

## Ruang lingkup

- F1 registrasi nama, username, email, password.
- F2 login lokal dengan username atau email.
- F3 Google OAuth dan explicit safe linking.
- F4 JWT session, logout, expiry, revoke-all.
- F5 USER/ADMIN, self-ownership, policy registry extensible.
- Persistent auth rate limit serta halaman login/register.

## Non-scope

- Reset password, MFA, passkey, email verification, dan provider selain Google.
- Profil organizer (RFC-004), assignment petugas, dan ownership event.
- Audit persistence/analytics (RFC-003) dan domain setelahnya.
- Account merge otomatis atau SSO enterprise.

## Gap kondisi saat ini

- `allowDangerousEmailAccountLinking` aktif; callback menautkan hanya dari email.
- Role string disalin ke JWT tanpa status atau revocation check.
- Tidak ada account relation, status user, `auth_version`, rate limit, atau policy pusat.
- Registrasi memakai validasi manual, hash sync, ID waktu, dan error nonstandar.
- Lookup `SELECT *`; fixture password tetap berada di source.

## Arsitektur komponen tekstual

`UI → Route/NextAuth adapter → Zod DTO → AuthService → repository → Prisma`. `Protected boundary → requireSession → cek user/status/authVersion → AuthorizationPolicy → use case`. `Credentials → authenticateLocal`; `Google callback → resolveGoogleIdentity`. `RateLimitService → auth_rate_limits`; auth domain tidak mengimpor NextAuth.

## Aliran data tekstual

1. Registrasi menormalisasi input, mengecek limit, hash async, lalu insert; unique constraint menentukan konflik.
2. Login melakukan lookup atau dummy hash, memeriksa status, lalu menerbitkan JWT `sub/role/authVersion/iat/exp`.
3. Boundary sensitif mencocokkan status, role, dan authVersion database.
4. Google memverifikasi state/nonce/email; account existing dipakai, linking email existing butuh session user yang sama.
5. Logout menghapus cookie; revoke-all menaikkan authVersion atomik.
6. Respons hanya membawa profil aman tanpa hash/provider token.

## Perubahan model data/skema eksak

### `auth_accounts`

- `id TEXT PRIMARY KEY` (CUID).
- `user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE`.

### `auth_rate_limits`

- `key_hash CHAR(64) PRIMARY KEY`; SHA-256 scope+IP+identifier.
- `scope VARCHAR(30) NOT NULL CHECK (scope IN ('register','login','oauth'))`.

- `blocked_until TIMESTAMPTZ NULL`.

- Index `auth_rate_limits_cleanup_idx(updated_at)`; IP/email mentah tidak disimpan.

Tidak ada tabel organizer, event, assignment, audit, atau analytics.

## Endpoint

### `POST /api/register`

- Auth publik; limit 5/IP/jam dan 3/identifier/jam.
- Request: `name` 2–120, `username` 3–40 `[a-z0-9._-]`, `email` ≤254, `password/confirmPassword` 10–128.
- 201: `{"data":{"id","name","username","email","role":"USER"}}`.
- 400/409/429 memakai envelope standar.

### `POST /api/auth/callback/credentials`

- Publik melalui NextAuth; CSRF wajib; form `csrfToken,username,password,callbackUrl`.
- Sukses 302 ke URL same-origin; gagal `/login?error=AUTH_INVALID_CREDENTIALS`.

### `GET /api/auth/signin/google` dan `GET /api/auth/callback/google`

- Publik; state/nonce/redirect tervalidasi.
- Konflik email existing tanpa session linking: `/login?error=AUTH_ACCOUNT_LINK_REQUIRED`.

### `GET /api/auth/session`

- Cookie session; 200 aktif berisi `user{id,name,username,role},expires`, anonim `{}`.
- `Cache-Control: private, no-store`.

### `POST /api/auth/signout`

- Session + CSRF; menghapus cookie.

### `POST /api/me/sessions/revoke`

- User ACTIVE; body kosong; 204 setelah increment `auth_version`.

### `GET /api/me`

- User ACTIVE; 200 profil aman; tidak menerima ID user dari client.

## State dan caching

- JWT cookie HttpOnly, Secure pada HTTPS, SameSite=Lax, path `/`, maksimum 8 jam.
- Database source of truth role/status/authVersion untuk aksi sensitif.
- Session/akun `private, no-store`; form state lokal; callback URL same-origin.
- Tidak ada optimistic auth/role update atau cache authorization lintas request.

## Algoritma/pseudocode inti

```text
authorize(actor, action, resource):
  bila actor tidak ACTIVE atau policy tidak ada: deny
  evaluasi role dan ownership dari database, bukan request
resolveGoogle(profile, actor?):
  require verified email; cari provider+sub
  bila email existing dan actor bukan owner: ACCOUNT_LINK_REQUIRED
  transaction create/link account tepat sekali
rateLimit(key):
  atomic upsert+increment key hash; reject 429 bila threshold/window terlampaui
```

## UI/UX

- Login/register menyediakan aturan password, show password, loading, field error, dan pesan kredensial generik.
- Konflik Google meminta login lokal lalu explicit linking; provider gagal tidak memblokir login lokal.
- Logout menyediakan “Keluar” dan “Keluar dari semua perangkat”.

## Kode error stabil

`AUTH_INVALID_CREDENTIALS`, `AUTH_REQUIRED`, `AUTH_SESSION_EXPIRED`, `AUTH_ACCOUNT_SUSPENDED`, `AUTH_ACCOUNT_DISABLED`, `AUTH_ACCOUNT_LINK_REQUIRED`, `AUTH_OAUTH_FAILED`, `AUTH_FORBIDDEN`, `AUTH_CSRF_INVALID`, `AUTH_RATE_LIMITED`, `USERNAME_ALREADY_EXISTS`, `EMAIL_ALREADY_EXISTS`, `VALIDATION_ERROR`.

## Logging dan monitoring

- Log register/login/OAuth/logout/access denied dengan identifier/IP ter-hash; larang password, email penuh, cookie, CSRF, dan token.
- Metrik success/failure/provider, rate-limit, linking conflict, p95; alert failure login >70% dan >50 request/5 menit atau OAuth error >10%/10 menit.

## Keamanan

- Bcrypt async cost minimum 12 atau hasil benchmark p95 ≤500 ms; panjang password maksimum 128.
- Dummy hash/pesan generik mencegah enumeration; OAuth verified email, state/nonce, explicit linking, CSRF, dan same-origin redirect wajib.
- Policy default-deny memakai role/owner/status database; suspended/disabled ditolak walau JWT belum expired.

## Kinerja

- Lookup memakai unique index/field eksplisit; login p95 ≤1 detik pada 20 concurrent dan callback internal ≤500 ms.
- Boundary sensitif maksimum dua query berindeks; rate limit atomic upsert; tanpa cache perizinan lintas request.

## Aksesibilitas dan lokalisasi

- Label dan autocomplete benar, error summary, focus ke error pertama, keyboard penuh.
- Tombol Google mempunyai accessible name; loading memakai `aria-live`.
- Pesan Indonesia, kode error Inggris stabil; layout 360 px tanpa overflow.

## Dependensi pihak ketiga/fallback

- Pin NextAuth 4.24.15, bcryptjs 3.0.3, Zod 4.5.4, Prisma 7.10.0.
- Tanpa credential Google, tombol disembunyikan dan login lokal tetap aktif.
- Database gagal menghasilkan `AUTH_SERVICE_UNAVAILABLE`; tidak ada JSON/in-memory.

## Kasus uji spesifik

- `F1-INT-001`: registrasi menyimpan lowercase dan hash, bukan password.
- `F1-CONC-002`: email sama bersamaan menghasilkan satu 201 dan satu 409.
- `F1-SEC-003`: limit menghasilkan 429 tanpa menyimpan IP mentah.
- `F2-INT-001`: username/email login; invalid selalu generik.
- `F3-E2E-001`: Google verified baru membuat satu user/account.
- `F3-SEC-002`: email existing tanpa explicit linking ditolak.
- `F4-E2E-001`: logout menutup protected page.
- `F4-INT-002`: revoke membuat JWT lama ditolak.
- `F5-SEC-001`: USER ke admin menerima 403.
- `F5-SEC-002`: user A tidak dapat membaca resource user B.

## Migrasi dan rollout

1. Pastikan RFC-001/backup/isolation lulus; tambah enum, kolom, tabel secara additive.
2. Backfill role dan google_id; deploy dual-read, alihkan Prisma, lalu smoke local/Google.
3. Contract `google_id` terpisah; rollback membaca field lama atau pulihkan branch setelah contract.

## Risiko dan mitigasi

- Account takeover Google: verified email dan explicit linking.
- Role JWT basi: revalidasi database dan authVersion.
- Bcrypt membebani serverless: benchmark dan rate limit.
- Migrasi/capability: expand-backfill-contract dan extension policy, bukan role client.

## Kriteria penerimaan per fitur

- **F1:** input valid menghasilkan akun ACTIVE unik dengan adaptive hash dan rate limit.
- **F2:** kredensial valid membuat sesi; invalid generik dan abuse dibatasi.
- **F3:** callback aman, account tidak duplikat, linking tidak berbahaya.
- **F4:** protected route, expiry, logout, dan revoke menolak sesi lama.
- **F5:** policy server default-deny menguji USER/ADMIN dan self-ownership; domain mendatang dapat menambah policy tanpa melemahkan core.

## Definition of Done

1. Regression RFC-001 lulus; acceptance/failure F1–F5 mempunyai test.
2. Tidak ada dangerous linking, hardcoded credential, JSON, ID waktu, atau role client.
3. Rate limit, CSRF, open redirect, enumeration, revocation, role, ownership tests lulus.
4. Branch coverage auth ≥90%; format/lint/typecheck/build/test/scan lulus.
5. Migration/backfill/rollback serta Google per environment diuji.
6. UI responsif/aksesibel dan semua endpoint memakai error envelope/correlation ID.
7. Tidak ada blocker/critical atau security Critical/High.
8. RFC-003 belum diterapkan dan hanya dimulai setelah RFC ini disetujui.
