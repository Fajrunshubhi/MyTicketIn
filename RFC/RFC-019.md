# RFC-019 — Production Security dan Fraud Prevention

## 1. Metadata dan urutan
- Status: **Deferred**.
- Horizon: roadmap komersial; bukan MVP akademik atau otorisasi live traffic.
- Relevansi: hardening **F63**, **F64**, dan **F73 hanya bila disetujui terpisah**.
- **F65–F72 tetap di luar scope**.
- Prasyarat: **RFC-001 sampai RFC-018 seluruhnya selesai dan lulus**.
- Pendahulu langsung: **RFC-018 — Refund, Chargeback, dan Dispute**.
- Penerus langsung: **RFC-020 — Reliability, Support, dan Commercial Launch**.
- Commercial Entry Gate (CEG): **belum disetujui**.
- Implementasi wajib sekuensial; real traffic, live credential, dan payment produksi tetap dilarang.

## 2. Ringkasan dan sasaran
RFC ini merancang threat model produksi, MFA privileged user, risk rules, velocity limit,
device/session control, hardening webhook/QR/payment, vulnerability management, pentest, dan incident response.
Kontrol default-deny, dapat diaudit, dan hanya diuji pada environment sintetis/certification.
Threshold, risk appetite, retention, challenge policy, dan tindakan fraud wajib dipasok decision gate.
Sasaran:
1. Melindungi aset dan trust boundary seluruh alur komersial.
2. Mewajibkan assurance/MFA pada privileged action.
3. Menghasilkan keputusan risiko deterministik, terversi, dan explainable.
4. Membatasi abuse secara atomik lintas akun, device, IP, dan provider token.
5. Menyiapkan vulnerability lifecycle, pentest, incident response, dan kill switch.

## 3. Scope
- Threat model untuk auth, organizer, event, order, payment, ledger/payout, refund/dispute, QR, dan support.
- MFA enrollment/recovery/step-up, session rotation/revocation, privileged access grant.
- Rules engine tanpa arbitrary code; risk decision dan reason code immutable.
- Velocity dimensions/windows, device/session signals, review queue, dan feedback loop.
- Webhook/payment/refund/payout/QR hardening, supply chain, secret, infrastructure, dan audit.
- SAST/SCA/DAST/secret/IaC scan, SBOM, pentest/retest, incident drill, serta monitoring.

## 4. Non-scope
- Menentukan risk appetite, score band, threshold, blacklist, auto-block, atau retention.
- ML fraud model, browser fingerprint invasif, atau data broker tanpa RFC/privacy approval terpisah.
- Menyimpan PAN, CVV, raw QR, password, MFA response, session token, atau provider secret.
- Menjamin fraud nol atau menggantikan provider/manusia.
- Mengaktifkan credential/endpoint/traffic produksi.
- Mengimplementasikan F65–F72 atau F73.
- Mengubah eligibility refund/dispute RFC-018.

## 5. Prasyarat lengkap
### Governance
- CEG disetujui; risk, security, privacy, incident, dan business owner ditunjuk.
- Risk appetite, loss budget, false-positive tolerance, serta customer remediation disetujui.
- Klasifikasi data, lawful basis, privacy notice, DPIA, retention, deletion, dan legal hold disetujui.
- Privileged role, segregation of duties, vulnerability severity/exception, dan disclosure policy final.
- Incident severity, notification duty, evidence handling, dan provider escalation disetujui.
### Teknis/provider
- RFC-001–018 lulus dengan blocker/critical dan security Critical/High nol.
- F63 payment/ledger/payout serta F64 refund/dispute memiliki audit dan kill switch.
- Secret manager/KMS, edge protection, rate limit store, SIEM, pager, queue, dan backup tersedia.
- Production-like environment terisolasi tersedia tanpa data/credential nyata.
- Asset/dependency inventory, SBOM, data flow, serta owner tersedia.
- Provider MFA/payment/webhook/fraud/dispute capability dan key rotation telah certification-test.
- Pentest scope/RoE/retest dan support identity-verification script disetujui.

## 6. Unresolved decision gates
- `DG-019-01`: crown jewels, threat acceptance; Security + Business.
- `DG-019-02`: MFA method, enrollment, recovery, step-up/session freshness; Security + Support.
- `DG-019-03`: privileged role, scope, expiry, maker-checker; Security + Operations.
- `DG-019-04`: risk rules, score band, action, fail mode; Risk + Product.
- `DG-019-05`: velocity dimension/window/limit; Risk + SRE.
- `DG-019-06`: device/session signal dan retention; Privacy + Security.
- `DG-019-07`: webhook timestamp/replay/key rotation; Payment owner.
- `DG-019-08`: QR rotation/revocation/challenge; Security + Event Ops.
- `DG-019-09`: vulnerability SLA dan exception; Security + Engineering.
- `DG-019-10`: incident severity/notification/evidence; Legal + Security + Support.
- `DG-019-11`: pentest vendor/scope/exit; Security.
- `DG-019-12`: data/provider/geolocation control; Legal + Privacy + Risk.
Semua gate default **BLOCKED**; production config menolak threshold/retention/fraud action implisit.

## 7. Threat model tekstual
### Aset
- Identity/session, privileged access, payment reference, ledger/payout, refund/dispute/evidence.
- QR hash/check-in state, ownership, audit, secret, signing key, artifact, backup, dan log.
### Aktor
- Bot/abuser eksternal, account takeover actor, organizer/petugas/support insider.
- Provider/dependency terkompromi, supply-chain attacker, phisher, dan operator salah konfigurasi.
### Boundary
```text
Browser [untrusted] → CDN/WAF → Next.js boundary [auth, CSRF, validation]
  → application [authorization + risk] → PostgreSQL [transaction + audit]
  → outbox/worker → external providers
Provider webhook [untrusted] → raw signature/timestamp/replay store → canonical state
QR [copyable bearer artifact] → hash lookup + event authorization + atomic one-time use
```
Ancaman minimum: spoofing, tampering, repudiation, disclosure, DoS, privilege escalation,
credential stuffing, fixation/theft, IDOR, CSRF, replay/forgery, payment/refund abuse,
chargeback abuse, QR cloning, insider misuse, supply-chain compromise, secret leak, dan unsafe recovery.

## 8. Aliran keputusan risiko
1. Boundary memvalidasi auth, assurance, CSRF, input, idempotency, dan rate limit dasar.
2. Service membangun `RiskContext` hanya dari signal allowlisted dan diminimalkan.
3. Engine memuat satu ruleset ACTIVE terversi dan memverifikasi schema/hash.
4. Rule dievaluasi deterministik berdasarkan priority; match menghasilkan reason code.
5. Aggregator menghasilkan `ALLOW`, `CHALLENGE`, `REVIEW`, atau `BLOCK`.
6. Business service menjalankan action; client tidak pernah memasok score/action.
7. Decision, version, provenance, dan outcome diaudit tanpa raw sensitive signal.
8. Review manusia append-only; feedback chargeback RFC-018 menjadi event baru.

## 9. Skema database usulan eksak
```sql
CREATE TYPE mfa_type AS ENUM ('WEBAUTHN','TOTP');
CREATE TABLE mfa_credentials (
  id UUID PRIMARY KEY, user_id UUID NOT NULL REFERENCES users(id), type mfa_type NOT NULL,
  credential_id_hash CHAR(64) UNIQUE, public_key TEXT, encrypted_secret TEXT,
  sign_count BIGINT CHECK(sign_count>=0), status VARCHAR(16) NOT NULL,
  enrolled_at TIMESTAMPTZ, last_used_at TIMESTAMPTZ, revoked_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL
);
CREATE TABLE mfa_recovery_codes (
  id UUID PRIMARY KEY, user_id UUID NOT NULL REFERENCES users(id),
  code_hash CHAR(64) NOT NULL UNIQUE, used_at TIMESTAMPTZ, created_at TIMESTAMPTZ NOT NULL
);
CREATE TABLE privileged_access_grants (
  id UUID PRIMARY KEY, user_id UUID NOT NULL REFERENCES users(id),
  privilege VARCHAR(64) NOT NULL, scope_type VARCHAR(32) NOT NULL, scope_id UUID,
  status VARCHAR(16) NOT NULL, requested_by UUID NOT NULL REFERENCES users(id),
  approved_by UUID REFERENCES users(id), expires_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL, updated_at TIMESTAMPTZ NOT NULL,
  UNIQUE(user_id,privilege,scope_type,scope_id)
);
```
```sql
CREATE TYPE risk_action AS ENUM ('ALLOW','CHALLENGE','REVIEW','BLOCK');
CREATE TABLE risk_rule_sets (
  id UUID PRIMARY KEY, name VARCHAR(100) NOT NULL, version INTEGER NOT NULL CHECK(version>0),
  status VARCHAR(16) NOT NULL, schema_version INTEGER NOT NULL, rules_json JSONB NOT NULL,
  rules_sha256 CHAR(64) NOT NULL UNIQUE, approved_by UUID REFERENCES users(id),
  activated_at TIMESTAMPTZ, created_at TIMESTAMPTZ NOT NULL, UNIQUE(name,version)
);
CREATE TABLE risk_decisions (
  id UUID PRIMARY KEY, subject_type VARCHAR(32) NOT NULL, subject_id UUID NOT NULL,
  actor_user_id UUID REFERENCES users(id), rule_set_id UUID NOT NULL REFERENCES risk_rule_sets(id),
  action risk_action NOT NULL, score INTEGER, reason_codes TEXT[] NOT NULL,
  context_hash CHAR(64) NOT NULL, correlation_id VARCHAR(64) NOT NULL,
  decided_at TIMESTAMPTZ NOT NULL
);
CREATE TABLE risk_signals (
  id UUID PRIMARY KEY, decision_id UUID NOT NULL REFERENCES risk_decisions(id),
  signal_type VARCHAR(64) NOT NULL, source VARCHAR(64) NOT NULL,
  value_bucket VARCHAR(64), value_hash CHAR(64), observed_at TIMESTAMPTZ NOT NULL,
  expires_at TIMESTAMPTZ
);
CREATE TABLE velocity_counters (
  key_hash CHAR(64) NOT NULL, dimension VARCHAR(64) NOT NULL,
  window_started_at TIMESTAMPTZ NOT NULL, window_seconds INTEGER NOT NULL CHECK(window_seconds>0),
  count BIGINT NOT NULL CHECK(count>=0), amount_idr BIGINT NOT NULL CHECK(amount_idr>=0),
  expires_at TIMESTAMPTZ NOT NULL,
  PRIMARY KEY(key_hash,dimension,window_started_at,window_seconds)
);
```
```sql
CREATE TABLE device_sessions (
  id UUID PRIMARY KEY, user_id UUID NOT NULL REFERENCES users(id),
  session_id_hash CHAR(64) NOT NULL UNIQUE, device_id_hash CHAR(64),
  assurance_level VARCHAR(16) NOT NULL, risk_state VARCHAR(16) NOT NULL,
  ip_prefix_hash CHAR(64), user_agent_family VARCHAR(64),
  last_seen_at TIMESTAMPTZ NOT NULL, expires_at TIMESTAMPTZ NOT NULL,
  revoked_at TIMESTAMPTZ, created_at TIMESTAMPTZ NOT NULL
);
CREATE TABLE security_incidents (
  id UUID PRIMARY KEY, incident_no VARCHAR(32) NOT NULL UNIQUE,
  severity VARCHAR(8) NOT NULL, status VARCHAR(24) NOT NULL, title VARCHAR(200) NOT NULL,
  commander_user_id UUID REFERENCES users(id), declared_at TIMESTAMPTZ NOT NULL,
  contained_at TIMESTAMPTZ, closed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL, updated_at TIMESTAMPTZ NOT NULL
);
```
Indeks wajib: MFA `(user_id,status)`; grant `(user_id,status,expires_at)`; decision
`(subject_type,subject_id)`, `(actor_user_id,decided_at)`, `(action,decided_at)`;
signal/counter `(expires_at)`; session `(user_id,risk_state)`; incident `(status,severity,declared_at)`.
TOTP secret dienkripsi envelope; rules JSON divalidasi dan tidak boleh menjalankan kode.

## 10. Kontrak risk engine
```ts
type RiskAction = "ALLOW" | "CHALLENGE" | "REVIEW" | "BLOCK";
interface RiskEngine {
  evaluate(input: RiskContext, ruleSetVersion: number): Promise<{
    decisionId: string; action: RiskAction; reasonCodes: string[]; expiresAt?: string;
  }>;
}
```
Fail-open/fail-closed diputuskan per use case pada `DG-019-04`, tanpa default global.

## 11. Kontrak API eksak
- Semua endpoint: Zod, RFC-014 envelope, no-store, audit, dan scoped authorization.
- `POST /api/security/mfa/enroll`; session; body `{type:"WEBAUTHN"|"TOTP"}`;
  201 `{enrollmentId,type,challenge}`; TOTP secret hanya sekali.
- `POST /api/security/mfa/enroll/:id/verify`; pemilik; body `{response}`;
  200 `{status:"ACTIVE",recoveryCodes?}`; challenge replay/expired ditolak.
- `POST /api/security/step-up`; session; body `{method,response,actionContext}`;
  200 `{assuranceLevel:"STEP_UP",validUntil}`.
- `GET /api/security/sessions`; pemilik; 200 `{items:[{id,deviceLabel,lastSeenAt,current,riskState}]}`.
- `POST /api/security/sessions/:id/revoke`; pemilik/privileged; idempoten; 200 `{status:"REVOKED"}`.
- `POST /api/internal/risk/evaluate`; internal service identity, bukan route publik;
  body `{subjectType,subjectId,actorId?,signals,ruleSetVersion}`; 200 `{decisionId,action,reasonCodes}`.
- `GET /api/admin/risk/reviews`; fraud analyst + MFA; cursor/filter; PII minimum.
- `POST /api/admin/risk/reviews/:id/decision`; analyst + step-up + `If-Match`;
  body `{decision:"ALLOW"|"BLOCK",reasonCode,notes?}`; append-only.
- Error: `MFA_METHOD_DISABLED`, `MFA_CHALLENGE_INVALID`, `SESSION_ASSURANCE_REQUIRED`,
  `SESSION_REVOKED`, `RISK_REVIEW_REQUIRED`, `RISK_BLOCKED`, `VELOCITY_LIMITED`.

## 12. State
- MFA: `PENDING → ACTIVE → REVOKED`.
- Grant: `PENDING → ACTIVE → SUSPENDED|REVOKED|EXPIRED`.
- Session: `NORMAL → CHALLENGED → NORMAL|RESTRICTED|REVOKED`.
- Ruleset: `DRAFT → APPROVED → ACTIVE → RETIRED`; satu ACTIVE per nama.
- Incident: `DECLARED → CONTAINING → ERADICATING → RECOVERING → MONITORING → CLOSED`.
Terminal state tidak dibuka kembali; recurrence membuat record baru yang ditautkan audit.

## 13. Kontrol keamanan dan compliance
- MFA phishing-resistant diprioritaskan; method/recovery final menunggu gate.
- Session ID dirotasi setelah login, MFA, privilege change, dan recovery; revoke berlaku request berikutnya.
- Device signal diminimalkan/di-hash, bukan identitas pasti, dan tunduk DPIA/retention.
- Provider-hosted/tokenized payment digunakan; scope PCI wajib dikonfirmasi.
- Payment amount/currency/reference dihitung server-side; redirect bukan authority.
- Webhook: raw signature, key ID, timestamp, replay unique, schema/size allowlist.
- Refund, payout, dispute, role grant, serta secret rotation membutuhkan step-up.
- QR opaque/hash/no-cache/server-validation; event authorization dan atomic use dipertahankan.
- Secret manager, least privilege, JIT production access, signed artifact, SBOM, provenance wajib.
- PII/secret/token/evidence dilarang pada log, analytics, trace, dan fixture.

## 14. Vulnerability, pentest, dan incident response
- CI menjalankan SAST, SCA, secret, IaC/container, license, SBOM, dan DAST aman.
- Temuan memiliki owner/severity/due date; SLA/exception expiry mengikuti `DG-019-09`.
- Critical/High terbuka memblokir gate.
- Pentest independen mencakup auth/IDOR, tenant isolation, payment/webhook,
  refund/dispute/payout, QR, admin/support, business logic, dan cloud config.
- Target hanya environment/akun pada signed RoE; semua temuan diretest.
- Incident: detect → declare → contain → preserve → eradicate → recover → monitor → close.
- Runbook: account takeover, secret leak, webhook compromise, fraud/refund spike,
  QR cloning, data exposure, supply chain, dan provider outage.
- Evidence memakai UTC/hash/chain-of-custody; notifikasi mengikuti `DG-019-10`.

## 15. Error, logging, performa, dan monitoring
- Error code: `MFA_*`, `SESSION_*`, `RISK_*`, `VELOCITY_*`, `WEBHOOK_*`, `SECURITY_*`.
- Client tidak menerima rule, threshold, account existence, atau signal rahasia.
- Log aman: correlation, decision, reason, assurance, actor/subject hash, outcome.
- Metrik: auth/MFA/recovery, revoke, risk action, velocity reject, webhook replay,
  privileged action, QR reject, vulnerability age, incident MTTD/MTTR observasi.
- Alert threshold menunggu gate; synthetic alert tetap diuji.
- Risk evaluation mendapat latency budget RFC-020; ruleset cache bounded dan version-pinned.
- Counter atomik; audit/outbox transactional; edge dan aplikasi memberi layered DoS protection.

## 16. Strategi pengujian
- Unit/property: parser rules, deterministic evaluation, boundaries, tanpa arbitrary code.
- Integration: MFA/grant/session, atomic velocity, version activation, audit.
- Security: stuffing/enumeration, CSRF/fixation, IDOR/escalation, SSRF/injection.
- Webhook: forgery/replay/stale/oversized/key rotation/out-of-order.
- Fraud simulation: multi-account/device/IP/token, refund abuse, payout/refund race.
- QR: guessed/copied, wrong event, revoked staff, concurrent scan, excess rate.
- Resilience: engine/counter/SIEM/provider unavailable sesuai fail-mode matrix.
- Privacy: minimization, retention expiry, deletion/legal hold, access.
- Independent pentest/retest serta IR tabletop dan technical drill wajib lulus.

## 17. Rollout tanpa real traffic
1. Tutup CEG dan `DG-019-01..12`.
2. Terapkan schema additive, MFA/session, dan engine di environment terisolasi.
3. Replay fixture lalu synthetic shadow; bandingkan expected decision.
4. Jalankan certification, DAST, dependency drill, pentest, dan retest.
5. Latih privileged user dengan akun uji; uji recovery/revocation.
6. Jalankan incident, kill switch, secret rotation, dan evidence drill.
7. Serahkan evidence ke RFC-020; semua production/live flags tetap OFF.
- Kill switch granular untuk privileged login, payment, refund, payout, dispute, QR, ruleset, webhook.
- Rollback mengaktifkan ruleset APPROVED sebelumnya; tidak mengedit histori.
- Rollback tidak boleh menonaktifkan audit, signature, authorization, atau integrity.

## 18. Kriteria penerimaan
1. Threat model mencakup seluruh trust boundary/aset F63/F64 dan F73 bila relevan.
2. Privileged role memakai MFA, session freshness, least privilege, dan revocation teruji.
3. Risk decision deterministik, explainable, versioned, tanpa threshold rekaan.
4. Velocity/device/session control atomik dan memenuhi privacy policy.
5. Payment/webhook/refund/dispute/payout/QR lulus abuse/replay test.
6. Vulnerability gates, pentest/retest, serta incident drill lulus; Critical/High nol.
7. F65–F72 tetap di luar scope dan F73 nonaktif tanpa keputusan terpisah.
8. Tidak ada secret/data nyata, real traffic, atau live credential.

## 19. Risiko
- False positive: risk appetite gate, shadow test, review, dan remediation policy.
- Rule ditebak: respons client aman dan ruleset restricted.
- Counter race: atomic operation, layered limits, concurrency test.
- MFA recovery bypass: assurance, audit, support script, maker-checker.
- Device privacy: minimisasi, hashing, DPIA, retention gate.
- Insider abuse: segregation, JIT grant, audit, anomaly alert.
- Pentest mengganggu: isolated target dan signed RoE.
- Emergency control merusak transaksi: granular kill switch dan reconciliation.

## 20. Definition of Ready
1. RFC-001–018 Done dan evidence tersedia.
2. CEG serta `DG-019-01..12` ditutup.
3. Threat model, data classification, DPIA, assurance, risk, velocity, dan IR policy final.
4. Security infrastructure, certification environment, fixture, RoE, dan test account tersedia.
5. Schema/API/state direview Engineering, Security, Risk, Privacy, Legal, Support, dan Finance.
6. Rollback, key rotation, access review, pentest, dan exception process disetujui.
7. Tidak ada rencana real traffic/live credential sebelum RFC-020.

## 21. Definition of Done
1. Acceptance, regression, security, privacy, resilience, dan performance test lulus.
2. MFA/grant/session, risk/velocity, audit, monitoring, dan review workflow selesai.
3. Payment/webhook/refund/dispute/payout/QR hardening tervalidasi di certification.
4. Pentest/retest selesai; Critical/High terbuka nol.
5. Vulnerability process, incident runbook/tabletop/technical drill, rollback, dan kill switch terbukti.
6. Dokumentasi tanpa TODO, threshold rekaan, secret, atau data pribadi.
7. RFC-020 dapat dimulai sekuensial; Done tetap tidak mengizinkan traffic/live credential.
