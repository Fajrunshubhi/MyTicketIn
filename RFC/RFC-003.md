# RFC-003 — Audit dan Analitik

## Metadata dan urutan

- Status: Diusulkan.
- Fitur yang dimiliki: **F45, F52**.
- Kompleksitas: **Sedang–Tinggi**.
- Prasyarat seluruh RFC terdahulu: **RFC-001 dan RFC-002 wajib selesai dan lulus**.
- Pendahulu langsung: **RFC-002 — Identitas, Sesi, dan RBAC**.
- Penerus langsung: **RFC-004 — Organizer dan Moderasi**.
- Hanya fondasi dan actor context RFC terdahulu yang boleh dipakai.
- RFC-004 baru boleh dimulai setelah Definition of Done RFC-003 lulus.

## Keputusan dan sasaran

Bangun audit append-only untuk aksi sensitif dan event store analitik berversi. Audit ditulis dalam transaksi mutasi sehingga kegagalan audit membatalkan mutasi; analitik best-effort dengan retry terbatas sehingga kegagalannya tidak membatalkan domain. Setiap record memiliki correlation ID, schema version, identifier minimum, dan sanitasi. PostgreSQL menjadi storage awal; tidak diperlukan provider atau domain RFC berikutnya.

## Ruang lingkup

- Audit writer transaksional, sanitizer, immutable trigger, dan query admin.
- Actor `USER|SYSTEM|ANONYMOUS`, outcome, reason, before/after allowlist.
- Event registry v1, validator, deduplication key, emitter, dan metrik delivery.
- Event auth yang sudah tersedia dan contract test sintetis untuk nama event PRD.
- Halaman list/detail audit minimum; bukan dashboard RFC-012.

## Non-scope

- Membangun organizer/event/payment/ticket/check-in demi menghasilkan event.
- SDK analytics eksternal, warehouse, session replay, heatmap, atau ads tracking.
- Edit/hapus audit melalui UI/API, grafik, CSV, atau pencarian lintas entitas.
- PII analytics dan retensi data nyata.

## Gap kondisi saat ini

- Prototype hanya `console.error`; tidak ada audit yang dapat ditelusuri.
- Tidak ada actor/outcome/correlation, immutable storage, sanitizer, atau admin query.
- Tidak ada registry event, schema version, reason code, dedup, dan delivery metric.
- Domain sensitif mendatang membutuhkan fasilitas audit sebelum dibuat.

## Arsitektur komponen tekstual

`Sensitive use case → Prisma transaction → mutation + AuditWriter(tx) → atomic commit`. `Admin route → requireRole(ADMIN) → AuditQueryService → read repository → safe DTO`. `Use case → AnalyticsEmitter → EventSchemaRegistry → validate/redact → repository`. `Allowed client event → rate-limited route → server-derived actor → emitter`. Domain mendatang hanya mengimpor interface publik audit/analytics.

## Aliran data tekstual

1. Boundary membentuk actor context dari session atau system identity.
2. Use case mengambil before state allowlist, melakukan mutasi, dan menulis audit dalam transaction.
3. Sanitizer membuang key sensitif dan membatasi payload; commit bersifat atomik.
4. Event analitik divalidasi registry, actor/entity diturunkan server-side, lalu insert.
5. Dedup key sama dianggap sukses tanpa row kedua.
6. Analytics gagal memunculkan degraded metric/log; audit gagal melakukan rollback.

## Registry event v1

- Aktif: `user_registered`, `login_succeeded`, `login_failed`, `access_denied`.
- Future-safe: `organizer_application_submitted|approved|rejected`.
- Future-safe: `event_created|submitted|published|rejected|cancelled`.
- Future-safe: `checkout_started|order_created|order_expired`.
- Future-safe: `payment_succeeded|payment_failed|webhook_rejected`.
- Future-safe: `ticket_issued|ticket_viewed`, `checkin_succeeded|checkin_rejected`.
- Registry hanya schema contract; tidak mengimpor module masa depan.
- Properti umum hanya `source,entityType,entityId,reasonCode`; tidak ada nama/email/token.

## Endpoint

### `GET /api/admin/audit-logs`

- Auth ADMIN.
- Query: `cursor?`, `limit 1..100` (25), `action?`, `entityType?`, `entityId?`, `actorUserId?`, `from?`, `to?`, `outcome?`.
- 200: `data[]`, `page.nextCursor`, `correlationId`; signed opaque cursor `(occurred_at,id)`.

### `GET /api/admin/audit-logs/{id}`

- Auth ADMIN; 200 safe detail; 404 `AUDIT_LOG_NOT_FOUND`.

### `POST /api/analytics/events`

- Auth opsional; client allowlist hanya event interaksi yang ditetapkan registry.
- Request: `eventName,occurredAt,schemaVersion,properties,deduplicationKey?`.
- 202 accepted; 400 invalid/not allowed; 429 limited.
- Actor/entity sensitif dari client diabaikan dan diturunkan server.

Tidak ada endpoint write/update/delete audit.

## State dan caching

- Audit/analytics di PostgreSQL; list/detail `private, no-store`.
- Filter/pagination menjadi URL state; dialog/filter draft memakai local state.
- Event server tidak hanya disimpan dalam antrean memory.
- Tidak ada cache agregasi; duplicate event idempoten.

## Algoritma/pseudocode inti

```text
auditedMutation:
  transaction: read allowlisted before; mutate; read after; append sanitized audit
sanitize:
  recursively drop password|secret|token|cookie|authorization|email
  truncate string 500 dan total JSON 16 KiB
emit:
  validate registry/version; insert
  unique dedup = accepted; error lain = metric degraded tanpa rollback domain
```

## UI/UX

- `/admin/audit` menampilkan waktu, actor type/ID tersamar, aksi, entitas, outcome, reason.
- Detail before/after read-only sebagai daftar diff; tidak ada tombol edit/hapus.
- URL menyimpan filter; loading/empty/error/permission state jelas.
- Outcome memakai teks+ikon, bukan warna saja.

## Kode error stabil

`AUDIT_WRITE_FAILED`, `AUDIT_LOG_NOT_FOUND`, `AUDIT_FILTER_INVALID`, `ANALYTICS_EVENT_INVALID`, `ANALYTICS_EVENT_NOT_ALLOWED`, `ANALYTICS_EVENT_TOO_LARGE`, `ANALYTICS_RATE_LIMITED`, `ANALYTICS_DELIVERY_DEGRADED`, `CURSOR_INVALID`.

## Logging dan monitoring

- Log audit hanya audit ID/action/outcome/correlation, bukan before/after.
- Metrik write/failure audit, accepted/dropped/dedup analytics, p95 insert/query.
- Alert langsung untuk audit failure; analytics drop >1% selama 15 menit.
- Percobaan update/delete trigger menjadi security event.
- Retensi analytics demo 90 hari; audit sepanjang MVP; perubahan butuh decision gate.

## Keamanan

- Query audit ADMIN dan default-deny; cursor ditandatangani.
- Allowlist per action ditambah recursive denylist; payload maksimum 16 KiB.
- Larang password, secret, cookie, OAuth/QR token, provider payload, dan PII tak perlu.
- Client analytics allowlist/rate limit; actor selalu server-derived.
- Trigger database memberi defense-in-depth immutability.

## Kinerja

- Cursor pagination, default 25/maksimum 100; list tidak memuat before/after.
- Audit insert overhead p95 ≤50 ms.
- List 25 record p95 ≤500 ms pada 100.000 row.
- Analytics timeout 100 ms agar event nonkritis tidak menahan mutasi.

## Aksesibilitas dan lokalisasi

- List/table semantic dengan caption/header dan navigasi keyboard.
- Diff dapat dibaca sebagai teks, bukan warna; filter mengumumkan hasil via live region.
- Waktu `id-ID` dengan zona dan elemen `time` ISO.
- Kode event Inggris stabil; label/pesan Indonesia; layout mobile dapat digulir tanpa kehilangan aksi.

## Dependensi pihak ketiga/fallback

- Hanya Prisma/Zod/Pino dari RFC-001; tidak ada SDK analytics.
- PostgreSQL event store adalah default dan fallback demo jika provider kelak dipilih.
- Analytics gagal: domain lanjut dan degraded alert; audit gagal: transaction rollback.
- Tidak ada fallback log file.

## Kasus uji spesifik

- `F45-INT-001`: mutasi dan audit commit atomik.
- `F45-INT-002`: audit gagal membuat mutasi rollback.
- `F45-DB-003`: UPDATE/DELETE audit ditolak trigger.
- `F45-SEC-004`: sanitizer nested secret dan limit 16 KiB.
- `F45-SEC-005`: USER ke list/detail menerima 403.
- `F52-UNIT-001`: semua registry v1 menerima payload minimum sintetis.
- `F52-UNIT-002`: event asing/PII property ditolak.
- `F52-INT-003`: dedup key menghasilkan satu row.
- `F52-INT-004`: analytics failure tidak rollback mutasi.
- `F52-SEC-005`: client tidak dapat memalsukan actor/entity.

## Migrasi dan rollout

1. Regression RFC-001–002 dan backup preview wajib lulus.
2. Terapkan tabel/index/trigger additive; jalankan immutability/security test.
3. Shadow-write aksi auth, validasi redaction, lalu aktifkan audit wajib.
4. Aktifkan emitter/metric degraded dan contract test seluruh registry.
5. Rollback aplikasi berhenti menulis tanpa menghapus data/tabel; tidak ada down migration destruktif.
6. Sebelum RFC-004, uji transaksi audit agar moderasi dapat menggunakannya.

## Risiko dan mitigasi

- PII bocor: action allowlist, denylist, size cap, snapshot test.
- Mutasi lambat: payload kecil, index terukur, benchmark.
- Analytics menjadi hard dependency: timeout/degraded path.
- Taxonomy berubah: version immutable dan registry versioned.

## Kriteria penerimaan per fitur

- **F45:** actor/action/entity/time/outcome/reason/before-after tersensor tersimpan atomik dan immutable; writer dapat dipakai domain berikutnya.
- **F52:** registry minimum PRD v1, schema/reason/dedup tersedia; event RFC-002 aktif dan kontrak masa depan diuji sintetis tanpa forward dependency; tidak ada secret/PII.

## Definition of Done

1. Regression RFC-001–002 lulus.
2. Migration/index/constraint/trigger dan rollback strategy teruji.
3. Audit transaction dan analytics degraded path lulus integration test PostgreSQL.
4. Admin UI/API aman, paginated, Indonesia, responsif, dan aksesibel.
5. Branch coverage audit/analytics ≥90%; format/lint/typecheck/build/test/scan lulus.
6. Target performa/redaction/dedup/schema version mempunyai bukti.
7. Tidak ada blocker/critical, security Critical/High, SDK, atau import domain masa depan.
8. RFC-004 hanya dimulai setelah RFC ini disetujui.
